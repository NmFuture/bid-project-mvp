### TML-001 原始素材三级目录无法删除 【已解决】

- 测试模块：技术标素材库 / 原始素材 / 素材目录
- 问题位置：技术标原始素材库下的三级目录，例如 `技术标 > 客户素材 > 国电投`；补充反馈：在其他文件夹下也存在该问题，例如在 `项目素材` 下新建一个项目文件夹后同样无法删除。
- 实际表现：鼠标悬停在三级目录上时，顶部“删除文件夹”按钮处于不可用状态，无法删除该文件夹；该现象不只出现在客户素材目录，也出现在项目素材下新建的项目文件夹。
- 期望表现：选中或悬停客户素材下的三级目录后，应允许删除文件夹；若因目录内存在文件、权限限制或系统保护不允许删除，应给出明确原因提示。

### TML-013 技术标素材库存在商务标遗留命名和分类口径【已修复】

- 测试模块：技术标素材库 / 前端页面实现 / 产品逻辑一致性
- 问题位置：技术标素材库原始素材页面的代码与页面逻辑。
- 实际表现：技术标素材库页面中仍存在较多商务标遗留命名和口径，例如代码中使用 `BUSINESS_BID_TYPE = '技术标'`、`BUSINESS_WORKSPACE = 'tech'`、`BUSINESS_ROOT_PATH = '技术标/通用素材'` 等命名；页面中也保留了类似“固定素材 / AI填写 / 其他”等偏商务标素材分类口径。

### TML-014 标签存在数据库与 JSON 索引双事实源风险【已修复】

- 测试模块：技术标素材库 / 标签体系 / 数据一致性
- 问题位置：原始素材文件标签、技术标 JSON 索引标签、Wiki 标签及下游素材匹配链路。
- 实际表现：当前技术标素材标签可能同时存在两套来源：原始素材列表和人工编辑标签主要读写数据库 `raw_files.ext_fields.tags`；技术标 JSON 索引又提供 `/api/technical/materials/index/tags` 接口，并将标签写入 `technical_material_index.json`。如果两边没有严格同步，可能出现原始素材列表、Wiki、标签筛选和下游 AI 选材看到的标签不一致。
- 期望表现：建议明确标签唯一事实源，并统一所有标签读写链路。可选方案包括：以数据库作为标签真值，JSON 索引只作为派生快照；或以 JSON 索引为真值，但原始素材列表、导入标签、筛选、Wiki 和下游匹配都必须统一读取索引标签。
- 备注：标签会影响素材筛选、Wiki 卡片、缺口识别和投标文件生成时的素材选择。如果标签事实源不统一，可能导致“已打标签但筛选不到”“Wiki 与原始素材显示不一致”“AI 未按标签命中素材”等问题。
- 截图：无
- 状态：待确认 / 待梳理

### TML-015 业绩库存在新旧两套数据模型并存风险【已修复】

- 测试模块：技术标素材库 / 共用业绩库 / 数据模型一致性
- 问题位置：业绩库接口、数据表、下游素材匹配与投标文件生成链路。
- 实际表现：当前系统中同时存在旧的单条业绩记录模型 `performance_records`，以及新的业绩包模型 `performance_categories / performance_items / performance_attachments / performance_item_attachments`。前端业绩库页面主要面向业绩包/明细/合同附件模型，但后端仍保留旧业绩记录接口和服务；下游匹配逻辑也存在同时读取旧业绩记录与新业绩包候选的情况。
- 期望表现：建议明确业绩库唯一主模型。若未来以“业绩包 + 明细 + 合同附件”为主，应将旧 `performance_records` 标记为历史兼容或逐步迁移，前端展示、Wiki、缺口识别、素材匹配、合同附件引用和标书组装应统一读取同一套业绩数据源。
- 备注：若新旧模型长期并存，可能出现页面导入的业绩下游匹配不到、旧接口写入的业绩当前页面不展示、同一业绩重复出现、附件引用语义不一致、`PERF-* / PERCAT-* / PERITEM-*` 多套 ID 体系混用等问题。
- 截图：无
- 状态：待确认 / 待梳理
