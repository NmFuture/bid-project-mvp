# 技术标进度界面统一设计

## 目标

统一技术标七处长任务的进度展示、关闭、恢复和停止行为：

1. 招标文件解析。
2. 首次目录生成。
3. 重新生成目录。
4. 素材匹配。
5. 首次生成正文。
6. 重新生成正文。
7. 重新生成索引。

本次只调整技术标链路，不改变商务标页面和交互。

## 方案选择

采用“技术标专用统一任务进度层”：

- 使用统一的进度弹窗骨架和页面内进度展示规则。
- 使用统一的技术标后台任务登记、轮询和右下角任务栈。
- 各任务通过适配器提供标题、路由、状态查询、停止操作和进度摘要。
- 后端补齐真实取消能力，不用“停止前端展示”冒充停止任务。

不采用逐页复制实现，避免七处状态和交互继续分叉；不扩展为商务标通用任务中心，避免超出范围。

## 视觉与布局

### 进度弹窗

- 桌面端目标宽度约为 672px，对应现有 `md` 弹窗宽度；移动端保持左右安全边距并占满可用宽度。
- 弹窗由顶部标题区和主体区组成，删除现有底部 Footer。
- 顶部左侧显示当前任务，例如“正在重新生成目录”“正在生成技术标正文”。
- 顶部右侧使用带文字的“关闭”控件，替代单独的“×”图标。
- 主体保留进度条、百分比、当前步骤、数量信息、真实耗时和结果提示。
- 运行状态下，主体底部右侧显示“停止”按钮，使用现有“停止解析”的 `dangerQuiet` 风格。
- 点击停止后按钮立即禁用并显示“停止中…”，直到后端返回终态或明确失败。
- 已完成、已停止或失败时不显示停止按钮，结果说明仍位于主体内。

### 页面内进度

- 解析和首次目录生成继续使用页面内进度，不改造成弹窗。
- 两处都使用相同的进度卡片、状态颜色、耗时格式和停止状态。
- 停止按钮放在页面当前任务操作区，与现有“停止解析”控件保持一致。

### 右下角后台任务

- 视觉风格沿用现有解析后台小卡片。
- 单条信息顺序固定为：任务名、百分比、项目名。
- 最多展开显示 3 条，超过后显示“另有 N 个任务”。
- 多条任务按最近更新时间倒序排列，运行任务排在终态通知之前。
- 后台卡片不直接提供停止按钮，避免误触；点击卡片恢复完整进度界面后再停止。
- 用户已在任务对应页面时，点击卡片直接重新打开弹窗；否则先导航到对应页面，再自动打开弹窗。
- 解析和首次目录生成没有弹窗，点击后返回对应页面并定位到页面内进度区域。

## 关闭与完成行为

- “关闭”只关闭弹窗，不停止任务，也不清除后台任务登记。
- 关闭弹窗后，右下角立即显示对应后台任务卡片。
- 用户离开页面或刷新页面后，前端根据本地登记和后端状态恢复追踪。
- 弹窗仍打开时，任务结束后原位切换为已完成、已停止或失败状态。
- 弹窗已关闭或用户已离开时，不强制跳页、不重新弹窗，只更新右下角通知。
- 素材匹配完成时，如果用户仍停留在目录页，保留自动进入素材匹配页的现有流程；用户已经离开时只显示完成通知。
- 终态通知由用户点击查看或主动关闭后消失。

## 停止语义

- 点击“停止”后立即请求后端取消，不增加二次确认弹窗。
- 状态统一为 `queued`、`running`、`cancel_requested`、`cancelled`、`completed`、`failed`。
- `cancel_requested` 表示后端已经收到请求但任务尚未到达安全停止点，前端显示“停止中…”。
- 重复停止请求必须幂等；任务已经结束时返回当前终态。
- 后端在耗时阶段边界和批处理循环中检查取消信号，并在可安全中断的位置退出。
- 首次生成任务被停止后保留可重试状态。
- 重新生成目录、正文或索引被停止或失败时，不用半成品覆盖已有有效产物。
- 若外部会话支持中止，应同时请求中止；若不能立即中止，仍须阻止其迟到结果覆盖当前有效状态。

## 前端结构

### 统一任务定义

每种技术标任务提供以下元数据和行为：

- 稳定的任务类型和项目 ID。
- 运行标题、完成标题和失败标题。
- 对应页面路由及是否支持恢复弹窗。
- 状态查询方法和停止方法。
- 百分比、步骤、耗时、终态和错误信息的展示转换。

### 后台任务登记

- 使用技术标专用的本地登记表替代解析专用的单任务读取方式。
- 登记至少包含任务类型、项目 ID、项目名、开始时间和最近更新时间。
- 页面提交任务成功时登记；轮询确认终态后转为结果通知。
- 登记异常、过期或后端查无任务时清理，避免永久残留。
- 同一项目、同一任务类型只保留一条记录，多标签页通过 `storage` 事件同步。

### 统一进度组件

- 保留 `BidProgressPanel` 作为纯展示组件。
- 新增技术标进度弹窗壳，负责顶部标题、右上角关闭、主体内容和右下角停止区。
- 目录、素材匹配、正文和索引组件只负责把各自状态转换为统一展示字段。
- 业务页负责启动任务、恢复弹窗以及完成后的页面数据刷新。

## 后端结构

- 解析沿用现有取消接口和取消检查机制。
- 目录生成与重新生成目录共用目录任务取消接口和状态更新。
- 素材匹配从阻塞请求调整为可查询状态的后台任务，提供启动、状态和取消接口。
- 首次生成正文与重新生成正文共用正文任务取消接口和状态更新。
- 重新生成索引提供独立取消接口和状态更新。
- 队列任务记录保存可取消的任务 ID；本地执行回退也必须持有可查询的取消标记。
- 任务写入最终产物前再次检查取消状态，并采用临时产物完成后原子替换。

## 错误与竞态处理

- 状态查询暂时失败时保留上一次进度，并在后台重试，不把网络波动直接判为任务失败。
- 停止请求失败时恢复按钮可用状态，并展示明确错误，不静默吞掉异常。
- 完成与停止同时发生时以后端最终状态为准；已提交成功产物的任务返回 `completed`。
- 页面关闭弹窗后不得停止轮询任务本身；页面卸载只清理本页订阅，全局追踪继续工作。
- 多任务卡片必须使用稳定键，状态更新不得导致顺序无意义抖动。
- 目录、正文和索引互斥规则继续由后端校验，前端同步禁用冲突操作。

## 验证范围

遵循项目要求，只做聚焦验证：

- 后端取消接口、状态迁移、幂等停止和旧结果保护的单元测试。
- 前端任务登记、排序、恢复路由和终态清理的单元测试。
- 七处进度入口的界面契约测试，确认标题、关闭、停止和信息顺序一致。
- 前端构建。
- `git diff --check`。

不运行与本改动无关的全量集成测试；无法在本地验证的真实长任务中止效果，保留为 5090 环境的后续实测项，但取消状态和并发正确性在本地使用 mock 验证。
