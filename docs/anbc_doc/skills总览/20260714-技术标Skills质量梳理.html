Q1 · 58 条清单表放哪？

方案 A：留在 SKILL.md，表头加「此表被 checklist.py 运行时解析，勿改结构」警示（改动最小）。方案 B：移到 references/checklist.md，checklist.py 改指向（符合披露原则，agent 每次仍需读全表，token 成本不变）。方案 C：升级为独立 JSON/CSV 数据文件，彻底解除文档-数据耦合（最干净，改动最大）。

Q2 · 阶段命名要不要一次性收口？

历史别名（s1parse/s2toc/s4gap/s7）短期难改（后端和产物路径依赖），但至少可以：在 skills/ 根放一张「用户阶段 ↔ 命令别名 ↔ 工作目录」映射表，各 SKILL.md 引用它，替换掉现在九份各说各话的解释；并查清 format-cleaner 的「S2/S5」到底指什么。

v1 决议：已建 opencode/skills/STAGES.md（9 个 skill 全表 + 注意事项），各 SKILL.md 改为一行引用。「S2/S5」已查明为历史工作目录编号 s2_toc_workdir / s5_format_switch_workdir。别名改名不做，列为独立事项。

Q3 · frontmatter 统一到什么标准？

v1 决议：模板已写入 AGENTS.md（中文触发条件式、只管路由、allowed-tools 必填最小化、范例 tag-importer）。tag-importer 收敛为 [Read]；wiki-builder 去掉 AskUserQuestion（后端 subprocess 直跑，确认无交互场景）。AGENTS.md 变更提交时需走 PR review。
