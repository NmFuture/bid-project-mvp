# 04 技术标操作串讲（按钮 → API → 服务 → Skill）

> 定位：给全体成员的「垒积木」式串讲。`02-技术标主链路.md` 讲后端骨架，本文补上前端按钮层，把**用户在页面上点的每个按钮**一路串到 **API → 服务 → Skill/Agent → 落库/落卷**。
> 事实来源：前端 `src/workspaces/technical/**`、`src/api/index.js`（technical*API 系列）；后端 `app/api/routes/technical.py`；2026-08-09 逐按钮核对。

## 0. 五层积木：每次点击都穿过同样的五层

```
┌─────────────────────────────────────────────────────────┐
│ L1 页面层   workspaces/technical/pages/*.jsx（按钮文案） │
├─────────────────────────────────────────────────────────┤
│ L2 API 封装 src/api/index.js（technical*API，438-755 行）│
├─────────────────────────────────────────────────────────┤
│ L3 路由层   app/api/routes/technical.py（~100 个端点）   │
├─────────────────────────────────────────────────────────┤
│ L4 服务层   app/services/technical_*（确定性逻辑）       │
├─────────────────────────────────────────────────────────┤
│ L5 智能层   opencode agent + bid-tech-* Skill（LLM）     │
└─────────────────────────────────────────────────────────┘
        数据落点：Postgres（项目/素材）+ MinIO（文件）+ 共享卷（agent 产物）
```

规则只有一条：**按钮不直接碰智能层**。任何 AI 动作都是「按钮 → API → 服务写 manifest → opencode_client 建会话 → agent 跑 Skill → 产物写回共享卷 → 服务收口落库」。记住这条主线，后面每个阶段都是它的实例。

阶段进度条（`TechnicalProjectStageProgress`）是页面的「总导航」：1→目录、2→大纲、3/4→缺口、5/6→共创；项目入口 `/workspace/tech/projects/:id` 按 `currentStage` 自动重定向到对应阶段页。

## 1. 第一块积木：解析页 `/parse/technical`（S0/S1 上传解析 → 参与决策）

组件 `TechnicalTenderReview.jsx`（标题「技术标解析」）。

| 按钮 | API | 走向 |
|---|---|---|
| 上传并解析 | POST `/technical/projects`（建暂存草稿）→ POST `.../parse-results/upload-and-run` | L5：Skill `bid-tech-tender-structured-parser`，分片并行（默认 7 槽）；返回 `queued` 转后台任务，前端 1s 轮询 `.../parse-results/progress` |
| 停止解析 | POST `.../parse-results/cancel` | 中止 AbortController + 后端取消 |
| 重新解析 | POST `.../parse-results/run` | 不重新上传，重跑（failed/stale/cancelled 时出现） |
| 附表「纳入素材库」勾选 / 全选 | POST `.../appendices/{id}/approve`（批量 `.../appendices/approve`） | 解析确认：决定附表 blankDocx 是否入素材库 |
| 附表预览 | GET `.../appendices/{id}/preview` | **OnlyOffice 只读**嵌入 |
| 不参与该项目 | DELETE `/technical/projects/{id}` | 决策=abandon，删草稿，流程终止 |
| 参与该项目并进入素材库 | PUT `/technical/projects/{id}`（`reviewDecision: participate`，走 Wizard 弹窗） | 决策=participate，跳素材库归集素材 |

> 串讲要点：解析是**唯一先建项目再决策**的环节——未参与前项目都是 `isParseDraft` 暂存态，点「解析新的招标文件」会删掉上一个未参与草稿。上传大文件超时 5 分钟，有恢复轮询。

## 2. 第二块积木：目录生成 `/template-directory` → 目录审核 `/outline`

组件 `TechnicalParseResult.jsx` / `TechnicalOutlineReview.jsx`。

| 按钮 | API | 走向 |
|---|---|---|
| 上传模板文件 | POST `.../template-files/upload` | 业主模板可选，未传走 `.../template-fallback` 默认模板 |
| 生成目录 | POST `.../directory-generation/run` | L5：Skill `bid-tech-outline-generator`（6 章+1 附表并行决策）；**全系统唯一真 SSE**：GET `.../directory-generation/stream`，断线回退轮询 |
| 进入目录确认 | PUT `.../stages/1` → 跳 `/outline` | 阶段推进的标准动作（每个阶段页头都有） |
| 保存目录 | PUT `.../outline`（前端先重编号） | 树编辑：+子项/+同级/删除/拖拽/inline 改题全是纯前端，随保存提交 |
| 招标依据标签 | GET `.../outline?fileId=` | **OnlyOffice 搜索桥**：postMessage/BroadcastChannel 驱动右侧招标文件预览定位 |
| 重新生成目录 | POST `.../outline/regenerate` | 注意：这里用轮询，没用 SSE |
| 进入素材匹配 | PUT outline → POST `.../outline/confirm` → POST `.../gaps-detection/run` → PUT `.../stages/2` → 跳 `/gaps` | **全链路最关键的衔接按钮**：确认目录后连发缺口识别 |

## 3. 第三块积木：缺口页 `/gaps`（全前端最重，3565 行）

组件 `TechnicalGapRecognition.jsx`。一个页面承载「缺口识别 → 素材匹配 / AI填写 / 人工补料 → 评审 → 正文装配」四个阶段，按按钮分组记：

**页头工具栏**

| 按钮 | API | 走向 |
|---|---|---|
| 附表填写规则 | POST `.../appendix-source-matrix`（xlsx） | 客户×附表→素材来源规则路由表 |
| 项目事实表 | 弹窗内：POST `.../gaps/facts/specs-upload` → `facts/build` → `facts/curate` | L5：Skill `bid-tech-fact-curator` 只产建议，PUT `.../gaps/facts?confirm=true` 定稿 |
| 生成技术标正文 | POST `.../fill-generation/run` | L4 `tech_assembly` → L5 Skill `bid-tech-assembler` + `format-cleaner` |
| 进入共创导出 | PUT `.../stages/4` → 跳 `/editor` | 需正文生成完成 |

**缺口处理（右侧目录项详情 + 素材卡片）**——三类处理对应缺口决策三态：

| 按钮 | API | 对应决策态 |
|---|---|---|
| 确认 / 已定案 | POST `.../gaps/{gid}/confirm-ready` | ready：系统预选素材直接定案 |
| 选择（素材卡片） | POST `.../gaps/{gid}/select-material` | review_required：候选素材人工挑 |
| AI填写 / 重新AI填写 | POST `.../gaps/{gid}/ai-fill`（附表先弹参考素材选择） | fill_required：L5 Skill `bid-tech-table-filler` / `word-placeholder-filler` |
| 复核通过 | POST `.../gaps/{gid}/artifacts/{aid}/confirm` | AI 产物人工定案；「批量复核通过」是循环调它 |
| 上传素材（兜底区） | POST `.../gaps/{gid}/upload`（仅 .docx） | material_required：人工补料，上传即选用 |
| 一键填写（N） | POST `.../gaps/body-fill` | 正文类缺口后台批量 AI 填写，轮询进度 |
| 忽略本级 | POST `.../gaps/{gid}/title-only` | 仅留标题，子级解冻各自匹配 |

**预览体系**：素材预览走 `GET /technical/materials/raw/{id}/cleaned/preview`；AI 产物预览是 `TechnicalPreviewModal` 的 **OnlyOffice 双栏对比**（参考稿 vs AI结果），弹窗内直接「复核通过 / 上一条 / 下一条」。

## 4. 第四块积木：共创编辑 `/editor`（S4 共创 → 导出）

组件 `TechnicalCoCreationEditor.jsx`。主区 **OnlyOffice 在线编辑**，失败降级 textarea + PUT `.../document/save` 兜底。

| 按钮 | API | 走向 |
|---|---|---|
| 下载Word / 下载PDF | GET `.../final-document`（fileUrl）/ GET `.../final-document/pdf`（先生成再下载） | 当前前端的「导出」就是这两颗按钮 |
| 重新生成正文 | POST `.../fill-generation/run` | 覆盖当前正文，完成后自动刷新 |
| 发送给AI（右栏对话） | POST `.../document/technical-chat` | 通用问答，不改 Word |
| 应用标准/自定义格式 | POST `.../document/technical-format` | 技术标排版预设，应用后刷新 OnlyOffice |

## 5. 旁路积木：素材库 / Wiki / 证书台账 / 日志

- **素材库 `/materials/raw`**（`TechnicalMaterialDB.jsx`）：上传（文件夹/冲突覆盖/v2）、多选批量打标签/删除、自动打标签、文件夹 CRUD、拖拽移动、**切分技术素材**（`split/preview` AI 增强 → `split/confirm`）、OnlyOffice/iframe 预览。清洗/Wiki 进度条轮询 `GET .../materials/pipeline-progress`。
- **Wiki `/materials/wiki`**（只读为主）：「重建Wiki / 刷新重试」→ POST `.../wiki/bootstrap`（后台 job 轮询）；「查看全文」→ GET `.../raw/{id}/fulltext`。
- **证书台账 `/materials/certificates`**：「识别范围」PUT `.../certificates/scopes`、「增量识别」POST `.../certificates/incremental`（轮询 status）、行级重新识别/编辑/删除。为附表「证书编号/有效期」类字段供结构化数据。
- **日志 `/logs`**：审计概览/筛选/导出 CSV（`GET /technical/audit[/export]`）+ 行为流回放。

## 6. 三种特殊交互（横切所有积木）

| 交互 | 真实用法 | 易误判点 |
|---|---|---|
| 进度反馈 | **仅目录生成用 SSE**（EventSource + 断线回退轮询）；解析、缺口填写、事实表、装配、证书、Wiki、流水线全是 1~1.2s 轮询 status | 不要在串讲里说「进度都是 SSE」 |
| OnlyOffice | view：附表预览、招标文件（带搜索桥）、素材/产物预览、AI 双栏对比；edit：共创正文（降级 textarea） | 搜索定位靠 postMessage，不是服务端跳转 |
| 上传 | 招标文件/模板/素材/事实表/来源矩阵，超时 5~30 分钟，409 冲突弹「覆盖/v2」 | 缺口兜底上传只收 .docx 且走 dataURL |

## 7. 已知接缝（串讲时被问到的标准答案；2026-08-12 复核）

- 导出仍只有 final-document 直下载：`export`/`export/check` 前端**连封装都没有**；`forceSave` 有封装（`src/api/index.js:615`）但全 src 零调用。注意：coverage/export 类页面是**有意不接**——`src/workspaces/README.md:15` 明确禁止重新引入项目级 generate/coverage/export 页面。
- 缺口页已接线：单条 `aiFill`、一键 `bodyFill`、缺料台账 PATCH（证书台账页）。仍空挂：`submitReview`、`gaps/recheck`（有封装零调用）、`coverage`（连封装都没有，覆盖率由页面本地从 items 计算）；评审职责仍由 confirm-ready/复核通过承担。
- Wiki 页仍只读：API 封装已收窄为 `wiki.create/update/delete`（移动/附件/AI 摘要封装已无），页面只调 list/bootstrap。
