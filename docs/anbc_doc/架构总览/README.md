# 架构手册（docs/architecture/）

> 本目录是全项目架构的「事实源」：从系统全景 → 业务主链路 → 模块卡片三层组织。
> 阅读顺序：先 `00-系统全景.md`，再按需进入主链路文档，最后查 `modules/` 单模块卡片。
> 交互式总览页：`架构总览.html`（由 `_data/*.json` 汇总生成，可在浏览器直接打开）。

## 目录

| 文件 | 内容 |
|---|---|
| `00-系统全景.md` | 容器/服务拓扑、数据存储、异步任务模型、双轨分层规约 |
| `01-商务标主链路.md` | 上传解析 → 参与决策 → 目录 → 缺口 → AI填写 → 共创导出，每环节 Input/Output |
| `02-技术标主链路.md` | 同上，技术标轨道（含附表 AI 填写链路） |
| `03-素材库与Wiki.md` | 素材上传/清洗/索引/标签/Wiki 生成的数据流 |
| `modules/*.md` | 每个代码模块一张卡片：职责 / Input / Output / 调用链 / 中间数据 |
| `_data/*.json` | 模块卡片的结构化摘要，供 HTML 总览页与后续工具消费 |

## 维护约定

- 模块有实质性行为变更（新增输入输出、改调用链、改状态机）时，同步更新对应 `modules/<name>.md` 卡片与 `_data/` 摘要。
- 主链路文档只描述稳定骨架，不记录冲刺细节；专题攻坚记录仍放 `docs/` 根目录按日期命名。
