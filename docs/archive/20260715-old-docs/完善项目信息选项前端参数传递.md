# 完善项目信息选项前端参数传递

> 改动说明。本文档用于说明“完善项目信息”界面已完成的前端字段调整、数据保存结构，以及后续商务标/技术标预留接口需要提供的数据格式。

## 当前状态

本次改动已覆盖商务标链路和技术标链路。

当前前端仍优先使用静态配置，便于现阶段测试；同时已经为后续素材库 JSON 接入预留了商务标和技术标两套独立接口。由于后续商务标素材库和技术标素材库会分开维护，因此两个链路不再共用同一个选项接口。

## 已完成改动

### 客户字段

已删除原“客户来源”字段，不再区分“重点客户 / 普通客户”。

界面统一显示：

```text
客户 *
```

控件类型：

```text
下拉选择
```

当前客户下拉先使用前端静态配置。后续接入素材库时，客户选项由对应链路的预留接口返回。

如果选项中包含 `其他`，用户选择后直接保存 `其他`，不会额外展示文本输入框。

### 风机机型明细

商务标和技术标都已增加“风机机型明细”区域。

每一行包含：

- `风机机型`：下拉选择，当前来自前端静态配置，后续由接口提供。
- `风机台数`：用户手动输入，必须是正整数。
- `基础形式`：前端固定下拉，不由接口提供。
- `删除`：删除当前机型行。

区域支持：

- 添加多种机型。
- 删除已添加机型。
- 一种机型对应一种台数和一种基础形式。

## 基础形式固定选项

基础形式虽然是下拉框，但不属于素材库接口数据。

固定选项为：

```text
钢塔
混塔
单桩
导管架
多桩承台
```

后续接口不要返回 `foundationTypes`。

## 预留接口

商务标和技术标预留接口已经拆分。

```http
GET /api/business/project-info/options
GET /api/technical/project-info/options
```

当前接口返回静态占位数据：

- 商务标接口 `source` 为 `business-static-placeholder`。
- 技术标接口 `source` 为 `technical-static-placeholder`。

旧的共用接口不再作为入口：

```http
GET /api/project-info/options
```

## 接口需要提供的数据

后续素材库整理完成后，每条链路只需要提供两个数组：

```json
{
  "customers": ["华润", "中电建", "其他"],
  "turbineModels": ["EW10.0-220下置", "EW12.0-252"]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `customers` | `string[]` | 是 | 客户下拉选项。素材库中有什么客户，这里就返回什么客户。 |
| `turbineModels` | `string[]` | 是 | 风机机型下拉选项。素材库中有什么机型，这里就返回什么机型。 |
| `source` | `string` | 否 | 数据来源标识，便于排查。 |
| `updatedAt` | `string` | 否 | 数据更新时间，建议使用 ISO 时间字符串。 |

建议完整返回示例：

```json
{
  "customers": ["华润", "中电建", "华能", "其他"],
  "turbineModels": ["EW10.0-220下置", "EW12.0-252", "EW16.0-252漂浮式"],
  "source": "business-material-library",
  "updatedAt": "2026-06-15T12:00:00+08:00"
}
```

技术标接口返回结构相同，只是数据来源和具体选项可不同：

```json
{
  "customers": ["华能", "国家电投", "三峡"],
  "turbineModels": ["EW8.5-230", "EW16.0-270"],
  "source": "technical-material-library",
  "updatedAt": "2026-06-15T12:00:00+08:00"
}
```

## 接口不需要提供的数据

不要在项目选项接口中返回以下字段：

```json
{
  "foundationTypes": ["钢塔", "混塔"],
  "turbineCounts": [1, 2, 3]
}
```

原因：

- `foundationTypes` 已由前端固定维护。
- `turbineCounts` 由用户在界面中手动输入，并校验为正整数。

## 前端读取规则

前端会读取接口返回的：

```text
customers
turbineModels
```

展示规则：

- `customers` 中有什么，客户下拉就显示什么。
- `turbineModels` 中有什么，风机机型下拉就显示什么。
- 空字符串、重复项会被前端过滤。
- 如果接口暂不可用或返回空数组，前端会回退到当前静态配置。

当前代码中已经按链路预留了两个 API 包装：

```js
businessProjectInfoOptionsAPI.get()
technicalProjectInfoOptionsAPI.get()
```

## 项目保存结构

创建或更新项目时，前端会提交完整多机型数组：

```js
turbineModels: [
  {
    model: 'EW10.0-220下置',
    turbineCount: '10',
    foundationType: '单桩',
    source: 'static-options'
  },
  {
    model: 'EW12.0-252',
    turbineCount: '6',
    foundationType: '导管架',
    source: 'static-options'
  }
]
```

为兼容旧流程，前端同时保留第一条有效机型作为主机型：

```js
turbineModel: {
  model: 'EW10.0-220下置',
  turbineCount: '10',
  foundationType: '单桩',
  source: 'static-options'
}
```

客户字段继续写入现有字段，便于兼容项目列表、素材路径和后续流程：

```js
{
  customerName: '华润',
  customerCanonicalName: '华润',
  materialCustomerName: '华润',
  owner: '华润'
}
```

## 后续素材库接入建议

商务标素材库和技术标素材库建议分别生成或维护各自的选项 JSON，再由后端分别暴露到对应接口。

建议流程：

```text
商务标素材库目录 / 技术标素材库目录
  -> 分别生成 customers、turbineModels
  -> 后端缓存或读取整理后的 JSON
  -> 分别返回商务标/技术标项目选项接口
  -> 前端按链路展示对应下拉选项
```

不建议每次打开前端下拉框都实时扫描素材库目录。更合理的做法是：

- 素材库更新后刷新或重新生成 JSON。
- 后端读取整理后的 JSON。
- 后端可增加缓存，避免频繁目录扫描。
