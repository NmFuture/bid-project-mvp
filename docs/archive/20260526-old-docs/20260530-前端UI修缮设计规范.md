# 投标智能体平台 · 前端 UI 修缮设计规范

> 目标：在**不改主题色、不改信息架构**的前提下，把当前"能用但内部互相打架"的样式系统收口成一套**自洽、可维护、视觉统一**的设计系统。
> 方法：参考《使用 Codex 和 Claude Code 重构前端 UI》的工作流——**先文档/Spec，再分阶段落地，组件化描述，Storybook 兜底**。

---

## 一、现状诊断（看清楚再动手）

### 1.1 技术栈与结构（健康）

- React 19 + React Router 7 + Tailwind 4（`@tailwindcss/vite`），**无第三方组件库**，全部自研。
- 目录分层清晰：`components/ui`（原子）、`components/shared`（业务无关复用）、`workspaces/{business,technical}`（按端/业务分包）。这套分层符合重构文档"多端通用部分组件化"的思路，**值得保留**。
- 设计 token 集中在 `src/index.css` 的 `@theme`，是一套完整的 Material-3 命名体系（primary / surface / on-* / container 层级）。

### 1.2 核心矛盾（必须修）

| # | 问题 | 证据 | 影响 |
|---|------|------|------|
| **A** | **Token 与 base 层互相打架** | `Dashboard.jsx` 用 `bg-gradient-to-br` 做指标卡；但 `index.css` 里 `main [class*="bg-gradient"]{background-image:none!important}` 直接抹掉 | 设计意图被静默吃掉，渐变卡片在 `main` 里全变纯色，开发者改不动也看不出为什么 |
| **B** | **同一个蓝色三套硬编码** | header `#05202E`/`#154e7a`、侧栏 `#0067B6`/`#0f77c4`、token `--color-primary:#0068b7`、StageProgress `#0067B6` | 主题色无法一处改动全局生效，"保持主题色不变"的诉求反而最难维护 |
| **C** | **大量 `!important` 收口** | `index.css` 里 `main [class*="shadow"]`、`button{border:none!important}`、`.page-header-actions>button{height:30px}` 等全局强制 | 是历史"补丁摞补丁"留下的，新组件一写就被全局规则改形，难以预期 |
| **D** | **字号 scale 被压平** | `--text-2xl`~`--text-4xl` 全部 = `1.125rem`；`PageHeader` 却用 `text-3xl md:text-4xl font-extrabold` | 标题层级在视觉上塌缩成一个字号，信息层次丢失 |
| **E** | **死代码** | `src/App.css` 是 Vite 模板残留（`.hero`/`.vite`/`#next-steps`），未被引用 | 噪音 |
| **F** | **阴影/圆角不统一** | 卡片有的 `rounded-xl` 有的 `rounded-md`；阴影有的 `shadow-[0_8px_24px...]` 有的被 base 改成 `0 1px 2px` | 同类卡片观感不一致 |

### 1.3 结论

> 不是"重画 UI"，而是**收口设计系统**：把散落的硬编码色、被 `!important` 反复纠正的规则、互相矛盾的字号，统一回 token，让一套规则自洽。主题色、布局、信息架构**全部保持现状**。

## 二、设计原则（修缮的北极星）

承接重构文档的"为功能服务、规规矩矩第一"，落到本项目：

1. **企业级克制**：投标是严肃的专业工作。少渐变、少光效、信息密度优先于装饰。当前 base 层"扁平化"方向是对的，只是执行不彻底。
2. **单一事实来源（Single Source of Truth）**：所有颜色、间距、圆角、阴影、字号 **只从 token 取**，组件里不出现裸 hex。
3. **层级靠"对比"而非"颜色种类"**：用字号/字重/留白拉开层级，而不是引入更多颜色。
4. **可预测**：删掉 `main [class*=...]` 这类"猜测式"全局覆盖，改成组件显式声明样式。
5. **主题色锁定**：primary 蓝、secondary 绿、AI-accent 青——**色值一个不改**，只是收敛到 token 统一引用。

## 三、设计 Token 修缮方案

### 3.1 颜色：保持色值，收敛引用

主题色**完全不变**，但把目前散落在组件里的 header/侧栏硬编码 hex **提升为 token**，让"改主题"成为可能（即使现在不改）：

```css
@theme {
  /* —— 主题色：保持现状，色值不动 —— */
  --color-primary: #0068b7;
  --color-secondary: #14a83b;
  --color-ai-accent: #18b7d9;
  /* ...（其余 on-*/container 维持原样）... */

  /* —— 新增：把 Shell 的深色链路收为 token（色值取自现有硬编码）—— */
  --color-shell-header: #05202e;        /* 顶栏背景（原硬编码）*/
  --color-shell-header-border: #154e7a; /* 顶栏分隔线 */
  --color-shell-rail: #0067b6;          /* 侧栏背景（原硬编码）*/
  --color-shell-rail-border: #0f77c4;
  --color-shell-rail-active: #4c95cd;   /* 侧栏选中态 */
}
```

> 落地后，`AppShell.jsx` 里 `bg-[#05202E]` → `bg-shell-header`，`bg-[#0067B6]` → `bg-shell-rail`，`StageProgress` 的 `#0067B6` → `bg-primary`（注意：侧栏蓝 `0067B6` 与 primary `0068b7` 仅差 1，**建议统一为 primary**，消除"两个几乎一样的蓝"）。

### 3.2 字号：恢复真实层级

当前把 2xl~4xl 全压成 18px 是为了"企业规范 18/16/14/12"，但这让 `PageHeader` 的 `text-4xl font-extrabold` 形同虚设。改为**语义化标题 token**，既守住规范上限又恢复层级：

```css
@theme {
  /* 正文体系守住 18/16/14/12 */
  --text-xs: 0.75rem;   /* 12 辅助 */
  --text-sm: 0.875rem;  /* 14 正文（base）*/
  --text-base: 0.875rem;/* 14 */
  --text-lg: 1rem;      /* 16 小标题 */
  --text-xl: 1.125rem;  /* 18 区块标题 */
  /* 页面级标题单独给一档，不再全压平 */
  --text-2xl: 1.25rem;  /* 20 卡片/弹窗主标题 */
  --text-3xl: 1.375rem; /* 22 页面主标题（对齐 Dashboard 现用的 22px）*/
}
```

> 配套：`PageHeader` 的 `text-3xl md:text-4xl font-extrabold` 收敛为 `text-3xl font-bold`（22px/600），与 `Dashboard` 的 `text-[22px] font-bold` 自动对齐，**消除两套标题写法**。

### 3.3 间距 / 圆角 / 阴影：三档制

引入三档语义，禁止再写一次性的 `shadow-[0_8px_24px-12px...]`：

```css
@theme {
  --radius-card: 0.75rem;   /* 12px 卡片/弹窗 */
  --radius-control: 0.5rem; /* 8px 按钮/输入/徽章容器 */
  --radius-pill: 9999px;    /* 胶囊 */

  --shadow-card: 0 1px 2px rgba(13, 33, 55, 0.05);          /* 静态卡片 */
  --shadow-card-hover: 0 8px 24px -12px rgba(0, 104, 183, 0.35); /* 悬浮抬升 */
  --shadow-overlay: 0 12px 28px -16px rgba(0, 62, 111, 0.20);    /* 弹窗 */
}
```

> 三档对应当前实际在用的三种阴影值，只是统一命名。落地后删除 base 层的 `main [class*="shadow"]{...!important}`——因为来源已经被收口，不再需要"事后纠正"。

## 四、组件层修缮（用组件名说话）

参照重构文档"用 Accordion/Trigger/Content 而非长描述"，本项目的原子组件命名要稳定、职责单一。以下是**需要收口或补齐**的清单：

### 4.1 已有原子（巩固，不重写）

| 组件 | 现状 | 修缮动作 |
|------|------|---------|
| `ui/Button` | variant/size 体系完整 | 把 `shadow-[0_1px_2px...]` 内联值换成 `shadow-card`；其余保留 |
| `ui/Badge` `ui/IconButton` `ui/Toolbar` `ui/Dialog` | 基础可用 | 圆角/阴影换 token，逻辑不动 |
| `shared/StatusBadge` | 6 语义态，已统一 | **作为状态色唯一出口**，禁止页面再手写 `bg-primary-fixed text-...` 状态条 |
| `shared/EmptyState` | OK | 统一所有"空/错/无权限"出口 |
| `shared/PageHeader` | 字号过大 | 见 3.2，收敛标题 |
| `shared/StageProgress` `StageBreadcrumb` | 硬编码 hex | 节点色 `#14A83B`→`secondary`、`#0067B6`→`primary` |

### 4.2 建议新增的原子（消除重复写法）

页面里反复手搓、应抽成组件的模式：

- **`ui/Card`**：合并目前 `DataCard` + 各页 `rounded-xl border ... bg-white` 的散写。统一 `radius-card` + `shadow-card`，`hover` 走 `shadow-card-hover`。Dashboard 的 ProjectCard/ParallelProjectCard 都应基于它。
- **`ui/Metric`**（指标卡）：取代 Dashboard 里被 `!important` 吃掉渐变的 `MetricCard`。**改为实色 container 底 + 左侧 3px 强调条**（呼应 `.ai-marker` 既有语言），不再依赖会被 base 抹掉的 gradient。
- **`ui/ProgressBar`**：项目卡里 `h-1.5 ... bg-gradient-to-r` 出现多次，抽成一个组件，颜色按 `value` 阈值取 token。
- **`shared/SectionPanel`**（区块容器）：Dashboard 的 `PanelHeader` + 卡片体反复出现，抽成 `<SectionPanel icon title hint action>`。

> 这些不是"新功能"，是把**已经存在的重复 JSX** 收成命名组件——降低 AI 后续改动时破坏样式的概率。

## 五、视觉呈现修缮要点（逐处对齐）

### 5.1 指标卡（Dashboard）—— 最该改的一处

**问题**：用了 `bg-gradient-to-br from-primary-fixed ...`，但 `main` 里渐变被 `!important` 删除 → 实际渲染成 from 色的纯色块，丢了设计意图。

**方案**（二选一，推荐 B）：
- A. 删除 base 的 gradient 抹除规则，让渐变恢复——但与"扁平化企业风"方向相悖。
- B.（推荐）**改为实色卡 + 左强调条 + 大号数字**：
  ```
  ┌─────────────────────────┐
  ┃ 在跑项目                  │   ← 左侧 3px primary 强调条
  ┃ 12        [icon]         │   ← text-3xl tabular-nums
  └─────────────────────────┘
  ```
  底色用 `surface-container-low`，强调条/图标用对应语义色。克制、统一、不被 base 吃掉。

### 5.2 卡片圆角阴影统一

全站卡片统一 `radius-card`(12) + `shadow-card`；可点击卡片 hover 用 `shadow-card-hover` + `border-primary/40`（保留现有 Dashboard 的悬浮抬升手感，只是统一来源）。删除 `rounded-md`/`rounded-xl` 混用。

### 5.3 Shell 深色链路

顶栏/侧栏色值不变，但全部走 §3.1 新 token。**统一侧栏蓝到 primary**（`0067B6`→`0068b7`），让"平台蓝"只有一个色。

### 5.4 表格

`index.css` 的 `table thead/tbody` 全局规则保留（这是好的统一），但把硬编码 `#F7F7F7`/`#1f3d56`/`#d4dde7` 换成 `surface-container-low`/`on-surface`/`outline-variant` token。

### 5.5 动效

现有 `animate-fade-in`/`float-in`/`stagger` 体系克制得当，**保留**。仅确认 `prefers-reduced-motion` 分支已覆盖（已覆盖，✓）。

## 六、落地阶段拆分（承接重构文档"分阶段 + comment 讨论"）

> 每阶段独立可验收、可回滚。**Phase 0/1 是纯收口，零视觉风险，先做。**

| 阶段 | 内容 | 风险 | 验收 |
|------|------|------|------|
| **0 清理** | 删 `App.css`(死代码)；建本规范文档；列出全部裸 hex 位置 | 无 | 构建通过、无引用残留 |
| **1 Token 收口** | §3 全部 token 落入 `@theme`；新增 shell/radius/shadow token | 低 | token 存在、未被消费也不报错 |
| **2 Base 层瘦身** | 删 `main [class*="bg-gradient"/"shadow"]` 抹除规则；表格/控件硬编码换 token | 中（可能暴露被掩盖的样式） | 逐页走查无塌陷 |
| **3 原子收口** | Button/Badge/StatusBadge/PageHeader 换 token；新增 `ui/Card` `ui/Metric` `ui/ProgressBar` `shared/SectionPanel` | 中 | Storybook 枚举各态 |
| **4 页面对齐** | Dashboard → 用新 Metric/Card；其余页面卡片/标题逐个换组件 | 中 | 双 workspace + 三角色逐页对比 |
| **5 Storybook 兜底** | 在 `AGENT.md` 加规则：新组件须有枚举全状态的 story（正常/空/加载/错误/禁用） | 低 | story 覆盖率 |

> 建议：Phase 2 之前先用 Codex 做一次"裸 hex / `!important` / `bg-gradient` 用法"的全量 grep 清单（约定俗成它擅长架构梳理），Opus 负责按清单逐个改前端（它擅长写前端、改交互）——正是重构文档说的**异构 multi-agent 分工**。

## 七、给 AI 协作者的描述模板（省 token）

后续让 AI 改这套 UI 时，用组件名 + token 名，不要长描述。例：

- ❌ "把那个有渐变的统计卡片改成纯色的，左边加一条蓝线，数字大一点"
- ✅ "把 Dashboard 的 `MetricCard` 重构为 `ui/Metric`：底色 `surface-container-low`，左侧 3px `--color-primary` 强调条，数值用 `text-3xl tabular-nums`，移除 `bg-gradient-*`。"

---

## 八、不做的事（边界）

- **不改主题色**（primary/secondary/ai-accent 色值锁定）。
- **不改信息架构 / 导航 / 路由**（6 项一级导航、双 workspace、stage flow 全保留）。
- **不引入第三方 UI 库**（自研体系已成型，引入反而破坏一致性）。
- **不改后端契约 / 业务逻辑**。
