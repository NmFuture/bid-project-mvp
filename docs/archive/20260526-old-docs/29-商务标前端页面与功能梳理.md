# 商务标前端页面与功能梳理

基线：2026-05-24 当前工作树。本文只梳理当前前端代码已经存在的商务标相关页面与功能，不把后续规划当成已完成能力。

## 1. 总体结论

当前商务标不是严格按 `S0-S6` 每个阶段独立一个页面呈现，而是采用了“主流程页面 + 合并阶段页面 + 支撑页面”的结构。经本轮确认，商务标主流程不再把 `/generate`、`/coverage`、`/export` 作为必经页面。

商务标相关前端页面可以按 11 个用户可见路由页面 + 1 个项目入口跳转路由理解：

| 类别 | 数量 | 页面范围 |
| --- | ---: | --- |
| 首页与项目入口 | 2 | 工作台、商务标项目列表 |
| 商务标主流程 | 5 | 解析、模板与目录、目录审核、素材匹配、共创编辑导出 |
| 素材与管理支撑 | 4 | 结构化素材库、素材 Wiki、日志、设置 |
| 路由跳转页 | 1 | 项目入口自动跳转页 |

需要特别注意：当前商务标前端把原来的“生成标书”能力合并进了 `S3 商务标素材匹配` 页面；商务标项目进入第 4 阶段时仍在 `/gaps` 内处理正文生成，第 5、6 阶段进入 `/editor` 完成共创和下载，而不是独立的 `/generate` 或 `/export` 页面。产品口径上，商务标可以收敛为 6 个主入口：`/parse/business`、`/workspace/business/projects`、`/template-directory`、`/outline`、`/gaps`、`/editor`。

## 2. 主流程页面

| 阶段/入口 | 前端路由 | 前端组件 | 页面功能 |
| --- | --- | --- | --- |
| 工作台 | `/dashboard` | `Dashboard.jsx` | 展示当前用户的项目概览、双流程并列项目卡片、待办和活动记录。TB 角色看到技术标/商务标并列入口，B 角色看到自己负责的商务标项目。 |
| 商务标解析入口 | `/parse/business` | `BusinessTenderReview.jsx` | 新建商务标解析项目，上传商务招标文件，查看解析进度和结构化解析结果。当前页面重点呈现商务评分、报价评分、符合性审查、响应要求、资质支撑、保证金/承诺函线索，并支持附件模板预览、确认入库、决定参与或放弃。 |
| 商务标项目列表 | `/workspace/business/projects` | `BusinessProjectList.jsx` + `BusinessProjectWizardModal.jsx` | 查看商务标项目列表，按商务标工作区锁定标书类型，创建/编辑/删除项目。新建项目时填写项目名称、客户、项目来源、负责人、日期等；商务标不要求填写技术标的投标机型。 |
| 项目入口跳转 | `/workspace/business/projects/:id` | `BusinessProjectEntryRedirect.jsx` | 不是业务操作页。打开项目时根据项目 `reviewDecision` 和 `currentStage` 自动跳转：未决定参与时回到商务标解析页；已参与后进入当前阶段对应页面。 |
| S1 模板与目录 | `/workspace/business/projects/:id/template-directory` | `BusinessParseResult.jsx` | 查看解析结果，上传商务投标文件模板，或启用默认商务模板兜底；根据招标要求和模板生成投标目录，并进入下一阶段。商务标如果没有上传模板且没有启用默认模板，会提示先上传商务标模板文件。 |
| S2 审核目录 | `/workspace/business/projects/:id/outline` | `BusinessOutlineReview.jsx` | 审核、编辑并确认投标文件目录。支持新增根节点、子节点、同级节点，修改标题，删除、移动、展开/收起目录，并查看目录依据。商务标会保留商务目录来源中的章节编号。 |
| S3 素材匹配 | `/workspace/business/projects/:id/gaps` | `BusinessGapRecognition.jsx` | 商务标当前最核心的执行页。按商务目录展示响应任务，生成/更新商务缺口计划，维护商务标项目事实表，匹配模板和素材，上传补充材料，预览素材，忽略或确认任务，触发 AI 起草，并可直接生成商务标正文。 |
| S4/S5/S6 共创导出 | `/workspace/business/projects/:id/editor` | `BusinessCoCreationEditor.jsx` | 当前商务标后半段主页面。已从共享 `CoCreationEditor.jsx` 拆出，页面固定商务标文案、文件名、页眉部分和格式接口。在线编辑商务标正文，嵌入 OnlyOffice 或回退文本编辑器，支持保存、商务标 AI 对话、改写建议、格式规范应用、完成共创，并在同一界面下载最终版 Word。 |

## 4. 当前商务标阶段与页面的对应关系

当前对外口径仍可说是 `S0-S6`，但前端呈现不是 7 个完全独立页面。

| 业务阶段 | 当前主要页面 | 说明 |
| --- | --- | --- |
| S0 解析/参与判断 | `/parse/business` | 商务招标文件解析、评分/附件/承诺函线索审核、参与或放弃。 |
| S1 模板与目录 | `/template-directory` | 上传商务模板或使用默认模板，生成目录。 |
| S2 审核目录 | `/outline` | 人工确认目录结构。 |
| S3 缺口处理/素材匹配 | `/gaps` | 目录响应任务、素材匹配、补料、AI 起草、事实表维护。 |
| S4 生成标书 | `/gaps` 内的“商务标正文生成” | 当前商务标把正文生成合并在 S3 页面里，`/generate` 不再作为商务标主流程页面。 |
| S5 共创 | `/editor` | OnlyOffice 编辑、AI 对话、改写建议、格式处理。 |
| S6 导出 | `/editor` 内下载 | 当前主流程在编辑页内完成最终 Word 下载，`/export` 不再作为商务标主流程页面。 |

## 5. 为什么 UI 看起来不像完整 S0-S6

原因主要有四个：

1. `ProjectStageProgress` 视觉上把阶段压缩为 4 组：目录生成、目录确认、素材匹配、共创导出，而不是直接显示 S0-S6。
2. `businessStageFlow` 对商务标有特殊路由：商务标第 4 阶段导向 `/gaps`，第 5、6 阶段导向 `/editor`，而不是分别导向 `/generate` 和 `/export`。
3. `BusinessGapRecognition` 页面已经内置“商务标正文生成”，页面文案也明确写了“S3 已合并原生成标书阶段”。
4. `/generate`、`/coverage`、`/export` 商务标路由已删除，不再作为兼容入口保留。

## 6. 下一步需要统一的产品口径

如果要让商务标流程更容易向客户解释，建议先确定一个口径：

| 决策点 | 选项 A | 选项 B | 建议 |
| --- | --- | --- | --- |
| S4 是否独立页面 | 保持现在：S3 内生成正文 | 恢复 `/generate` 为商务标 S4 主页面 | 已确认采用选项 A，`/generate` 不进商务标主流程。 |
| S6 是否独立页面 | 在 `/editor` 内直接下载 | 强制跳转 `/export` 做最终导出 | 已确认采用选项 A，`/export` 不进商务标主流程。 |
| 覆盖诊断是否给商务标使用 | 暂时隐藏或弱化 | 改造成商务标响应覆盖检查 | 当前采用选项 A，`/coverage` 不进商务标主流程。 |
| 阶段条怎么展示 | 继续 4 组压缩 | 明确显示 S0-S6 | 给客户演示时建议显示 S0-S6，否则容易误解“缺阶段”。 |

## 7. 商务标主流程路由收敛建议

后续前端实现可以按下面口径处理：

| 当前路由 | 商务标主流程是否保留 | 建议处理 |
| --- | --- | --- |
| `/workspace/business/projects/:id/generate` | 不保留 | 已删除商务标路由。 |
| `/workspace/business/projects/:id/coverage` | 不保留 | 已删除商务标路由。 |
| `/workspace/business/projects/:id/export` | 不保留 | 已删除商务标路由。 |

最终客户可见的商务标主流程建议统一为：

`/parse/business` -> `/workspace/business/projects` -> `/template-directory` -> `/outline` -> `/gaps` -> `/editor`
