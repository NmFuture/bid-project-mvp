# 目标一与目标二最终目标

> 日期：2026-05-05
> 目的：明确附表填写与素材库待填写内容生成的最终目标、验收基准、交付产物和持续迭代规则。

## 1. 总目标

建设一个可泛化的技术标填报 Skill，能够面对新的招标项目、新素材库、新附表、新章节模板时，自动完成：

- 资料读取与证据索引。
- 结构化事实抽取。
- 素材库待填写内容生成。
- 技术附表填写。
- 证据链保留。
- 不确定内容标黄。
- 与人工填写版本对比检测。
- 未达标时自动诊断和迭代修复。

最终判断标准不是“跑完一次流程”，而是自动结果达到人工填写版本至少 85% 的效果。

## 2. 共同硬性要求

目标一和目标二共同遵守以下规则：

- 不写死具体表格类型、章节类型、字段类型或项目名称。
- Skill 必须具有泛化性，脚本、Prompt、配置、文档、评测逻辑都不能直接写死当前样例、当前 70 多张表、当前项目或人工答案。
- 禁止通过硬编码答案、硬编码文件名、硬编码表名、硬编码单元格位置、硬编码章节文本、硬编码评分豁免等作弊方式达到验收标准。
- 当前人工版本只能作为评测基准和误差分析依据，不能作为生成阶段的答案来源。
- 填写优先级固定为：`项目定制 > 客户定制 > 通用/标准素材`。
- 主要机型、项目名称、容量、台数、轮毂高度、性能承诺、交货计划等核心事实必须全局一致。
- 每个关键值、关键段落、关键表格行必须保留证据链。
- 证据链至少包括：来源文件、章节/表格/段落位置、原文片段、事实类型、置信度。
- 找不到证据、证据冲突、推理链不足的内容不能硬编，必须标黄高亮。
- 检测必须以人工填写版本为 gold answer。
- 自动结果必须达到人工版本至少 85%。
- 如果检测低于 85%，流程不能停止，必须进入诊断、补检索、修复、再评测循环。

## 4. 目标一：附表填写

### 4.1 目标定义

目标一是把空白技术附表自动填写到接近人工填写版的质量。

系统需要理解每张附表的行列语义、单位、上下文、引用关系和填写意图，然后从招标文件、项目定制素材、客户定制素材、通用素材和结构化事实库中寻找证据并填写。

目标一不是为现有 70 多张附表逐一写死脚本，而是形成可泛化的附表填写能力。

### 4.2 输入

- 空白附表模板。
- 招标文件。
- 项目定制素材。
- 客户定制素材。
- 通用/标准素材。
- 目标二沉淀的结构化事实库。
- 人工填写完成的附表，作为验收基准。

### 4.3 输出

- 自动填写后的全部附表 Word 文件。
- 标黄版附表：低置信、无法填写、冲突内容全部高亮。
- 每个填写单元格的证据链。
- 结构化事实库更新结果。
- 质量检测报告。

结构化事实库至少覆盖：

- 项目名称。
- 招标编号。
- 招标人/业主/管理单位。
- 投标机型。
- 单机容量。
- 台数。
- 总容量。
- 轮毂高度。
- 叶轮直径。
- 叶尖高度。
- 安全等级。
- 风资源参数。
- 发电量和等效小时数。
- 功率曲线保证率。
- 单台和全场可利用率。
- 主要部件更换率。
- 供货范围。
- 交货进度。
- 生产基地。
- 业绩统计。
- 认证与测试情况。
- 服务和质保承诺。

### 4.4 检测与验收

目标一检测必须以人工填写版附表为 gold answer。

检测维度包括：

- 逐表填写覆盖率。
- 逐单元格事实匹配度。
- 数值、单位、范围、百分号、型号等格式一致性。
- 空白应填项漏填率。
- 错填率。
- 关键承诺项准确率。
- 证据链完整率。
- 标黄项是否合理。

验收标准：

- 总体效果达到人工版本至少 85%。
- 每张附表需要单独评分。
- 关键参数表、承诺表、交货进度表、供货范围表等重点表不能只靠总体均分通过。
- 低于 85% 时，必须继续诊断和修复。

## 5. 目标二：素材库待填写内容生成

### 5.1 目标定义

目标二是把素材库中的 `待填写-*`、`机型固化&待填写-*` 等文件，自动补全成可直接进入技术标正文的成稿素材。

目标二不是只生成“能读的素材”，而是同时完成两件事：

- 生成可直接拼入标书正文的章节级素材。
- 沉淀可被附表、正文其他章节、评分索引复用的结构化事实。

因此，目标二是“素材资产成稿 + 事实库沉淀 + 证据链管理”的任务。

### 5.2 输入

- 素材库中的待填写文件。
- 素材库中的机型固化文件。
- 招标文件。
- 项目定制文件。
- 客户定制文件。
- 通用/标准素材。
- 目标一和历史流程已有的结构化事实。
- 人工填写完成的目标版本，作为验收基准。

### 5.3 输出

- 填写后的素材库 Word 文件，保持原目录结构。
- 可直接拼接进技术标正文的成稿章节。
- 标黄版素材：无法确定、证据不足、冲突内容全部高亮。
- 结构化事实库，供目标一附表填写和正文其他章节复用。
- 每个关键值、关键段落、关键表格行的证据链。
- 素材库质量检测报告。

### 5.4 典型待填写对象

目标二至少覆盖以下类型，但不能局限于这些类型：

- 投标说明函。
- 技术评分标准索引表。
- 投标关键数据一览表。
- 供货保障能力。
- 投标机型业绩情况。
- 投标总体方案概述。
- 供货范围概述。
- 投标方案技术先进性综述。
- 项目投标设备综合技术参数与性能指标。
- 投标机型样机认证与测试专题。
- 投标项目设备交货进度。
- 设备运行和维护专题。
- 产品交付、考核及验收。
- 项目风机各子系统中带待填写内容的专题。

### 5.5 检测与验收

目标二检测必须以人工填写版本为 gold answer。

检测维度包括：

- 章节结构是否与人工版本一致或等价。
- 待填写占位符是否被正确消解。
- 关键事实是否与人工版本一致。
- 表格行列是否完整。
- 长段落是否保留原素材可复用内容，并正确替换项目化内容。
- 章节索引、评分索引是否正确。
- 是否生成可直接拼入正文的内容。
- 是否沉淀结构化事实。
- 证据链是否完整。
- 标黄项是否合理。

验收标准：

- 自动生成素材达到人工版本至少 85%。
- 检测不只看文本相似度，还要看事实一致性、表格完整性、章节可拼接性和引用索引正确性。
- 低于 85% 时，必须继续诊断和修复。

## 6. 目标一与目标二的关系

目标二是事实与正文素材生产层。

目标一是附表落表层。

两者不能割裂运行。理想流水线如下：

```text
原始资料/招标文件/素材库
  -> 证据索引
  -> 结构化事实库
  -> 目标二：成稿素材生成
  -> 目标一：附表填写
  -> 全局一致性校验
  -> 与人工版本对比评分
  -> 低于 85% 则诊断修复并再次评测
```

同一组事实必须跨目标复用，例如：

- 投标机型。
- 项目容量。
- 台数。
- 轮毂高度。
- 发电量。
- 等效小时数。
- 功率曲线保证率。
- 单台和全场可利用率。
- 主要部件更换率。
- 主机和叶片生产基地。
- 供货工具数量。
- 业绩汇总。

## 7. 迭代闭环

每轮自动填写后必须执行检测。

如果任一目标低于 85%，流程进入以下闭环：

1. 对比人工版本，定位缺失项、错填项、格式问题和证据问题。
2. 判断失败原因：检索缺失、事实抽取错误、表格理解错误、写入失败、证据冲突或格式损坏。
3. 补充检索范围或调整事实抽取。
4. 重新生成对应素材或附表。
5. 重新运行检测。
6. 达到 85% 后输出结果和质量报告。

不允许将“已生成一版文件”视为完成。

## 8. 最终交付标准

最终交付必须同时满足：

- 目标一附表填写达到人工版本至少 85%。
- 目标二素材生成达到人工版本至少 85%。
- 通过泛化性检查：实现中不存在面向当前样例、当前项目、当前人工答案的硬编码或作弊逻辑。
- 关键值有证据链。
- 不确定项、冲突项、无法填写项已标黄。
- 质量报告能说明每个目标的达标情况和剩余差距。
- 结构化事实库能同时反哺正文素材生成和附表填写。
- 生成结果可被后续 S4 生成标书流程直接使用。
