# 业绩库项目级拆分与合同附件设计说明

## 1. 背景

原始业绩库通常按一个机型或一个场景维护两类文件：

- 汇总表：例如 `海上8MW及以上业绩_汇总表.docx`、`陆上11MW业绩_汇总表.docx`。
- 合同包：例如 `海上8MW及以上业绩_合同.docx`、`陆上11MW业绩_合同.docx`。

旧实现会把合同包作为一个大附件挂在业绩分类下。这样能保存文件，但无法精确支持后续按项目、型号、年份筛选和重组，也无法让用户只选择某几个项目合同进入标书。

本轮目标是把业绩库升级成“结构化条目库 + 项目级合同附件库”：

- 每一行业绩表数据拆成一个独立项目条目。
- 从汇总表里提取关键筛选字段，重点是 `型号` 和 `交货期/投运时间`。
- 合同包按项目拆成多个独立 DOCX，每个项目条目关联一个项目合同附件。
- 后续生成标书时，可以按机型、交货年、投运年、项目等多条件筛选，再把勾选的项目合同重新拼接。

## 2. 最终用户形态

业绩库列表页展示的是业绩分类，例如：

| 分类 | 明细 | 型号 | 时间 | 附件 |
| --- | ---: | --- | --- | --- |
| 陆上11MW业绩 | 2 条 | 11-230 | - | 项目合同：2 个 |
| 海上8MW及以上机型合同业绩表 | 21 条 | EW11.0-208 等 | 2020-2026 | 项目合同：21 个 |

进入某个分类详情后，表格每一行是一个项目条目，条目上可以下载它自己的项目合同，而不是下载整个大合同包。

## 3. 数据结构

### 3.1 业绩分类

表：`performance_categories`

用途：

- 保存分类名称、场景、功率段、标签、状态。
- 聚合展示该分类下的机型、合同年、交货年、投运年。
- 关联原始汇总表附件和合同包附件。

### 3.2 业绩条目

表：`performance_items`

用途：

- 一行汇总表对应一条业绩条目。
- 保存原始行字段 `row_values`，同时沉淀核心字段：
  - `project_name`
  - `customer_name`
  - `turbine_model`
  - `turbine_models`
  - `delivery_or_operation_time`
  - `contract_year`
  - `delivery_year`
  - `operation_year`
  - `time_facts`

### 3.3 分类附件

表：`performance_attachments`

用途：

- 保存原始汇总表 DOCX。
- 保存原始合同包 DOCX。
- 合同包只作为拆分来源，不再作为最终筛选颗粒度。

### 3.4 项目级附件

表：`performance_item_attachments`

用途：

- 保存拆出来的单项目合同 DOCX。
- 每条记录绑定：
  - `category_id`
  - `item_id`
  - `source_attachment_id`
  - `file_name`
  - `minio_key`
  - `format_version`
  - `match_confidence`
  - `match_method`
  - `source_title`
  - `source_block_start`
  - `source_block_end`

`format_version` 是生成格式版本。本轮升级到 `3`，用于让旧项目合同在打开详情时自动重拆。

## 4. 汇总表解析规则

入口函数：`parse_performance_summary_docx`

核心目标是从 Word 表格中识别表头和行数据，保留完整字段，同时提取可筛选字段。

### 4.1 型号提取

优先识别以下表头：

- `型号和规格`
- `型号`
- `机型`
- `风机型号`

解析结果：

- `turbineModel`：原始型号文本。
- `turbineModels`：拆分后的型号数组。

拆分逻辑：

- 支持空格、逗号、顿号、斜杠、分号分隔。
- 只保留看起来像机型的片段。
- 典型例子：
  - `SG8.0-167` -> `["SG8.0-167"]`
  - `EW8.0-230 EW8.5-230` -> `["EW8.0-230", "EW8.5-230"]`

### 4.2 时间提取

优先识别以下表头：

- 合同时间：`合同时间`、`合同日期`、`签约时间`、`签订时间`、`签订日期`
- 交货时间：`交货期`、`交付时间`、`交货时间`、`交付日期`
- 投运时间：`投运时间`、`投运日期`、`并网时间`、`运行时间`
- 混合字段：`交货期/投运时间`、`交货/投运`、`交付/投运`

解析结果：

- `deliveryOrOperationTime`：用于页面展示的原始时间文本。
- `contractYear`：合同年。
- `deliveryYear`：交货年。
- `operationYear`：投运年。
- `timeFacts`：保存原始时间文本和提取到的年份集合。

如果只有 `交货期/投运时间` 混合列，会把该年份同时作为交货年和投运年的候选，便于筛选。

## 5. 合同拆分规则

入口函数：`split_performance_contract_docx`

目标是把一个合同包拆成多个项目合同块。

### 5.1 分块方式

优先根据合同标题块识别项目起点。若没有明显标题，则退化为根据分页符识别起点。最后兜底为整个文档作为一个合同块。

每个合同块保留：

- 原始标题。
- 块起止位置。
- 原始段落、表格、图片、关系文件。
- 生成后的独立 DOCX 内容。

### 5.2 项目匹配

入口函数：`match_contract_chunks_to_items`

匹配优先级：

1. 项目名称文本匹配。
2. 如果项目名称匹配置信度不足，则按汇总表行序与合同块顺序兜底匹配。

每个匹配会记录：

- `match_confidence`
- `match_method`
- `source_title`
- `source_block_start`
- `source_block_end`

这样后续如果出现匹配不准，可以知道是标题匹配还是顺序兜底。

## 6. 项目合同 DOCX 输出规范

入口函数：`render_contract_item_docx`

### 6.1 标题

项目合同生成时，首段标题使用汇总表里的项目名称，不再保留原合同长标题。

例如：

- 原合同标题：`华电新疆喀什 2×66 万千瓦风力发电机组采购合同`
- 生成标题：`华电新疆喀什 2×66 万千瓦`

这样用户下载单项目合同时更容易识别，也避免标题重复冗长。

### 6.2 表格与段落

对拆分后的内容做统一段落格式：

- 行距：1.5 倍。
- 段前：0。
- 段后：0。
- 表格、图片、扫描页尽量原样保留。

### 6.3 字体清理

为避免 OnlyOffice 打开时提示字体缺失，生成 DOCX 时统一清理字体引用。

最终保留字体：

- 中文：`Songti SC`
- 西文：`Times New Roman`
- 符号：`Symbol`

清理范围：

- `word/document.xml`
- `word/styles.xml`
- `word/stylesWithEffects.xml`
- `word/numbering.xml`
- `word/fontTable.xml`
- `word/theme/theme1.xml`

同时移除 `rFonts` 上的 `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme`、`cstheme`、`hint`，避免主题字体或提示属性误触发字体缺失。

## 7. OnlyOffice 字体处理

为了让 OnlyOffice 真正具备上述字体，容器侧也做了处理。

### 7.1 字体挂载

`docker-compose.yml` 中 OnlyOffice 增加字体目录挂载：

```yaml
${ONLYOFFICE_CUSTOM_FONTS_HOST_DIR:-./sewpg-bid-backend/onlyoffice/fonts}:/usr/share/fonts/truetype/custom:ro
```

当前内置字体文件：

- `Songti.ttc`
- `ArialUnicode.ttf`

### 7.2 容器启动时刷新字体缓存

OnlyOffice entrypoint 会执行：

```bash
fc-cache -f /usr/share/fonts/truetype/custom
documentserver-generate-allfonts.sh
```

这样 OnlyOffice 的字体列表、转换器缓存和前端编辑器字体清单保持一致。

## 8. API 入口

核心接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/materials/performance/categories` | 分类列表，支持型号和年份筛选 |
| `POST` | `/api/materials/performance/categories/preview` | 预览汇总表解析结果 |
| `POST` | `/api/materials/performance/categories/import` | 导入汇总表并创建分类和条目 |
| `GET` | `/api/materials/performance/categories/{category_id}` | 分类详情，并触发旧合同包按最新格式拆分 |
| `POST` | `/api/materials/performance/categories/{category_id}/attachments` | 上传汇总表或合同包附件 |
| `GET` | `/api/materials/performance/categories/{category_id}/attachments/{attachment_id}` | 下载分类附件 |
| `GET` | `/api/materials/performance/categories/{category_id}/items/{item_id}/attachments/{attachment_id}` | 下载项目级合同附件 |

注意：详情接口会调用懒加载拆分逻辑。如果项目级附件不存在，或已有附件 `format_version` 小于当前版本，会自动基于合同包重新生成。

## 9. 前端行为

业绩库页面重点展示：

- 型号聚合。
- 合同/交货/投运年份聚合。
- 项目合同数量。
- 明细表中的单项目合同下载入口。

用户的实际工作流：

1. 导入业绩汇总表。
2. 上传对应合同包。
3. 系统自动拆出项目级合同。
4. 在分类详情中查看每一条业绩。
5. 按型号、年份等条件筛选。
6. 勾选需要的项目条目，用于后续标书拼接。

## 13. 后续扩展建议

### 13.1 批量导入

当前能力已经支持单分类导入和合同拆分。后续可以增加批量导入入口：

- 自动扫描一组文件。
- 按文件名匹配 `*_汇总表.docx` 和 `*_合同.docx`。
- 批量创建分类、导入条目、上传合同包、触发拆分。
- 输出导入报告，标记未匹配、拆分不足、项目匹配置信度低的文件。

### 13.2 人工校准

如果合同包顺序或标题异常，自动匹配可能需要人工校准。建议后续增加：

- 项目条目与合同块的人工重绑。
- 查看合同块来源标题。
- 查看匹配方式和置信度。
- 重新生成单项目合同。

### 13.3 后续拼接

项目级附件已经为后续拼接留好颗粒度。后续生成标书时建议读取：

- 选中的 `performance_items`
- 对应的 `performance_item_attachments`
- 筛选条件快照
- 附件排序策略

再按目标标书目录要求合并为一个业绩证明附件包。

### 13.4 字体策略

当前使用 `Songti SC` 解决 macOS 与 OnlyOffice 环境下的中文字体可用性。若未来需要在国产化环境或 Windows 环境部署，可以把字体配置抽象为环境变量：

- `CONTRACT_OUTPUT_EAST_ASIA_FONT`
- `CONTRACT_OUTPUT_WESTERN_FONT`
- `ONLYOFFICE_CUSTOM_FONTS_HOST_DIR`

这样可以切换到企业统一授权字体。
