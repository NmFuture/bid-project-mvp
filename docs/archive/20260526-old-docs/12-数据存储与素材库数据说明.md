# 数据存储与素材库说明

> 当前双轨口径。
> 更新日期：2026-05-24

## 1. 存储底座

系统仍共用一套基础设施：

- PostgreSQL：项目状态、素材元数据、Wiki、审计、设置。
- MinIO：原始素材、清洗稿、Wiki 附件、项目文档。
- 本地工作目录：解析产物、目录产物、生成中间产物、OnlyOffice 工作文件。

共享底座不等于共享业务入口。业务访问必须按技术标和商务标分流。

## 2. 技术标素材

技术标素材入口：

```text
/api/technical/materials/...
```

技术标素材范围：

```text
技术标/通用素材
技术标/客户素材/{客户}
技术标/项目素材/{项目}
```

技术标 Wiki 也从技术标入口读取和维护。

## 3. 商务标素材

商务标素材入口：

```text
/api/business/materials/...
```

商务标素材范围：

```text
商务标/通用素材
商务标/客户素材/{客户}
商务标/项目素材/{项目}
```

商务标 Wiki 也从商务标入口读取和维护。

## 4. 项目素材范围

项目进入后续流程时，前端只通过对应 workspace 查询素材范围：

```text
技术标项目 -> technicalProjectsAPI.materialsPath(projectId)
商务标项目 -> businessProjectsAPI.materialsPath(projectId)
```

后端返回 `readableScopes`、`paths`、`identity` 和当前标类。前端再使用对应 workspace 的 materials API 查文件和 Wiki。

## 5. URL 口径

底层 `material_store` 只负责持久化和通用元数据，不直接暴露业务 URL。对外 URL 由：

- `technical_material_store`
- `business_material_store`

改写成对应 workspace 的素材路径。
