# 技术标 Wiki 改为镜像三级目录索引 — 修改说明 & 使用手册

> 生成于 2026-06-18。让技术标素材库 Wiki（`/workspace/tech/materials/wiki`）的目录树**严格等于**素材库三级目录结构。
> 配套：`20260618-技术标三级目录JSON索引-下游使用Handoff.md`（索引本身的说明）。

## 1. 一句话说明

技术标 Wiki 的目录树现在**确定性镜像**三级目录 JSON 索引：

```
技术标Wiki（自动生成）
├─ 01-标准文件   ← 一级 = 档位 tier（standard）
│   └─ EW5.0-220 ← 二级 = 3 级目录（机型号）
│       └─ 概述.docx ← 三级 = 文件卡片
├─ 02-客户定制   ← tier=customer，二级=客户名
└─ 03-项目定制   ← tier=project，二级=项目标识
```

不再走 LLM，不再用旧的「素材总表/章节映射/素材卡片…」5 节点结构。商务标 Wiki 不受影响，仍走原 LLM 链路。

## 2. 改了什么（3 处 + 1 次数据清理）

### 改动 1：后端生成逻辑 `app/services/wiki_generation.py`
- 顶部 import 三级索引服务（`load_technical_material_index` / `rebuild_technical_material_index`）。
- 新增 `_generate_technical_wiki(mode)`：技术标专用确定性路径。流程：
  1. `rebuild_technical_material_index()` 实时重建索引（失败/空则回退读已落盘快照）；
  2. 把索引 JSON 写成临时 manifest（`_write_technical_index_manifest`）；
  3. subprocess 跑 skill 脚本把索引镜像成 Wiki blueprint；
  4. import 覆盖/刷新 Wiki 节点。`generator` 标记为 `technical_index_mirror`。
- `generate_platform_wiki` 顶部加一行短路：技术标 → 调上面的函数；**商务标分支完全没动**。

### 改动 2：Skill 脚本 `opencode/skills/bid-tech-wiki-material-builder/scripts/run_from_manifest.py`
- 重写为：吃**原始三级目录索引 JSON**（顶层有 `tiers[]`），按 tier→folder→file 生成三层节点树。
- 输出 schema 升级为 `bid-wiki-blueprint-v2`。
- 兼容直接喂索引 JSON，或喂包裹了它的 manifest（`materialIndex`/`index` 键）。

### 改动 3：Skill 说明 `opencode/skills/bid-tech-wiki-material-builder/SKILL.md`
- 由「5 聚合节点」约定改为「镜像三级目录」约定，写明三档语义与字段。

### 数据清理（一次性）
- 删除两个历史手建残留顶层节点 `WIKI-0001 风资源`、`WIKI-0003 机组选型`（2026-05-10 种子，无真实素材）。它们标题不在自动清理白名单里，`replace` 也不会清，故手动删。

## 3. 怎么用（日常）

### 普通用户：前端两个按钮
- **重建Wiki**（推荐修树用）：清掉旧的自动生成根，按当前素材库三级结构重新镜像。对应 `bootstrap mode=replace`。
- **刷新Wiki**：只替换自动生成的子节点，保留根。对应 `bootstrap mode=refresh`。

> 素材库目录结构变动后（建/删/移目录、上传、拆分），点「重建Wiki」即可让树重新对齐。

### 命令行 / 接口
```bash
# 重建（覆盖）
curl -s -X POST http://localhost/api/technical/materials/wiki/bootstrap \
  -H 'Content-Type: application/json' \
  -d '{"mode":"replace","bidType":"技术标"}'

# 查看当前目录树
curl -s http://localhost/api/technical/materials/wiki
```

返回里 `generation.generator` 应为 `technical_index_mirror`，`generation.summary` 给出「N 档位 / M 目录 / K 文件」。

## 4. 别人怎么快速复用 / 改

### 想本地验证脚本产出（不连后端）
脚本可独立运行，输入就是一份索引 JSON：
```bash
cd opencode/skills/bid-tech-wiki-material-builder/scripts
python3 run_from_manifest.py /path/to/technical_material_index.json
# stdout 给出 outputFile 路径，里面是 blueprint（nodes 三层树）
```
样例索引：`doc/anbc_doc/technical_material_index.sample.json`。

### 想改节点展示内容（每个卡片/目录显示什么）
全在 `run_from_manifest.py` 三个函数里，改 markdown 即可，**不碰后端**：
- `build_tier_node`：一级（档位）节点
- `build_folder_node`：二级（3 级目录）节点 + 文件清单表
- `build_file_card`：三级（文件卡片）

### 想给商务标也做同款镜像
照 `_generate_technical_wiki` 复制一份，把索引来源换成商务标的索引服务，在 `generate_platform_wiki` 里加对应短路分支即可。

## 6. 常见疑问

| 现象 | 原因 / 处理 |
|---|---|
| 重建后多出陌生顶层节点 | 历史手建节点，标题不在清理白名单。确认无用后手动删 DB 行（`wiki_nodes`，CASCADE 自动清子节点）。 |
| 树是空的 | 索引为空（素材库无 3 级目录文件）。脚本仍产合法空 blueprint，`summary` 会标注。 |
| 档位顺序不对 | 固定 standard→客户→项目，由脚本 `TIER_ORDER` 控制。 |
| 客户名/项目名没显示 | 看 `tier`：customer 用 `customerName`、project 用 `projectId`；`customerId`/`projectCode` 索引侧恒空，勿依赖。 |
| 改了代码没生效 | 没 rebuild 镜像。见第 5 节。 |
