## 第一部分：安全与部署问题（测试文档之外，上线前必修）

后端约 270 个路由中仅 38 处使用 `Depends(current_user)` 鉴权，以下为按优先级排列的发现。

### P0 —— 上线前必修

#### S1. 绝大多数业务 API 无鉴权（最高危）

- 现状：`code/sewpg-bid-backend/app/api/routes/business.py:34-58` 等项目/素材/文档接口无任何鉴权依赖；`Depends(current_user)` 仅出现在 `settings.py`、`technical.py`（4 处）、`business.py`（5 处），而 `business_gaps.py`（20 路由）、`performance.py`（17）、`project_info.py` 等约 230 个端点均无鉴权。
- 影响：未登录即可读取/创建/删除全部投标项目、素材、文档。
- 建议：在 `app/api/router.py` 对各业务 router 统一加 `dependencies=[Depends(current_user)]`，仅放行 login/healthz；OnlyOffice 回调用 token 校验单独放行。
- 连带注意：前端 SSE 用 `EventSource`（`src/api/index.js:37-55`）无法带 Authorization 头，统一加鉴权时 SSE 端点需改为 query token 或 fetch-stream 方案。

#### S2. 用户管理接口无角色校验，普通用户可提权

- 现状：`code/sewpg-bid-backend/app/api/routes/settings.py:20-34` 创建/更新用户只要求登录；`app/services/auth_service.py:247-251` 允许任意登录用户修改他人 `roles`/`password`；全后端无 `require_role` 类检查（roles 字段只在 `models/materials.py:326` 展示用）。
- 建议：对用户管理、系统设置、LLM/OCR 网关配置接口加管理员角色依赖。

#### S3. opencode 服务 4096 端口无密码对宿主发布

- 现状：`code/docker-compose.yml:195`（`OPENCODE_SERVER_PASSWORD` 默认空）、`:222-223`（`ports: 4096:4096`）；后端调用方 `app/services/opencode_client.py:36-40` 不携带任何鉴权头。opencode server 具备文件读写和 shell 执行能力。
- 影响：同网段任意主机可远程在容器内执行命令。
- 建议：删除 `ports` 映射只走内部网络，或强制设置 `OPENCODE_SERVER_PASSWORD` 并在客户端带鉴权。

#### S4. OnlyOffice JWT 关闭 + 回调 token 为空即放行

- 现状：`code/docker-compose.yml:250-253`（`JWT_ENABLED=false`、`JWT_SECRET` 空）、`:51`（`ONLYOFFICE_CALLBACK_TOKEN` 默认空）；`app/services/bid_document_flow.py:62-65` `if not expected: return`（token 未配置时直接放行回调写文件）。
- 影响：伪造 OnlyOffice 回调可覆盖任意项目文档。
- 建议：生产默认开启 JWT；`_validate_callback_token` 在未配置 token 时应拒绝而非放行。

### P1 —— 部署配置必修

#### S5. 默认弱凭据硬编码且"空值回落"使加固失效

- 现状：`code/docker-compose.yml:33`（`biduser:bidpass`）、`:56-57`（`minioadmin:minioadmin`）、`:67`（`AUTH_ADMIN_PASSWORD:-123456`）；`app/core/config.py:204-210` 代码内同样硬编码默认库密码/MinIO 密钥，`:222` `os.getenv(...).strip() or "123456"`——即使运维显式设空也会回落到 `123456`；`auth_service.py:90` 用同一弱口令播种 4 个角色账号。
- 建议：移除代码内默认口令，启动时强制要求环境变量（生产模式缺失即 fail-fast）；播种账号改用随机初始密码。

#### S6. Postgres / MinIO 控制台端口直接对宿主发布

- 现状：`code/docker-compose.yml:281-282`（5432 发布，弱口令）、`:317-319`（MinIO 9000/9001 发布，minioadmin/minioadmin）。
- 建议：生产环境移除这些 `ports` 映射，仅用内部网络；MinIO 控制台至少改强口令并限制来源。

### P2 —— 排期跟进

#### S7. 登录接口无速率限制/防爆破

- 现状：`app/api/routes/auth.py:14-47` 与 `auth_service.py:111-150` 无任何失败计数、锁定或限流；配合默认口令（S5）风险放大。
- 建议：按 IP/账号加失败次数限制（Redis 计数 + 指数退避）。

#### S8. requirements.txt 依赖大量未锁定

- 现状：`code/sewpg-bid-backend/requirements.txt:8-19` 中 13 行为 `>=` 无上限（PyMuPDF、pandas、lxml、asyncpg、sqlalchemy、minio、redis 等），镜像构建每次可能解析出不同版本。
- 建议：生成完整 lock（pip-tools/uv），镜像构建使用锁定文件。

#### S9. 未鉴权 healthz 泄露内部路径与拓扑（低危）

- 现状：`app/api/routes/system.py:12-38` 返回服务器绝对路径、内部服务地址，且无鉴权。
- 建议：healthz 只返回 `status: ok`；详细信息移到鉴权后的 `/api/settings/health`（已存在，`settings.py:147`）。

#### S10. 前端会话 token 存 localStorage（置信度中）

- 现状：`src/App.jsx:55`、`src/api/index.js:83-117` 会话 token 存 localStorage，JS 可读。正面：全前端无 `dangerouslySetInnerHTML`/`innerHTML`/`eval`，当前 XSS 面较小。
- 建议：如接受此风险可保留；更稳妥是 HttpOnly Cookie + SameSite。

### 已确认无问题/良好的点（无需处理）

- SQL 注入：`performance_library_service.py:272-301` 虽用 f-string 拼 SQL，但全部走 `:param` 绑定参数；其余 ORM 用法正常。
- 路径穿越：`file_utils.py:10-13` `safe_filename` 剔除路径分隔符；`bid_document_flow.py:71-77` 对回写 URL 做了 scheme/host 白名单校验（SSRF 防护已存在）。
- 密码存储：PBKDF2-SHA256 26 万轮 + `hmac.compare_digest`（`auth_service.py:24-45`）。
- TODO/FIXME 堆积：前后端均为 0 处。
- CORS 使用显式来源列表而非 `*`（`main.py:33-39`）。
- 子进程调用均为参数列表形式，未见 `shell=True`/`os.system`。
