## 2. 任务边界

### 2.1 本任务负责（聚焦六件事）

1. **字段接收**：接收并对齐甲方字段清单、王立博提供的 Excel 材料。
2. **数据抽取**：从招标文件解析结果、项目创建信息、项目材料中取数。
3. **规范化**：统一字段名与值格式（含机型去后缀，见 §5）。
4. **人工确认**：复杂/歧义字段走人工确认，AI 只给建议。
5. **写入**：字段值 + 元数据（来源、状态）写入事实表。
6. **验证**：端到端验证下游模块能正确读取。

### 2.2 本任务不包含

- ❌ 附表填写——由肖雨航负责（TASK-20260722103，✅）。
- ❌ 素材匹配算法本身。
- ❌ 目录生成与正文组装。
- ❌ 技术标/商务标字段体系统一——不默认承担（⚪ 是否共用一套事实表仍是工作假设，见 §13）。
- ❌ 甲方尚未提供的业务字段的定义——未被甲方字段表确认的字段一律标"候选"，不进正式 Schema（见 §4）。

## 5. 来源优先级与冲突规则

同一字段有多个来源时，按以下优先级取值（高 → 低）：

1. **甲方人工确认结果**
2. **甲方正式项目实施表 / 字段维护表**
3. **招标文件原文及可定位证据**
4. **项目创建时用户填写的信息**
5. **AI 或解析程序给出的建议**

**冲突处理规则**：

- 同一字段出现冲突时，**不得静默覆盖**；保留全部冲突来源，字段进入「存在冲突」状态，转人工确认。
- 字段级已有约定的优先级从其约定。例：认证证书类字段"型式认证数据优先，无型式认证用设计认证数据"（清单已注明）。

## 7. 字段状态模型

```
未提取 → 已自动提取 → 待人工确认 → 已人工确认
   │           │            │
   ▼           ▼            ▼
缺少来源    存在冲突 ──────→ 已人工确认（人工裁决后）
   │
   ▼
 不适用（字段对本项目不适用，需注明原因）
```

- 状态枚举：`未提取` / `已自动提取` / `待人工确认` / `已人工确认` / `缺少来源` / `存在冲突` / `不适用`。
- **禁止**用空字符串同时表达"未解析""没有这个字段""不适用"——空值必须有状态字段配套说明。
