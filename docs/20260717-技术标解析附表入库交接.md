## 1. 需求与结果

本次改动解决技术标 S1 解析阶段附表只生成解析产物、未进入项目素材库的问题。

最终行为如下：

| 需求 | 实现结果 |
| --- | --- |
| 解析出的附表进入素材库项目文件夹 | 确认参与并保存最终项目信息后，自动写入最终技术标项目素材根目录 |
| 附表增加“待填写-”前缀 | 素材库文件名统一为 `待填写-{附表标题}.docx` |
| 全局目录结构 JSON 更新 | 上传完成后严格重建并校验 `technical_material_index.json` |
| 重复解析同名附表 | 使用 `on_conflict="version"` 更新同一素材并保留版本记录 |
| 不影响商务标 | 同步入口只在技术标项目确认参与的更新流程中执行 |

示例：

```text
解析标题：附表A.1 投标机型总方案信息表
素材名称：待填写-附表A.1 投标机型总方案信息表.docx
素材目录：技术标/项目定制/{materialProjectId}
```

解析结果中的附表 `title` 保持原值，仅素材库文件名增加前缀。

## 2. 数据流

```text
技术标上传解析 / 复用已有招标文件解析
  -> S1 解析生成 structured.appendices
  -> materialize_parse_appendix_docx_assets 生成附表 DOCX
  -> 保存解析结果，不进入素材库
用户确认参与并在完善项目信息弹窗保存最终项目身份
  -> BidProjectService.update 持久化 reviewDecision=participate 和最终 materialProjectId
  -> sync_technical_parse_appendices
     -> 解析项目素材身份 materialProjectId
     -> raw_bootstrap_folders 初始化项目素材根目录
     -> technical_material_store.raw_upload 批量上传附表
     -> rebuild_technical_material_index_strict 严格重建全局 JSON
     -> 校验本次新增 RAW ID 全部存在于索引
  -> 返回 technicalParseAssetSync 同步结果并进入技术标工作区
```

附表入库入口是 `technical_project_service.update` 收到 `reviewDecision=participate`。解析入口和 `BidParseService.results` 只生成、读取或物化附表，不向素材库上传。

## 3. 目录与命名规则

### 3.1 项目素材目录

技术标项目素材的规范路径为：

```text
技术标/项目定制/{materialProjectId}
```

“项目素材”是业务语义和历史别名；技术标素材门面会归一为实际二级目录名“项目定制”。
`materialProjectId` 优先取项目绑定的素材项目 ID；未绑定独立素材项目时使用当前工作区项目 ID。

### 3.2 文件名

命名函数会执行以下处理：

1. 使用解析附表的 `title`，不使用解析临时文件名中的 `APPX-xxxx-` 前缀。
2. 清理 Windows 非法文件名字符。
3. 标题已有 `.docx` 后缀时不重复追加。
4. 标题已有 `待填写-` 前缀时不重复追加。
5. 最终名称固定为 `待填写-{标题}.docx`。

## 5. 索引更新策略

原有 `rebuild_technical_material_index()` 是 best-effort 钩子：失败时记录日志并返回空字典，不能向调用方保证 JSON 已更新。

本次新增：

```python
await rebuild_technical_material_index_strict()
```

严格入口使用原有 `_INDEX_WRITE_LOCK` 和原子写盘逻辑，但不吞异常。附表上传后还会遍历重建结果，确认本次上传返回的每个 `RAW-xxxx` 都已进入索引；缺少任意文件即报错。

全局索引位置：

```text
documents/_runtime/materials/technical_material_index.json
```

容器内通常对应：

```text
/data/documents/_runtime/materials/technical_material_index.json
```

读取接口：

```text
GET /api/technical/materials/index
```

## 6. 失败语义

以下情况会阻断当前确认参与请求并暴露错误：

- 调用项目不是技术标项目。
- 项目缺少可用的素材项目 ID。
- 任一附表的 `docxPath` 不存在或不是文件。
- 素材上传返回的文件数量少于待上传附表数量。
- 全局 JSON 严格重建失败。
- 重建后的全局 JSON 未包含本次新增素材 ID。

没有提取到附表时返回 `status=skipped`，不会创建空项目目录，也不会重建索引。

已知状态边界：`update_workspace_project` 会先持久化最终项目信息和 `reviewDecision=participate`，再执行素材同步。因此同步失败时确认参与请求会报错，但项目状态可能已经是“参与”。如果后续要求项目确认与素材入库事务一致，应新增独立的素材同步状态和重试入口，或调整参与状态的持久化时点。
