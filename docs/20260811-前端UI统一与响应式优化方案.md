## 1. 文档目的

本方案用于把当前前端从“页面可用但视觉规格分散”收口为统一、稳定、可维护的企业级界面体系，并作为后续分批实施、评审和验收的共同基线。

本方案回答以下问题：

1. 哪些现状问题需要解决，证据位于哪里。
2. 字体、字号、颜色、间距、圆角、阴影、按钮和表格采用什么统一规格。
3. 桌面、平板、手机和矮屏分别如何适配。
4. 登录、工作台、项目阶段页、素材库、日志和设置等页面如何分批优化。
5. 哪些文件可以改，哪些业务边界绝对不能触碰。
6. 每一批改动如何验证，什么条件下才算完成。

本文是当前双工作区架构下的有效 UI 方案。归档文档
`docs/archive/20260526-old-docs/20260530-前端UI修缮设计规范.md`

## 2. 项目背景与用户场景

### 2.1 产品定位

本产品是上海电气风电投标业务的专业工作台，核心用户包括：

- 技术标负责人和技术工程师。
- 商务标负责人和商务人员。
- 同时统筹技术标与商务标的项目经理。
- 管理系统配置、模板、用户和运行健康的管理员。

用户的主要任务不是浏览内容，而是持续完成招标文件解析、目录评审、素材匹配、缺口处理、文档共创、导出和审计。界面需要支持长时间、高频率、跨阶段操作。

### 2.2 设计关键词

- 稳重
- 成熟
- 专业
- 简洁
- 高信息密度
- 强秩序
- 可扫描
- 低干扰

### 2.3 设计方向

采用 **Trust & Authority + Data-Dense Dashboard**：

- 深色企业顶栏负责品牌识别。
- 品牌蓝负责导航、主要动作和阶段强调。
- 白色与浅灰负责大面积内容承载。
- 绿色、青色、红色只表达成功、信息/AI、异常等语义。
- 通过字号、字重、间距、边框和对齐建立层级，不依赖更多颜色和装饰。

唯一需要持续强化的视觉特征是“阶段状态”：在阶段进度、关键指标和当前任务中使用清晰的文字、图标与低饱和状态色，不使用左侧强调条或括号式选中效果，也不增加与投标流程无关的装饰元素。

### 2.4 明确禁止的视觉方向

- 不做营销式大标题和首页式卡片堆叠。
- 不新增紫色、粉色、金色等非现有语义色。
- 不使用装饰性渐变、光斑、玻璃拟态和大面积模糊。
- 不使用夸张阴影、悬浮卡片和无意义入场动画。
- 不在卡片内继续嵌套卡片。
- 不把所有标签和按钮都做成胶囊形。
- 不引入另一套图标语言、UI 框架或在线字体。

## 5. 设计系统规范

### 5.1 色彩

#### 5.1.1 原则

- 锁定当前色板，不更换品牌配色。
- 组件只能使用语义 Token，不新增裸 hex。
- 品牌色与状态色可以保留原值，但允许改变它们承担的角色以满足对比度。
- 颜色不能成为状态的唯一表达，必须同时配合文本、图标或形状。

#### 5.1.2 建议语义映射

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| `brand-deep` | `#05202E` | 顶栏、登录品牌背景 |
| `brand-primary` | `#0068B7` | 主要操作、链接、选中态、焦点 |
| `brand-primary-hover` | `#005995` | 主按钮 hover/active |
| `brand-primary-soft` | `#E8F4FF` | 选中背景、信息提示背景 |
| `shell-rail` | `#0067B6` | 桌面侧栏，保持现有色值 |
| `status-success` | `#14A83B` | 成功图标、进度、边框 |
| `status-success-strong` | `#0D5A23` | 成功实心按钮或小字前景 |
| `status-info-ai` | `#18B7D9` | AI、信息和运行中辅助标识 |
| `status-danger` | `#C54040` | 错误和危险操作 |
| `surface-page` | `#F7F9FB` | 页面背景 |
| `surface-panel` | `#FFFFFF` | 主面板和表单表面 |
| `surface-subtle` | `#F1F5F9` | 次级区块、表头、筛选区 |
| `text-primary` | `#2A4258` | 标题、正文 |
| `text-secondary` | `#60758A` | 辅助正文、说明 |
| `text-disabled` | `#95A7BA` | 禁用态、占位和边框，不作为小字号正文 |
| `border-default` | `#C4D0DC` | 分隔线、面板边框 |

#### 5.1.3 对比度处理

- 14px 正文和按钮文字对比度目标至少 4.5:1。
- `#14A83B` 不再直接承载白色 12/14px 小字；实心成功按钮使用 `#0D5A23` 或改为浅绿背景加深绿文字。
- `#95A7BA` 只用于边框、图标弱态、占位和禁用态，辅助正文统一使用 `#60758A`。
- 侧栏激活态应使用更深背景或更大的字重，避免 11px 白字直接落在 `#4C95CD` 上。

### 5.2 字体与排版

#### 5.2.1 字体角色

- 标题：`PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`, `Helvetica Neue`, Arial, sans-serif，字重 600。
- 正文：同一中文系统字体栈，字重 400。
- 控件标签：同一字体栈，字重 500 或 600。
- 项目编号、百分比、数量、日期对齐场景：使用系统等宽数字能力 `font-variant-numeric: tabular-nums`；仅代码、ID 等场景使用现有 monospace 栈。
- 不在线加载 Google Fonts 或 Noto Sans SC，避免内网和首屏依赖。

#### 5.2.2 字号层级

| 语义 | 字号 / 行高 | 字重 | 典型位置 |
| --- | --- | --- | --- |
| 页面标题 | 22px / 30px | 600 | 工作台、项目列表、设置 |
| 弹窗主标题 | 18px / 26px | 600 | 向导、详情、确认弹窗 |
| 区块标题 | 18px / 26px | 600 | 项目区、待办区、素材区 |
| 卡片标题 | 16px / 24px | 600 | 项目名称、配置分组 |
| 正文 | 14px / 22px | 400 | 描述、表格内容 |
| 控件标签 | 14px / 20px | 500/600 | 按钮、表单 label |
| 辅助说明 | 12px / 18px | 400 | 时间、ID、次级信息 |
| 关键指标 | 24px / 32px | 600 | 工作台数量、统计值 |

约束：

- 不使用 10px、11px 正文。
- 不再把 `text-xl` 到 `text-4xl` 压成相同字号。
- 手机端输入框、下拉框和文本域使用至少 16px，避免 iOS 聚焦自动放大。
- 标题使用 `text-wrap: balance` 或 `text-pretty`，长项目名使用 `min-w-0`、换行或行数截断。
- 字距保持 0，不使用负 letter-spacing。

### 5.3 间距

采用 4px 基准网格：

| Token | 值 | 用途 |
| --- | ---: | --- |
| `space-1` | 4px | 图标与短标签 |
| `space-2` | 8px | 紧凑控件内部、同组操作 |
| `space-3` | 12px | 表格单元、紧凑卡片 |
| `space-4` | 16px | 常规卡片、手机页面边距 |
| `space-6` | 24px | 页面区块间距、桌面卡片 padding |
| `space-8` | 32px | 页面大区块或宽屏边距上限之一 |

统一规则：

- 页面 section gap 默认为 24px。
- 卡片内部默认为 16px，复杂表单面板可用 24px。
- 同组按钮 gap 为 8px。
- 表单字段纵向 gap 为 16px，label 与控件 gap 为 6-8px。
- 页面边距统一由 Shell 或页面容器提供，页面根节点不得重复添加同级 padding。

### 5.4 圆角、边框与阴影

| 语义 | 规格 |
| --- | --- |
| 控件圆角 | 6px |
| 卡片/面板圆角 | 8px |
| 弹窗圆角 | 8px |
| 状态徽标、头像 | `9999px`，仅限确有胶囊/圆形语义 |
| 默认边框 | 1px `border-default` |
| 选中面板 | 中性浅底、细边框和字重，不使用左侧强调线 |
| 静态面板阴影 | 无，或 `0 1px 2px rgba(13,33,55,0.05)` |
| 浮层阴影 | `0 12px 28px rgba(13,33,55,0.14)` |

禁止：

- 页面自行新增随机 `shadow-[...]`。
- 同类卡片混用 `rounded-md/lg/xl`。
- 使用阴影代替必要边框。
- 通过全局 `[class*=shadow]` 或 `[class*=gradient]` 覆盖组件声明。

### 5.5 动效

- 常规交互时长 150-200ms。
- 只过渡 `color`、`background-color`、`border-color`、`opacity`、`transform` 和必要的 `box-shadow`。
- 禁止 `transition-all`。
- 运行进度只在有真实或已定义的展示进度时变化，不新增装饰性计数动画。
- 页面切换不做大幅滑入或批量 stagger。
- 保留现有 `prefers-reduced-motion`，降级时关闭非必要动画和位移。

### 5.6 控件尺寸

| 类型 | 桌面尺寸 | 手机/粗指针尺寸 |
| --- | --- | --- |
| 紧凑按钮 | 32px 高 | 44px 命中区 |
| 默认按钮 | 40px 高 | 44px 高 |
| 主要按钮 | 40px 高 | 44-48px 高 |
| 图标按钮 | 32/36px 视觉框 | 至少 44x44px 命中区 |
| 输入/下拉 | 36-40px 高 | 至少 44px 高 |
| 分页按钮 | 32px 视觉框 | 至少 44x44px 命中区 |
| 表格表头 | 40px | 40px |
| 表格正文行 | 44px，长文本行允许自适应 | 由移动信息块替代或自适应 |

## 6. 全局布局与响应式规范

### 6.1 断点

| 范围 | 用途 |
| --- | --- |
| `<768px` | 手机 |
| `768-1023px` | 平板竖屏/小平板 |
| `1024-1279px` | 小桌面/平板横屏 |
| `1280-1535px` | 标准桌面 |
| `>=1536px` | 宽屏桌面 |

继续使用 Tailwind 标准断点，不新增与现有体系冲突的自定义断点。额外重点检查 `1366x768` 矮屏。

### 6.2 Shell 尺寸

- 顶栏高度保持 48px。
- 桌面侧栏宽度保持 78px。
- Shell 使用 `min-height: 100dvh`。
- `<main>` 是普通页面唯一主滚动容器。
- 页面底部必须为固定/吸底导航和 safe area 预留空间。
- 顶栏、侧栏、底部栏不得遮挡内容、弹窗关闭按钮或表单操作区。

### 6.3 内容容器

建立三类内容容器：

| 容器 | 适用页面 | 宽度策略 |
| --- | --- | --- |
| 全局内容框 | 所有登录后页面 | `width: 100%`、`max-width: 1600px`、水平居中 |
| `layout-fluid` | 表格、编辑器、素材库、日志 | 在全局内容框内使用 `width: 100%` |
| `layout-standard` | 设置、解析、项目向导 | `max-width: 1120-1280px` |
| `layout-reading` | 审阅摘要、说明、窄表单 | `max-width: 880-960px` |

统一页面水平 padding：

- 手机：16px。
- 平板：20-24px。
- 标准桌面：24-32px。
- 宽屏：最大 40px。

推荐由 Shell 输出 `clamp(16px, 2.2vw, 40px)` 等价策略，页面根节点不再重复提供相同 padding。

### 6.4 滚动所有权

每个视口只允许一个明确的页面主滚动区。复杂工作区可有内部滚动，但必须明确边界：

- 页面主滚动：`main`。
- 目录树：只滚动目录树容器。
- 文档预览：只滚动预览或 iframe 自身。
- 弹窗正文：只滚动 DialogBody，头部和底部动作保持可见。
- 移动端抽屉：使用 `overscroll-behavior: contain`。

禁止依靠 `min-height: 640/680/720/885px` 撑开主要布局。文档和素材工作区统一使用：

```css
height: calc(100dvh - var(--shell-header-height) - var(--page-header-height) - var(--page-gap));
min-height: 0;
```

## 7. 组件级规范

### 7.1 AppShell

目标文件：`src/components/layout/AppShell.jsx`、`src/index.css`。

- 顶栏、侧栏和移动导航尺寸统一由 Token 控制。
- workspace 与非 workspace 页面使用同一套内容 padding。
- 非 workspace 页面也必须在手机端提供主导航。
- 增加首焦点可见的“跳到主内容”链接和 `#main-content`。
- 侧栏 active、hover、focus 层级必须清晰并满足对比度。
- 用户菜单为真正菜单语义；装饰图标使用 `aria-hidden="true"`。
- Logo 提供明确 `width/height`，减少布局偏移。

不得改变 workspace 切换、权限过滤、用户菜单、退出和导航目标。

### 7.2 PageHeader

目标文件：`src/components/shared/PageHeader.jsx`。

- 页面只允许一个 H1。
- 标题 22px/600，说明 14px/22。
- 标题区与动作区在窄屏纵向排列。
- 动作区允许换行，不强制隐藏图标。
- 主操作最多一个，其他操作使用 secondary/quiet/ghost。
- 长标题使用 `min-w-0` 和合适换行，不挤压动作区。

### 7.3 Button / IconButton / FileButton

目标文件：`src/components/ui/Button.jsx`、`IconButton.jsx`、`FileButton.jsx`。

- 统一 `primary`、`secondary`、`quiet`、`ghost`、`danger`、`text` 语义。
- `success` 只用于确实表示确认/成功的操作，不作为第二主按钮。
- loading 状态保留按钮宽度，显示 spinner 与“处理中…”等现有动作名。
- disabled 状态不能只降低到不可读的透明度。
- 图标按钮必须有 `aria-label` 和 tooltip/title。
- 文件按钮继续保持 label + file input 语义，不改上传事件。
- 原生 `<a>`、`<button>`、`<label>` 的语义不得因组件化互换。

### 7.4 表单控件

适用：输入框、文本域、下拉框、复选框、单选框、文件上传区。

- 可见 label 与控件通过 `htmlFor/id` 关联。
- 输入提供有意义的 `name`、正确 `type`、`autocomplete` 和必要 `inputMode`。
- placeholder 不能代替 label。
- 错误紧邻字段，使用 `aria-describedby`；不改变现有校验规则和触发时机。
- checkbox/radio 的 label 与控件共享完整点击区域。
- 聚焦态使用品牌色边框 + 2px focus ring。
- 手机端输入字号至少 16px、高度至少 44px。
- 原生 select 显式设置背景色和文字色。

### 7.5 FilterBar / Toolbar / 分段控件

目标文件：`FilterBar.jsx`、`Toolbar.jsx`、`MaterialsViewSwitch.jsx` 及薄封装。

- 同一组筛选器使用 8px gap，支持自动换行。
- 筛选 label 不得只写一个笼统“筛选”，每个控件有各自可访问名称。
- 手机端筛选器默认单列或两列，主要动作独占一行或靠下显示。
- 模式选择使用 segmented control/tabs，不用多个风格不同的文本按钮。
- tab 高度桌面至少 32px，手机命中区至少 44px。

### 7.6 DataCard / 面板

目标文件：`DataCard.jsx` 和页面纯展示容器。

- 面板半径统一 8px，默认边框 1px。
- 普通页面区块尽量使用无阴影布局。
- 卡片只用于独立对象、重复项目、工具和弹窗，不把整个页面 section 卡片化。
- 卡片内不再嵌套装饰卡片；双流程项目可使用分区或分隔线表达技术标/商务标。
- 可点击卡片 hover/active/focus 使用边框和浅背景，不依赖大幅上浮。

### 7.7 Badge / StatusBadge / RoleChip

- `StatusBadge` 是业务状态色的唯一共享出口。
- 状态必须有文字；图标只能作为补充。
- 高度、padding、字号统一，避免 10/11px 任意值。
- 胶囊只用于状态与角色，不用于一般操作按钮。
- 数量与百分比使用等宽数字。

### 7.8 Table / Responsive Data List

- 桌面表格保留语义 `<table>`，表头使用 `scope="col"`。
- 表头 40px，正文基础行 44px；长文本允许增高。
- 数量、金额、百分比、日期使用等宽数字并保持对齐。
- 表格容器负责横向滚动，页面本身不得横向滚动。
- 首列、关键识别列和操作列可按页面需要 sticky。
- 长文本使用 `break-words`、`line-clamp` 或 tooltip，不让单元格撑破布局。
- 手机端项目列表优先使用信息块；极复杂业绩/日志表可保留受控横向滚动。
- 移动信息块不得删字段或动作；低频字段可折叠，但必须可访问。
- 本轮不新增虚拟化，避免改变列表行为。

### 7.9 Pagination

- 纯图标按钮补齐 `aria-label`。
- 桌面视觉尺寸 32px，粗指针命中区至少 44px。
- 当前页使用品牌浅背景 + 品牌文字，不新增亮蓝裸色。
- 页码变化逻辑和请求行为不变。

### 7.10 Dialog / Drawer / Fullscreen Viewer

目标文件：`components/ui/Dialog.jsx` 和逐步迁移的自建弹层。

- 使用 `role="dialog"`、`aria-modal="true"` 和标题关联。
- 打开后焦点进入弹窗，Escape 可关闭，关闭后焦点返回触发点。
- 背景不可被键盘或滚轮继续操作。
- 弹窗最大高度基于 `100dvh` 和 safe area。
- Header/Footer 固定可见，Body 独立滚动。
- 手机端常规弹窗接近全屏，底部动作可吸底。
- 删除确认、上传、生成等 handler 和结果逻辑完全保留。

### 7.11 Toast / Loading / Empty / Error

- Toast 使用 `role="status"` 或错误时 `role="alert"`，设置合适的 `aria-live`。
- Toast 关闭使用按钮，不使用可点击 div。
- Loading 使用 `aria-busy`/`role="status"`，文案统一使用“…”而不是“...”。
- Error 说明问题和已有下一步，不修改错误来源。
- Empty State 只包含一个明确主动作，不使用大面积装饰。
- Skeleton 尺寸稳定，避免加载前后布局跳动。

### 7.12 StageProgress 与任务进度

- StageProgress 继续表达真实阶段顺序，不改阶段定义和跳转条件。
- 选中、已完成、锁定、失败状态统一颜色、图标和文字。
- 任务进度版式继续复用 `BidProgressPanel`。
- 目录、正文、素材匹配、解析的进度折算和文案口径继续遵循
  `docs/20260809-进度条展示设计.md`。
- UI 优化只能调整字号、间距、边框、图标和响应式，不能改变百分比、耗时、阶段和状态计算。

### 7.13 OnlyOfficeWorkspace

- 只调整外层 Grid/Flex、可用高度、边框和全屏按钮位置。
- 桌面允许目录/文档或文档/工具双栏。
- 小屏改上下排列，文档区必须保留足够可用高度。
- 不改 iframe key、session、mode、事件回调、下载和重挂载条件。
- 每次外层布局变化都必须验证预览、编辑、全屏、退出全屏和下载。

## 13. 风险与控制措施

| 风险 | 来源 | 控制措施 |
| --- | --- | --- |
| 全局 CSS 造成跨页回归 | `index.css` 有广泛选择器和 `!important` | 先建截图基线；逐条移除覆盖；新规则优先组件作用域 |
| 技术标改动误伤商务标 | 两端共享 Shell、基础组件和 OnlyOffice | 共享组件每次修改都做技术/商务代表页成对验收 |
| 相似页面被错误合并业务 | 项目列表、阶段页、素材库 JSX 相似 | 只抽纯展示组件；API/effect/handler/disabled 留在原页面 |
| OnlyOffice 重挂载导致会话丢失 | 多页依赖 iframe/session | 不改 key/session/mode/回调；只调外层 CSS；做完整冒烟 |
| 移除固定高度引入双滚动 | 现有 640-885px 规则 | 每页指定 scroll owner；重点验证 1366x768 |
| 移动表格遗漏字段或动作 | 当前依赖宽表完整展示 | 移动变体不删数据；低频字段可折叠但必须可达 |
| 组件化改变表单语义 | 原生 button/a/label 混用 | 保留 element、type、href、download、disabled 和 handler |
| 移动导航扩大交互范围 | “更多”需要 UI 展开状态 | 单独审批；复用现有导航定义和权限来源 |
| 配色不变但对比度不足 | 次文字和透明色较多 | 不换色板；调整前景/背景角色、字重和透明度 |
| 新工具链扩大范围 | 历史方案建议 Storybook | 本阶段不新增 Storybook、UI 库、字体或图标依赖 |
| 大批量改动难回滚 | 前端页面体量大 | 按 Shell、普通页、阶段页、素材页分 PR |
| 文档与实现漂移 | 旧 UI 方案已归档 | 每个 Phase 更新决策记录、实施状态和最后验证 commit |
