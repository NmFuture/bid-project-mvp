# 商务标 S4 生成标书执行计划

> 用途：作为商务标 `S4 生成标书` 的方案讨论与后续执行清单。  
> 状态：方案初版，待讨论确认后执行。  
> 更新日期：2026-05-09  
> 范围：仅商务标 S4。技术标 S4 保持现状，只做必要的 `bidType` 分流，不混用技术标 workspace、技术标 gap plan、技术标 Wiki 或技术标 assembler。

## 1. 当前结论

### 1.1 现有 S4 后台情况

当前项目已有完整的技术标 S4 链路：

```text
fill-generation API
  -> draft_generation.py
  -> tech_assembly.py
  -> bid-tech-assembler
  -> s7assemble <manifest>
  -> 生成技术标正文 docx
```

现有技术标 S4 的核心文件：

| 类型 | 路径 | 作用 |
|---|---|---|
| 旧统一入口 | `code/sewpg-bid-backend/app/services/draft_generation.py` | 当前无条件转发到技术标 assembly |
| 技术标 S4 服务 | `code/sewpg-bid-backend/app/services/tech_assembly.py` | 准备技术标 manifest，调用技术标 assembler |
| 技术标 S4 Skill | `code/sewpg-bid-backend/opencode/skill/bid-tech-assembler/` | 技术标 Word 拼装 |
| opencode 命令 | `code/sewpg-bid-backend/opencode/Dockerfile` | 当前注册 `s7assemble` |
| S4 API | `code/sewpg-bid-backend/app/api/routes/generation.py` | `/fill-generation` 状态、触发、进度 |
| S4 前端 | `code/sewpg-bid-frontend/src/pages/GenerateProgress.jsx` | 生成标书状态页面 |

目前未发现商务标专用 S4 assembler：

- 没有 `bid-business-assembler`
- 没有 `businessassemble`
- 没有 `business_assembly.py`
- 当前 `/fill-generation` 如果直接用于商务标，会进入技术标拼装语义

### 1.2 商务标 S4 推荐路线

商务标 S4 采用与技术标类似的工程形态，但业务规则独立：

```text
S2 已确认商务目录
  + S3 已确认 business_gap_plan
  + 商务标项目事实表
  + 商务解析产物
  + 商务 Wiki / 素材库
  -> bid-business-assembler
  -> businessassemble <manifest>
  -> 商务投标文件 docx
  -> S5 共创
```

第一版采用确定性 runner 生成 Word。

这里的“确定性”不是固定内容，而是：

```text
相同输入 + 相同规则 = 相同输出
```

不是：

```text
所有项目都生成同一份固定 Word
```

商务标 S4 不负责创造事实，只负责把已经确认的目录、材料、字段、附件稳定装配成 Word。

## 2. 设计原则

### 2.1 商务标与技术标隔离

必须遵守：

- 不修改 `bid-tech-assembler` 的业务逻辑。
- 不让商务标读取技术标 `gap_state.plan`。
- 不让商务标写入 `technical-workspace`。
- 不复用技术标 `assembly_plan.json` schema 作为商务标正式 schema。
- 不把商务标 Wiki 伪装成技术标 Wiki。
- 不让商务标输出文件覆盖技术标中间产物。

允许复用：

- `/fill-generation` 这类历史 API 名称。
- `fill_state` 作为 S4 状态容器。
- 技术标 `opencode` 调用模式。
- 技术标 runner 的 manifest 模式。
- 技术标页面的进度展示结构。

### 2.2 商务标 S4 的职责边界

商务标 S4 负责：

- 根据已确认商务目录生成 Word 章节骨架。
- 根据 S3 已确认任务落位响应件。
- 根据项目事实表替换项目编号、项目名称、招标人、投标人、日期等字段。
- 挂载解析阶段生成并已审核的承诺书。
- 挂载 S3 上传或选择的补料。
- 使用商务 Wiki / 素材库选择已确认证据材料。
- 对缺失字段、待签字、待盖章、待确认有效期等事项输出复核清单。

商务标 S4 不负责：

- 重新解析招标文件。
- 重新生成商务目录。
- 重新识别缺口。
- 任意编造报价、日期、证书编号、授权人、业绩事实。
- 自动修改原始证书扫描件内容。
- 自动把未审核材料沉淀为通用素材。

### 2.3 确定性 runner 的必要性

商务标高风险字段多，第一版不建议让 AI 自由生成：

| 高风险内容 | 第一版处理方式 |
|---|---|
| 报价金额 | 只从项目事实表、确认表格或人工上传文件读取 |
| 项目编号 | 只从解析结果或项目事实表读取 |
| 招标人/项目单位 | 只从解析结果或项目事实表读取 |
| 授权人 | 未确认时写 `[待填写：授权人]` |
| 证书编号 | 只引用证据材料，不改写 |
| 证书有效期 | 提示复核，不自动承诺有效 |
| 保证金/保函 | 只挂载已上传或已选定文件 |
| 承诺书 | 使用解析阶段产物或模板填充，不临场扩写 |

后续 AI 增强应围绕“辅助判断”，而不是“创造事实”。

## 3. 目标链路

### 3.1 用户流程

```text
S0 商务解析
  -> 生成项目基础字段、商务评分标准、附件模板、承诺书产物

S1/S2 商务模板与目录
  -> 生成商务目录
  -> 人工审核确认目录

S3 商务缺口处理
  -> 生成 business_gap_plan
  -> 人工补料、选材、确认任务
  -> 维护项目事实表

S4 商务生成标书
  -> 根据目录和 S3 确认结果装配商务投标文件
  -> 输出 Word、装配计划、复核清单

S5 共创
  -> OnlyOffice 编辑和人工精修

S6 导出
  -> 导出最终文件
```

### 3.2 后端调用流程

```text
POST /api/projects/{project_id}/fill-generation/run
  -> store.start_fill_generation(project_id)
  -> draft_generation.generate_draft_for_project_with_progress(...)
  -> 根据 bidType 分流
      -> 技术标：assemble_tech_bid_for_project_with_progress(...)
      -> 商务标：assemble_business_bid_for_project_with_progress(...)
  -> business_assembly.py 准备 manifest
  -> OpencodeClient 调用 bid-business-assembler
  -> businessassemble <manifest>
  -> 写入 business-workspace/s4_assembly_workdir
  -> 保存 fill_state
```

### 6.3 `business_needs_review.md` 应包含

- 未填写字段。
- 使用占位符的章节。
- 待盖章文件。
- 待签字文件。
- 证书有效期待核验项。
- 机型证书与所选机型不确定项。
- S3 未确认但被引用的任务。
- 项目事实表未确认但已使用的字段。
- 多候选材料冲突。
- 图片/PDF/扫描件插入失败或仅保留引用的附件。

### 7.1 新增 Skill

```text
  samples/
    sample_manifest.json
    sample_business_assembly_plan.json
```

### 7.2 Skill 职责

`bid-business-assembler` 必须写清：

- 只服务商务标 S4。
- 不读取技术标 workspace。
- 不调用技术标 assembler。
- 不生成事实。
- 所有缺失值使用占位符。
- 所有需人工判断项写入 `business_needs_review.md`。
- 扫描件和图片类材料以原件优先，不能强制改写成文本。
- PDF、图片、扫描件第一版应尽量嵌入最终 Word，而不是只做附件引用。
- 商务评分标准必须进入最终商务标 Word。

### 7.3 runner 第一版职责

第一版 `run_from_manifest.py` 只做确定性装配：

1. 校验 manifest。
2. 读取商务目录。
3. 读取 `business_gap_plan`。
4. 读取项目事实表。
5. 读取解析产物。
6. 生成 `business_assembly_plan.json`。
7. 按目录顺序创建 Word。
8. 对可填字段做替换。
9. 对已确认 docx 产物做合并或复制正文。
10. 对图片/PDF/扫描件类材料尽量嵌入 Word。
11. 对缺失项写占位符。
12. 输出报告。

## 8. 商务标 Word 装配策略

### 8.1 章节骨架

以 S2 已确认商务目录为唯一骨架：

- 目录中有的章节必须出现在 Word 中。
- 目录中没有的内容不能随意新增大章节。
- 解析阶段生成的承诺书应优先落到 S3 指定的 `tocTarget`。
- 找不到明确落位时，进入“投标人需要说明的其他内容”或写入待复核。

### 8.2 材料落位

按优先级读取：

1. S3 已确认的 `resolvedArtifacts`。
2. S3 已选择的 `selectedMaterialRefs`。
3. S3 上传补料。
4. S3 未完全确认但已有明确候选或产物的任务。
5. 商务 Wiki 映射到的证据材料。
6. 商务素材库候选材料。
7. 占位符。

如果使用了 S3 未完全确认的任务，S4 允许继续生成，但必须在 `business_needs_review.md` 中标记。

### 8.3 字段填充

字段来源优先级：

1. S3 已确认项目事实表。
2. 商务解析 `projectFactFields`。
3. 项目基础信息。
4. 人工占位符。

禁止从正文中猜测高风险字段。

项目事实表未确认时，S4 允许生成带占位符或草稿值的 Word，但必须在 `business_needs_review.md` 中列出“项目事实表未确认”风险。

### 8.4 附件与扫描件处理

第一版确定采用“尽量嵌入 Word”的策略。

这里的“附件引用”是指：Word 正文里只写“详见附件：营业执照.pdf”，但不把 PDF 页面或证书图片真正放入 Word。  
这里的“嵌入 Word”是指：把图片、证书扫描件或 PDF 页面转成图片后，直接插入对应章节正文中。

商务标中很多证书、证明、授权文件本身就是图片或扫描件，因此第一版不能只做附件引用。

第一版处理规则：

- docx 文件可以尝试合并正文。
- 图片文件必须尽量插入到对应章节。
- PDF 文件必须尽量按页转图片后插入到对应章节。
- 扫描件必须尽量以图片形式嵌入对应章节。
- 无法安全插入时，才退化为附件引用，并写入 `business_needs_review.md`。

后续可增强：

- 多页证书批量插入。
- 附件页码索引。
- 自动横版页面处理。

### 8.5 商务评分标准处理

商务评分标准必须进入最终商务标 Word。

落位原则：

1. 如果 S2 商务目录中存在“商务评分标准”“评分响应”“评分索引表”等章节，优先落到对应章节。
2. 如果目录中没有明确章节，生成到“投标人需要说明的其他内容”或相近的评分/响应章节。
3. 如果解析阶段已产出 `商务评分标准.docx`，优先直接合并该 docx。
4. 如果只有结构化 JSON，则由 S4 生成评分标准表格。
5. 如果评分标准缺失，生成占位符并写入 `business_needs_review.md`。

允许例外：

- S3 未完全确认时，可以生成带风险提示和占位符的 Word。
- 项目事实表未确认时，可以生成带占位符或草稿字段的 Word。

## 11. 验收标准

### 11.1 第一版验收

第一版完成后应满足：

- 商务标点击“生成标书”不再进入技术标 assembler。
- 技术标点击“生成标书”仍然走原技术标链路。
- 商务标生成文件写入 `business-workspace/s4_assembly_workdir`。
- 最终 Word 可以在 S5 OnlyOffice 打开。
- Word 章节顺序与 S2 已确认商务目录一致。
- S3 已确认的承诺书、上传补料、选择素材能进入 Word。
- 图片、PDF 页面、扫描件第一版应尽量嵌入 Word；只有嵌入失败时才退化为附件引用。
- S3 未完全确认时允许生成，但必须输出明确复核风险。
- 项目事实表未确认时允许生成，但必须输出明确复核风险。
- 商务评分标准必须进入最终 Word。
- 缺失字段不乱填，统一写占位符。
- 待盖章、待签字、待确认有效期等事项进入 `business_needs_review.md`。
- 测试覆盖技术标回归和商务标新增链路。

### 11.2 不作为第一版验收项

以下能力可以后续增强，不要求第一版完成：

- 所有扫描件自动 OCR 并重排为 Word。
- 自动生成完整报价表。
- 自动判断所有证书有效期是否满足招标要求。
- 自动处理复杂横版/纵版混排。
- 自动生成附件页码索引。
- AI 自动改写所有说明文字。
