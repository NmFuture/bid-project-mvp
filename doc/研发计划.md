# 研发计划

## 1. 当前目标

先把现有框架收成可验收版本，再扩展新增需求。

研发重点不是继续堆页面或文档，而是用真实技术标、真实商务标样本跑通闭环，找出差距并修到可交付。

## 2. 阶段一：文档和基线收口

目标：

- 旧文档归档。
- 当前只保留 4 个核心文档。
- 确认当前代码可以启动、健康检查可用。

产出：

- `值得留下来的内容.md`
- `代码结构梳理.md`
- `需求梳理.md`
- `研发计划.md`

## 3. 阶段二：真实样本验收

目标：

- 准备 1 个真实技术标样本。
- 准备 1 个真实商务标样本。
- 分别从导入、解析、目录、素材、生成、编辑、导出跑完整流程。

重点记录：

- 哪一步失败。
- 是前端问题、后端问题、Skill 问题、素材问题，还是部署问题。
- 最终 Word/PDF 是否能被人工接受。

## 4. 阶段三：技术标质量提升

目标：

- 补齐附表填写。
- 补齐待填写 Word。
- 补齐证据来源和人工复核提示。
- 补齐格式和导出前检查。

验收：

- 真实样本可生成可编辑 Word。
- 人工能清楚看到哪些内容可用、哪些内容需要确认。

## 5. 阶段四：商务标质量提升

目标：

- 验证商务评分、资格条件、承诺、否决项、附件和业绩链路。
- 打通商务素材库和商务 Wiki 的真实使用。
- 完成商务标正文生成、共创和导出。

验收：

- 真实商务标样本能跑完整流程。
- 关键商务风险不被系统静默忽略。

## 6. 阶段五：新增需求一期

优先级：

1. 解析字段维护表。
2. 业绩共享。
3. 三级目录加标签检索。
4. 混排机型。
5. 部署监控和一键启停。

原则：

- 先做能支撑真实交付的最小版本。
- 不先做大而全配置中心。

## 7. 阶段六：生产加固

目标：

- 后端角色和工作区强授权。
- 项目类型 scope 校验。
- 设置页权限限制。
- 部署脚本、离线包、操作手册、管理员手册。
- 验收报告和已知边界清单。

## 8. 近期下一步

1. 选定真实技术标样本和真实商务标样本。
2. 启动当前 Docker 环境。
3. 分别跑一遍完整流程。
4. 把失败点整理成研发任务。
5. 先修阻断主流程的问题，再做体验优化。
