# 评测体系与 S3 重组开发记录

> 日期：2026-05-07
> 范围：仅覆盖 `doc/17-评测体系建设计划.md` 与 `doc/18-S3缺口处理重组路线.md` 的本轮开发落地。
> 不包含：`doc/14-甲方新增需求待办.md` 中的评分点覆盖、导出 PDF、商务标、邮件通知等事项。

## 1. 本轮目标

本轮不是继续调 S3 填写 prompt，也不是直接改主流程行为，而是先补两类基础设施：

1. **doc/17 评测体系工程化**：把“85% 人工基准”从口头目标变成可加载、可校验、可运行、可归因的字段级评测框架。
2. **doc/18 S3 重组基础件**：预置知识库 schema、确定性推理、结构化复查和 Wiki 健康检查，等 doc/17 baseline 出来后再决定是否接入主链路。

当前策略是：**评测先行，架构改造后置**。没有真实 baseline 前，不把 doc/18 的组件接入生产 S3 流程。

## 3. doc/17 评测体系落地

### 3.1 目录结构

新增目录：

```text
code/sewpg-bid-backend/eval/
  docs/
  gold/
  judge/
  runs/
  scripts/
```

关键约束写入 `eval/README.md`：

- eval 代码与生产 S3 Skill 物理隔离。
- eval 可以读取 Skill 导出的产物，但 Skill 不允许读取 eval/gold。
- eval 当前尽量只使用标准库；docx 草稿抽取使用项目已有 `python-docx`。

### 3.2 Schema 与加载校验

新增文件：

| 文件 | 作用 |
|---|---|
| `eval/docs/gold_schema.md` | 人工 gold CSV 契约。 |
| `eval/docs/prediction_schema.md` | 自动 prediction CSV 契约。 |
| `eval/scripts/gold_schema.py` | `GoldRow`、`PredictionRow`、主键和枚举定义。 |
| `eval/scripts/load_gold.py` | 加载 gold CSV。 |
| `eval/scripts/validate_gold.py` | 校验 gold CSV。 |
| `eval/scripts/load_predictions.py` | 加载 prediction CSV。 |
| `eval/scripts/validate_predictions.py` | 校验 prediction CSV。 |

gold 主键：

```text
project_id + doc_type + locator + field_name
```

prediction 使用同一主键对齐 gold。

### 3.3 Gold 草稿抽取

新增：

```text
eval/scripts/extract_gold_draft.py
```

用途：

- 对正文：识别 `[字段，待填写]`、`[待填写：字段]`、`[字段，待补充]` 等占位符，生成 body gold 草稿。
- 对附表：扫描 Word 表格行，生成 appendix gold 草稿。

注意：该脚本只生成**草稿**。真实 gold 仍需要人工补齐或校正：

- `human_answer`
- `field_type`
- `difficulty_tier`
- `evidence_source`

### 3.4 Prediction 抽取

新增：

```text
eval/scripts/extract_predictions.py
```

用途：

- 从当前 S3 填写产物的 `.fill_report.json` 中读取：
  - `filledFieldDetails`
  - `unfilledFieldDetails`
  - `evidenceRefs`
  - `fillReport`
- 转成统一 prediction CSV。

后续真实 baseline 时，需要重点检查 locator 对齐率。如果真实产物 locator 不够稳定，要继续补 locator 规则。

### 3.5 字段级 Diff 与 Metrics

新增：

| 文件 | 作用 |
|---|---|
| `eval/scripts/diff_engine.py` | 字段级匹配。 |
| `eval/scripts/compute_metrics.py` | 指标聚合。 |
| `eval/scripts/failure_breakdown.py` | 失败归因。 |
| `eval/scripts/audit_evidence.py` | 证据链抽样审计。 |

## 4. doc/18 S3 重组基础件

### 4.1 知识库证据卡片

新增：

```text
code/sewpg-bid-backend/app/services/kb_schema.py
```

包含：

- `KnowledgeLockStatus`
- `card_from_fact_field()`

锁定状态：

```text

```

当前仅提供 schema 和转换函数，尚未替换现有 `projectFactTable`。

### 4.2 确定性推理规则

新增：

```text
code/sewpg-bid-backend/app/services/derive_rules.py
```

当前支持：

- `单机容量 × 机组台数 = 总装机容量`
- `总装机容量 / 单机容量 = 机组台数`
- `保证发电量 / 总装机容量 = 保证有效小时数`
- 容量闭合检查

该模块用于 doc/18 中“LLM 不算数学”的工程底座。

### 4.3 结构化复查器

新增：

```text
code/sewpg-bid-backend/app/services/gap_reviewer.py
```

当前检查：

- 关键事实强一致：项目名、招标编号、投标机型、容量、台数等。
- 附表 vs 正文交叉引用：当前先覆盖投标机型。
- T5/黄标合理性：标黄但没有证据或检索记录时进入问题清单。
- 数值闭合：复用 `derive_rules.check_numeric_closure()`。

当前仅作为基础函数存在，尚未接入 S3 页面。

### 4.4 Wiki Health 与 BM25 预案

新增：

```text
code/sewpg-bid-backend/app/services/wiki_health.py
eval/docs/material_search_plan.md
```

`wiki_health.py` 当前输出：

- Wiki 卡片数
- Markdown 文件数
- 总字节数
- 估算 token 数
- 健康告警

`material_search_plan.md` 记录后续 BM25 兜底设计。当前未做数据库迁移，也未接入素材检索主链路。

## 7. 后续执行顺序

### 第一步：补齐人工基准文件

拿到人工版附表和正文后执行：

```bash
python3 eval/scripts/extract_gold_draft.py \
  --project-id PRJ-0003 \
  --doc-type appendix \
  --input /path/to/投标文件-附表.docx \
  --output eval/gold/PRJ-0003/appendix.csv

python3 eval/scripts/extract_gold_draft.py \
  --project-id PRJ-0003 \
  --doc-type body \
  --input /path/to/投标文件-正文.docx \
  --output eval/gold/PRJ-0003/body.csv
```

然后人工校对 gold。

### 第二步：抽取当前 S3 prediction

从真实 S3 AI 填写产物中收集 `.fill_report.json`，执行：

```bash
python3 eval/scripts/extract_predictions.py \
  --project-id PRJ-0003 \
  --doc-type appendix \
  --reports /path/to/appendix/*.fill_report.json \
  --output eval/runs/baseline-prj0003/predictions_appendix.csv

python3 eval/scripts/extract_predictions.py \
  --project-id PRJ-0003 \
  --doc-type body \
  --reports /path/to/body/*.fill_report.json \
  --output eval/runs/baseline-prj0003/predictions_body.csv
```

必要时合并为：

```text
eval/runs/baseline-prj0003/predictions.csv
```

### 第三步：跑真实 baseline

```bash
python3 eval/scripts/run_eval.py \
  --gold eval/gold/PRJ-0003/appendix.csv eval/gold/PRJ-0003/body.csv \
  --predictions eval/runs/baseline-prj0003/predictions.csv \
  --run-dir eval/runs/baseline-prj0003
```

产出：

```text
metrics.json
failure_breakdown.json
evidence_audit.csv
report.md
```

### 第四步：根据 baseline 决定 doc/18 接入范围

建议判断口径：

| baseline 结果 | 下一步 |
|---|---|
| 75-80 分以上 | 优先只接结构化复查器。 |
| 60-70 分 | 走 doc/18 轻量路径 A：KB、按需弹窗、fill_instructions、derive、reviewer。 |
| 低于 50 分 | 考虑完整四层重组。 |

### 第五步：准备 hold-out test

选择第二个人工完整项目作为 test 集，重复 gold 拆分和评测，但不允许先调 prompt。
