# 技术标与商务标双轨独立化实施计划

> 目标：把技术标和商务标做成两条独立生产线。先把商务标这条线整理清楚、跑通、规范好，再按同样标准整理技术标。
> 更新日期：2026-05-25

## 1. 一句话说明

用户按权限进入系统后，只能看到自己该看的业务线：

```text
技术标账号 -> 技术标入口 -> 技术标流程
商务标账号 -> 商务标入口 -> 商务标流程
双权限账号 -> 可选择技术标或商务标
```

进入之后，两条路要尽量互不影响：

```text
技术标页面 -> 技术标接口 -> 技术标后端逻辑 -> 技术标 Skill -> 技术标素材库 -> 技术标导出

商务标页面 -> 商务标接口 -> 商务标后端逻辑 -> 商务标 Skill -> 商务标素材库 -> 商务标导出
```

## 2. 为什么要这么做

现在系统已经有技术标和商务标两个入口，但很多地方还没有真正分干净：

- 有些商务标页面只是包了一层共享页面。
- 有些后端接口靠 `bidType` 判断走技术标还是商务标。
- 有些素材库逻辑是同一套代码里按标类过滤。
- 有些 UI 改动可能会同时影响两边。

这样继续做下去，后面会越来越难维护。一个人改技术标 UI，可能不小心影响商务标；一个人调技术标 Skill，也可能碰到商务标共用逻辑。

这次改造就是要把边界讲清楚、拆清楚。

## 3. 什么叫完全分离

这里的“完全分离”不是说必须拆成两个仓库，也不是说数据库、登录、部署都要复制两套。

真正要分离的是业务链路：

| 层级 | 技术标 | 商务标 | 要求 |
|---|---|---|---|
| 账号入口 | 技术标权限 | 商务标权限 | 按权限进入对应入口 |
| 前端页面 | 技术标页面 | 商务标页面 | 改一边 UI 不影响另一边 |
| 前端路由 | `/workspace/tech/...` | `/workspace/business/...` | 路由清楚分开 |
| API | 技术标接口 | 商务标接口 | 核心业务接口不要混在一起 |
| 后端服务 | 技术标 service | 商务标 service | 各自处理自己的业务逻辑 |
| Skill | `bid-tech-*` | `bid-business-*` | 调 prompt 或规则时互不影响 |
| 素材库 | 技术标素材库 | 商务标素材库 | 默认互相不可见 |
| Wiki | 技术标 Wiki | 商务标 Wiki | 独立生成、独立维护 |
| 导出 | 技术标 Word | 商务标 Word | 各自走自己的生成和格式逻辑 |

可以共享的是底层工具：

- 登录和权限底座
- 基础按钮、弹窗、表格组件
- HTTP 请求工具
- 文件上传底层能力
- OnlyOffice 编辑器壳
- Docker、数据库、MinIO 等基础设施

不能共享的是业务判断：

- 不要在同一个核心页面里写大量 `如果是技术标就这样，如果是商务标就那样`。
- 不要在同一个核心 service 里堆大量 `bidType` 分支。
- 不要让技术标 Skill 和商务标 Skill 共用一套业务 prompt。
- 不要让商务标素材默认去技术标素材库里找东西。

## 4. 最终想要的样子

以后开发时，规则应该非常简单：

```text
改技术标 UI：
只改 technical 侧页面，商务标页面不变。

改商务标 UI：
只改 business 侧页面，技术标页面不变。

调技术标 Skill：
只调 bid-tech-*，商务标 Skill 不变。

调商务标 Skill：
只调 bid-business-*，技术标 Skill 不变。

改技术标素材库：
只影响技术标素材、技术标 Wiki 和技术标生成。

改商务标素材库：
只影响商务标素材、商务标 Wiki 和商务标生成。
```

如果确实有少量共同素材，比如业绩表、企业资质、通用证书，也不能靠混用目录解决，而要明确标记为“共享素材”。

## 5. 先做商务标

第一阶段先把商务标整理成标准样板。

商务标目标流程先定为：

```text
商务标解析
-> 商务标项目列表
-> 商务标模板与目录
-> 商务标目录审核
-> 商务标素材匹配
-> 商务标共创编辑与导出
```

对应页面先收敛为：

```text
/parse/business
/workspace/business/projects
/workspace/business/projects/:id/template-directory
/workspace/business/projects/:id/outline
/workspace/business/projects/:id/gaps
/workspace/business/projects/:id/editor
```

商务标和技术标主流程都已经删除独立的生成、覆盖和最终导出前端页面。生成能力收进 `/gaps`，编辑、格式和下载收进 `/editor`，避免 AI 和用户误以为后半段还有另一套页面流程。旧根路径兼容入口和 workspace 内部兼容别名也已经删除，后续只保留明确的双轨主路径。前端阶段进度已经拆成 `BusinessProjectStageProgress` 和 `TechnicalProjectStageProgress`，两边组件都不再包含 `/generate`、`/coverage`、`/export` 页面配置。

旧根入口也不再作为真实业务入口使用，当前前端路由表已删除这些入口：

```text
/projects
/materials/structured
/materials/wiki
/audit
```

以后必须从明确的 workspace 入口进入：

```text
/workspace/tech/...
/workspace/business/...
```

## 6. 商务标要改清楚的内容

### 6.1 前端

- 商务标页面放在 business 侧。
- 商务标页面不要继续直接复用技术标主流程页面。
- 商务标阶段条、按钮、弹窗、表格、状态文案统一。
- 商务标项目进入流程要清楚：没参与回解析页，已参与进当前阶段。
- 商务标素材库和 Wiki 页面只展示商务标内容。

### 6.2 后端

- 商务标核心接口逐步独立出来。
- 商务标核心 service 独立出来。
- 商务标产物目录独立。
- 商务标生成、改写、格式处理走商务标自己的逻辑。
- 后端不要继续靠一堆 `bidType` 分支支撑主流程。

### 6.3 Skill

- 商务标解析用商务标 Skill。
- 商务标目录用商务标 Skill。
- 商务标素材匹配用商务标 Skill。
- 商务标正文生成用商务标 Skill。
- 商务标格式清理用商务标 Skill。

技术标 Skill 不参与商务标流程。

### 6.4 素材库

- 商务标有自己的原始素材目录。
- 商务标有自己的项目素材目录。
- 商务标有自己的 Wiki。
- 商务标素材查询默认不看技术标。
- 共享素材必须显式标记，不能靠路径混用。

## 7. 再同步技术标

商务标跑通并验收后，再用同样方式整理技术标。

技术标不是照搬商务标业务，而是照搬这套结构：

```text
独立页面
独立接口
独立后端 service
独立 Skill
独立素材库
独立 Wiki
独立导出逻辑
```

技术标仍然保留自己的业务特点，比如机型、技术响应、技术素材、技术标生成和技术标格式要求。

## 8. 实施顺序

### 第一步：冻结规则

- 确认本文档作为双轨独立化总原则。
- 确认以后新增需求默认先判断属于技术标还是商务标。
- 确认共享组件只能放底层，不能把业务流程继续混在一起。

### 第二步：商务标前端独立化

- 清理商务标旧路由。
- 拆掉商务标对技术标主流程页面的直接复用。
- 统一商务标 UI。
- 明确商务标每个页面的职责。

### 第三步：商务标后端独立化

- 梳理商务标 API。
- 梳理商务标 service。
- 梳理商务标产物目录。
- 减少主流程里的 `bidType` 分支。

### 第四步：商务标素材库独立化

- 补齐商务标素材目录。
- 补齐商务标 Wiki。
- 明确共享素材策略。
- 验证商务标不会误读技术标素材。

### 第五步：商务标完整验收

从头跑一遍商务标：

```text
上传商务标招标文件
-> 解析
-> 决定参与
-> 建项目
-> 生成目录
-> 审核目录
-> 匹配素材
-> 生成正文
-> 共创编辑
-> 导出 Word
```

### 第六步：同步整理技术标

- 按商务标样板整理技术标页面。
- 按商务标样板整理技术标 API 和 service。
- 按商务标样板整理技术标素材库和 Wiki。
- 最终形成两条平行、独立、互不干扰的业务线。

## 9. 验收标准

这件事完成时，应该能回答下面的问题：

- 改技术标 UI，会不会影响商务标？答案应该是不会。
- 改商务标 UI，会不会影响技术标？答案应该是不会。
- 调技术标 Skill，会不会影响商务标？答案应该是不会。
- 调商务标 Skill，会不会影响技术标？答案应该是不会。
- 商务标素材会不会默认读技术标素材？答案应该是不会。
- 技术标素材会不会默认读商务标素材？答案应该是不会。
- 用户登录后，能不能按权限进入正确业务线？答案应该是能。
- 商务标能不能从上传文件一直跑到导出 Word？答案应该是能。
- 技术标能不能按同样清晰的边界运行？答案应该是能。
