## 待办 12/15 联合改造计划

> 记录时间：2026-05-02
> 状态：已实施。待办 12 和 15 已按联合改造口径完成，后续模型效果和复杂样本质量调优继续在相关专项待办中推进。

### 目标流程

1. 解析页面先从招标文件中解析评分细则、项目基础信息、风机参数、性能指标、环境适应性、专题方案、附表空表等结构化结果，并完成是否投标决策。
2. 决定投标后进入技术标工作流，第一步上传投标模板；如项目未上传模板，则 fallback 到系统通用模板。
3. 调用目录生成 OpenCode Skill。目录生成输入为：素材库 Wiki、解析后的招标文件结构化结果、项目上传或 fallback 的投标模板。
4. 人工审核并确认目录后，进入“缺口识别与处理”。
5. “缺口识别与处理”调用新的 OpenCode Skill，根据已确认目录、素材库 Wiki、真实素材库、解析结果和已有补料记录，生成可审核的匹配/缺口/处理计划。
6. 缺口项支持直接上传客户资料，或调用 OpenCode Skill 进行 AI 填写。AI 填写时由人工指定需要填写的空表/Word，以及可参考的素材库文件、解析字段或补料文件。
7. AI 填写产物作为项目补料结果入库，并可用 OnlyOffice 预览；无法填写的字段高亮或进入人工确认。
8. 所有缺口解决后，在缺口页内执行“重新检查缺口/完整性校验”。
9. 校验通过后直接进入标书生成。标书生成 Skill 按人工确认后的目录和缺口处理计划，使用原始素材、人工补料和 AI 填写产物拼接完整技术标正文，随后进入共创阶段。

### 核心中间产物

新增统一计划数据，作为 S3 目录审核之后、S7 标书拼接之前的唯一桥梁，可存为 `gap_plan.json` 或项目状态中的 `gapPlan`。

计划至少包含：

- 目录项：`tocItemId`、`number`、`title`、父章节、目录审核版本。
- 状态：`matched`、`missing`、`needs_input`、`filling`、`resolved`、`ignored`。
- 已匹配素材：素材 ID、素材库层级、Wiki 卡片、清洗稿 Word、匹配理由、置信度。
- 缺口原因：无素材、素材不适用、需要客户资料、需要填写附表空表、需要人工确认。
- 处理动作：上传补料、选择已有素材、AI 填写、忽略并说明原因。
- AI 填写任务：空表/Word 来源、参考素材、可用解析字段、输出文件、未填字段、高亮信息。
- 解决产物：人工上传文件、AI 填写文件、OnlyOffice 预览会话、是否可进入 S7 拼接。
- 校验结果：缺口是否清零、仍需人工确认的项、阻断标书生成的原因。

### 后端改造

1. 新增缺口识别 Skill，例如 `bid-tech-gap-planner`。
   - 输入：已确认目录 JSON、招标解析结构化结果、素材库 Wiki、真实素材库索引、项目身份、已有补料记录。
   - 输出：匹配/缺口/处理计划 JSON，不直接生成正文 Word。
2. 新增 AI 填写 Skill，例如 `bid-tech-table-filler` 或 `bid-appendix-filler`。
   - 输入：待填写空表/Word、人工指定的参考素材、招标解析字段、项目参数和填写约束。
   - 输出：填好的 Word/表格文件、未填字段清单、证据引用和高亮提示。
3. 改造 S4/S5/S6 后端接口。
   - `run_gap_detection` 不再从目录叶子节点伪造缺口，改为准备 manifest 并调用 `bid-tech-gap-planner`。
   - 补料上传真实写入项目素材库，不再只生成 mock receipt。
   - AI 填写结果真实写入项目素材库或项目产物区，并挂回对应缺口项。
   - 审核/校验读取 `gapPlan`、真实补料记录和 AI 填写产物。
4. 改造 S7 标书生成。
   - `bid-tech-assembler` 增加 `gapPlanPath` / `assemblyPlanPath` 输入。
   - 优先按缺口页确认后的计划拼接，不再完全依赖固定 `skeleton_section` 规则临时猜素材。
   - Word 合并、Heading、finalize、verify 能力继续复用。

### 前端改造

1. 模板上传页承接目录生成入口。
   - 模板上传后按钮直接变为“生成目录”。
   - 当前页显示 OpenCode/Skill 进度、任务状态和原始输出。
   - 目录生成完成后直接进入目录审核。
2. 去掉独立目录生成页、备料页、审核页的主流程入口。
   - 老路由可保留兼容或重定向，避免历史链接失效。
3. 将缺口识别页升级为“缺口识别与处理”。
   - 展示目录项、匹配素材、缺口原因、处理动作、状态和校验结果。
   - 支持上传客户资料、选择已有素材、发起 AI 填写、忽略并填写原因。
   - 支持 AI 填写任务状态、产物 OnlyOffice 预览、未填字段提示。
   - 内嵌“重新检查缺口/完整性校验”。
   - 缺口全部解决后直接触发标书生成并进入共创。

5. 健康页展示真实状态、延迟、最近检查时间和错误说明。

完成标准：

- 技术标和商务标系统默认模板可分别上传和启用。
- 项目上传模板优先于系统默认模板；项目未上传模板时才使用设置中的默认模板。
- LLM 和 PDF/图片识别模型的 Base URL 和 API Key 可在设置页维护，后端不向前端回传明文 Key。
- LLM 和 PDF/图片识别模型连接测试能真实成功或失败。
- 关闭某个依赖服务后，健康页能显示异常。
- 所有设置变更有真实审计日志。

### 设置侧模板、工作区和文件区规划

> 记录时间：2026-05-03
> 状态：规划确认。用于约束后续实现和 MinIO 整理，不新增独立“目录模板”概念。

目标是让设置页直接上传的技术标/商务标系统默认模板，在项目未上传模板时自动成为技术标或商务标生成输入。它不是项目上传文件的替代展示项，而是全局模板资产；生成阶段按统一规则解析成“本轮有效模板”。

#### 一、模板资产区

设置页维护的是系统级模板资产，分技术标和商务标两类：

| 模板类型 | PostgreSQL 记录 | MinIO 对象位置 | 用途 |
| --- | --- | --- | --- |
| 技术标系统默认模板 | `template_assets.asset_type=default_template`，`table_key=technical` | `bid-templates/templates/default/technical/{uuid}-{file_name}` | 技术标项目未上传模板时优先使用 |
| 商务标系统默认模板 | `template_assets.asset_type=default_template`，`table_key=business` | `bid-templates/templates/default/business/{uuid}-{file_name}` | 商务标项目未上传模板时优先使用 |

规则：

1. 设置页上传只接受真实可打开的 `.docx`；小文件、坏 zip、非 Word 文件不能入库为启用模板。
2. 同一模板类型可以保留历史版本，但只能有一个 `is_active=true`。
3. MinIO 中的 `templates/default/...` 是系统默认模板区，不混入素材库 `raw/...`。
4. 技术标和商务标都只认设置侧当前启用的系统默认模板；旧 `templates/fallback/...` 对象不再进入生成链路。

#### 二、项目上传区

项目级上传仍保持当前语义：

```text
{UPLOADS_DIR}/{project_id}/tender/
{UPLOADS_DIR}/{project_id}/template/
```

其中：

1. `tender/` 保存招标文件原件。
2. `template/` 只保存用户在该项目真实上传的投标模板。
3. 设置侧默认模板不写入 `templateFileRecords`，避免污染项目文件列表。
4. 前端项目页展示“项目已上传模板”和“当前将使用的系统默认模板”应分开展示。

#### 三、有效模板解析区

S2 目录生成和 S7 标书生成都只能通过同一个解析入口拿模板，优先级如下：

1. 项目上传模板：`{UPLOADS_DIR}/{project_id}/template/`。
2. 设置侧当前启用系统默认模板：按项目 `bidType` 选择 `technical` 或 `business`。
3. 没有可用模板时，返回明确错误或提示，而不是让 Skill 读取空路径。

当使用设置侧模板时，后端下载到项目级临时输入区：

```text
{UPLOADS_DIR}/{project_id}/system-default-template/{file_name}
```

这些文件只表示生成时的输入副本。它们可以被 S2/S7 manifest 引用，但不代表项目有用户上传模板。

#### 四、S2/S7 工作区

技术标当前主流程的工作区继续保持两层：

```text
{DOCUMENTS_DIR}/{project_id}/technical-workspace/parse/
{DOCUMENTS_DIR}/{project_id}/technical-workspace/s2_toc_workdir.new/
{DOCUMENTS_DIR}/{project_id}/technical-workspace/s2_toc_workdir/
{DOCUMENTS_DIR}/{project_id}/technical-workspace/s2_toc_workdir.runs/
{DOCUMENTS_DIR}/{project_id}/technical-workspace/s4_gap_workdir/
{DOCUMENTS_DIR}/{project_id}/technical-workspace/s7_assembly_workdir/
{DOCUMENTS_DIR}/{project_id}.docx
```

规则：

1. S2 在 `.new` 中准备 `s2_input.json`、复制后的有效模板、招标文件文本和目录结果；成功后发布到 `s2_toc_workdir/`。
2. S2 失败时不覆盖上一次成功目录，`.new` 留作排查。
3. S7 在 `s7_assembly_workdir/` 中准备 `s7_assembly_input.json`、目录 JSON、Wiki 导出、素材库导出、缺口处理计划和有效模板路径。
4. S7 产出的正文 docx 复制到 `{DOCUMENTS_DIR}/{project_id}.docx`，供共创和导出使用。
5. 技术标/商务标后续都应复用“有效模板解析 -> 生成工作区 manifest -> Skill 执行 -> 文档区产物”的模式，只替换具体 Skill 和业务 manifest 字段。

#### 五、MinIO 整理口径

MinIO 需要按资产边界整理，而不是按页面随意堆文件：

| Bucket / key 前缀 | 归属 | 处理原则 |
| --- | --- | --- |
| `bid-templates/templates/default/technical/` | 技术标系统默认模板 | 保留历史版本；数据库只有一个启用指针；坏对象不得启用 |
| `bid-templates/templates/default/business/` | 商务标系统默认模板 | 同上 |
| `bid-materials/raw/...` | 素材库原始文件 | 属于素材库，不和系统模板混放 |
| `bid-documents/documents/{project_id}/...` | 生成文档和 OnlyOffice 同步 | 属于项目文档产物，不放模板 |

清理策略：

1. 先做只读盘点：列出 `template_assets` 中 active 记录、MinIO 对象 key、大小、DOCX 有效性和是否被引用。
2. 对无效 active 模板先停用或标记不可用，不直接硬删。
3. 对 MinIO 孤儿对象先归档或生成清理报告；确认后再删除。
4. 启动或健康检查时可以暴露“系统默认模板无效”状态，避免坏模板再次进入生成链路。

#### 六、验收标准

1. 设置页上传一个有效技术标默认模板后，新建技术标项目不上传模板也能在 S2/S7 使用该模板。
2. 设置页上传一个有效商务标默认模板后，新建商务标项目不上传模板也能在商务标生成链路使用该模板。
3. 项目上传模板时，永远优先使用项目模板。
4. 坏的系统默认模板不会被展示为可用模板，也不会进入 `s2_input.json` 或 `s7_assembly_input.json`。
5. 技术标或商务标没有有效系统默认模板时，提示“请先上传并启用对应类型的系统默认模板”，不静默使用其他模板。

### 待办 22：PDF / 图片型文件无感解析

目标是复用设置页 OCR/视觉模型配置，让模板上传和招标文件解析步骤能够自动读懂扫描件、图片和图片型 PDF；前端不提供单独 OCR 入口，也不暴露候选字段确认工作台。

后端改造：

1. OCR/视觉识别服务读取系统设置中的 Base URL、API Key、模型名、超时和最大 token 配置。
2. 招标文件解析遇到图片或图片型 PDF 时自动调用 OCR/视觉模型，把识别文本写入 S1 解析输入。
3. 模板上传允许 PDF 和图片格式；后续目录生成或正文生成遇到不可直接读取文本的模板时，按需调用 OCR/视觉模型读取模板内容。
4. 识别结果直接进入原有 LLM/Skill 解析链路，不生成需要用户处理的 OCR 候选字段。
5. OCR/视觉模型失败、超时或配置缺失时返回明确解析警告，不阻断可继续处理的主流程。
6. OCR/视觉模型配置修改和连接测试写审计日志；业务页不再记录“候选确认”类操作。

前端改造：

1. 模板上传和招标文件上传支持 PDF 与图片格式。
2. 解析页、模板与目录页不提供单独 OCR 上传入口。
3. 解析页、模板与目录页不展示 OCR 候选字段、确认、修改、忽略等交互。
4. 用户只看到正常解析结果、目录生成结果和必要的解析警告。

完成标准：

- 设置页未配置 OCR/视觉模型时，图片或扫描件解析给出明确警告，不直接失败成空白页。
- 上传图片或图片型 PDF 后，系统自动把识别文本交给 LLM/Skill 解析。
- 前端没有独立 OCR 入口，也没有 OCR 候选字段确认区。
- 可解析出的项目字段、评分点、附表线索等直接进入原有解析结果。
- OCR/视觉模型配置和连接测试可在审计日志中追溯。
