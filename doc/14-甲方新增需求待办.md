## 第 14 条实施口径

### 目标

第二个 S3 Skill 暂定名 `bid-tech-table-filler`，只做一件事：给定一个待填写 Word/表格和一组参考资料，填充原文件里的空缺位置。

它同时覆盖两类目标：

1. S0 从招标文件中解析出来的空附表，例如技术副表 C。
2. 素材库里的“待填写”Word 模板，例如产品交付、考核验收、设备综合技术参数、升降机等待填文件。

### 填写规则

1. 必须保留原 Word / 表格结构，不重建新表。
2. 能确定的字段直接填入。
3. 不能确定的字段写入 `[待人工补充：字段名]`，并黄色高亮。
4. 不允许编造数据。
5. 输出必须带填写报告：填了多少、没填多少、主要参考了哪些文件、哪些字段需要人工补。

### 参考资料优先级

1. 人工指定的素材优先级最高。
2. 如果上传了 Excel 梳理表，可用 Excel 建议作为参考。
3. 如果没有 Excel，由 OpenCode 根据 Wiki、素材索引和文件名自动判断。
4. 第一个 Skill 的 `recommendedMaterials` 只能作为兜底提示，不能当最终依据。

### 前端入口

前端保留一个简洁入口：

1. 显示 AI 建议的参考素材。
2. 如有 Excel，则显示 Excel 建议。
3. 允许人工增删或改选参考素材。
4. 发起填写时，以人工最终选择为准。

展示不要做重，只显示：

- 填写状态。
- 已填数量。
- 未填数量。
- 主要参考资料。
- OnlyOffice 预览入口。

字段级证据和详细填报依据默认折叠。

### 第一轮样例

先从技术副表 C 开始，优先验证：

1. `附表C.1 总体技术参数与规格`
2. `附表C.2 风轮系统技术参数`
3. `附表C.3 机械传动部件技术参数`

参考资料优先尝试机型投标参数表，例如当前样例中出现过的 `X2平台机型投标参数_20250106.xlsx`。如果第一个 Skill 推荐了风资源、塔架、发电量等明显不适合的材料，第二个 Skill 要能降权或忽略。

### 验收标准

1. 真实项目样例中，至少一个技术副表 C 文件被原样填充成功。
2. 输出 Word 能用 OnlyOffice 打开，表格结构不乱。
3. 未填项有 `[待人工补充：字段名]` 和黄色高亮。
4. 填写报告能说明参考资料、已填字段、未填字段。
5. 前端能让人工改选参考素材，并以人工选择为最终输入。
