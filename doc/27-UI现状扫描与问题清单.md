# UI现状扫描与问题清单

> 范围：第一轮只扫描和优化商务标链路。技术标链路暂不改动，仅在公共组件可能产生影响时作为回归风险检查对象。

## 一、扫描结论

当前前端已经具备一套基础色彩 token 和部分共享组件，但商务标链路的 UI 仍然大量依赖页面内手写 Tailwind class。主要问题不是缺少颜色，而是缺少统一的基础控件出口。

核心判断：

```text
商务标 UI 需要先收敛 Button / IconButton / Input / Select / Card / Badge / Dialog / Table / Toolbar。
```

第一轮不建议大改页面业务结构，也不建议直接重画 Figma 全页面。应先在商务标代码里建立稳定组件层，完成样板页验收后再沉淀到 Figma UI Kit。

## 四、主要问题清单

## P0：商务审核页与技术审核页共用实现，改造风险最高

### 发现

`BusinessTenderReview.jsx` 只是：

```text
<TenderReview config={{ bidType: '商务标' }} />
```

真实 UI 全在 `TenderReview.jsx` 内。该文件同时承载技术标和商务标。

### 风险

如果直接改 `TenderReview.jsx` 的按钮、表格、卡片、布局，技术标解析模块会被一起改动，违反“技术标暂不改动”的范围要求。

### 建议

后续改商务标审核页时优先等待商务/技术拆分完成，再改商务标专属页面。

如果拆分前必须推进，推荐新建商务标专属 View：

```text
BusinessTenderReview.jsx
BusinessTenderReviewView.jsx
```

`/parse/business` 指向商务标新 View，`/parse/technical` 继续保留旧 `TenderReview.jsx`。不建议在 `TenderReview.jsx` 里投入大量兼容分支，因为后续完全隔离时会产生返工。

## P0：按钮层级不统一

### 发现

商务标链路存在多套按钮写法：

```text
bg-primary / bg-[#0067B6] / bg-secondary / bg-tertiary / bg-surface-container-high
rounded-md / rounded-lg
h-7 / h-9 / h-10 / h-[34px] / px-2 / px-3 / px-4 / px-5
text-xs / text-sm / font-medium / font-semibold
stage-action-btn / 普通 button / label 伪按钮
```

集中出现位置：

```text
BusinessGapRecognition.jsx
TenderReview.jsx
MaterialDB.jsx
MaterialWiki.jsx
MaterialSelectModal.jsx
AuditDetailModal.jsx
```

### 影响

- 同层级操作视觉重量不一致。
- 商务标页面中“生成”“复核”“确认”“上传”“忽略”“预览”等动作难以快速区分主次。
- 后续新增按钮会继续复制页面内样式。

### 建议

新增基础组件：

```text
src/components/ui/Button.jsx
src/components/ui/IconButton.jsx
```

并固定：

```text
variant: primary / secondary / quiet / danger / text
size: sm / md / lg
```

第一轮先替换商务标样板页中的主操作、次操作、危险操作和图标按钮。

## P0：商务缺口页组件过大，页面内混合了业务逻辑和 UI 原子

### 发现

`BusinessGapRecognition.jsx` 同时包含：

- 状态映射。
- 任务列表。
- 事实表维护弹窗。
- 素材预览抽屉。
- 素材选择弹窗。
- 候选素材卡片。
- AI 填写结果。
- 已生成/已上传产物。
- 大量按钮和标签样式。

文件内已经定义了多个局部 UI 组件：

```text
StatCard
TaskStatusBadge
AssemblyModeButton
FactMaintenanceModal
BusinessMaterialPreviewDrawer
BusinessMaterialPickerModal
```

### 影响

- 页面维护成本高。
- 相似 UI 不能复用到素材库、审核页和后续 Figma 组件沉淀。
- UI 修改容易误伤业务逻辑。

### 建议

第一轮只做轻拆，不做大重构：

```text
TaskStatusBadge -> 迁移到 StatusBadge variant 映射
AssemblyModeButton -> 保留业务组件，但改用统一 Button/Card token
FactMaintenanceModal / PickerModal / PreviewDrawer -> 先对齐 Dialog/Drawer/Footer/Button
```

后续可再按业务模块拆到：

```text
src/components/business/
```

## P1：弹窗和抽屉样式不统一

- 弹窗标题区、底部按钮区、关闭按钮风格不一致。
- 商务素材选择、上传、切分审核、日志详情等弹窗体验割裂。
- Figma 后续难以沉淀为标准 Dialog / Drawer。

### 建议

新增基础组件：


## P1：表格和列表密集区没有统一 Table / List 规范

### 发现

商务审核页内有多张表：

```text
FieldGroupTable
ScoringCriteriaTable
PresenceTable
CommitmentClueTable
证据明细 table
```

商务缺口页也有事实表 table 和候选素材列表，素材库有目录树和文件列表。

虽然 `index.css` 对 table 做了全局基础样式，但各页面仍手写：

```text
min-w-[640px] / min-w-[980px] / min-w-[1040px] / min-w-[1120px]
px-4 py-2
bg-white / bg-surface-container-low / bg-[#f7f7f7]
rounded-md / rounded-lg / overflow-hidden
```

### 影响

- 表头、行高、空状态、操作列不完全一致。
- 评分表、证据表、素材列表之间视觉像不同模块拼接。

### 建议

新增基础组件或规范：

```text
src/components/ui/Table.jsx
src/components/ui/SectionTable.jsx
src/components/ui/EmptyPanel.jsx
```

第一轮可以先不抽象完整 Table 组件，但要统一表格容器 class、表头样式、空状态和操作列按钮。

## P1：状态标签重复定义

### 发现

已有 `StatusBadge.jsx`，但商务标页面仍定义了多套状态标签：

```text
TaskStatusBadge
cleanStatusMeta
REVIEW_DECISION_BADGE_CLASSES
factStatusLabels + 手写 tone
appendixQualityLabel + 手写 badge
```

### 影响

- 成功、待处理、待复核、错误、同步、清洗中等状态颜色不完全一致。
- 后续沉淀 Figma 时无法直接对应组件变体。

### 建议

扩展 `StatusBadge`：

```text
variant: pending / running / done / warn / error / info
shape: pill / soft-square
size: xs / sm
```

商务标业务状态映射集中放到：

```text
src/utils/statusMeta.js
```

或先放在商务标页面同级 helper 中，避免一次性重构过大。

## P1：PageHeader 标题视觉偏大，和 B 端工具密度不完全匹配

### 发现

`PageHeader.jsx` 当前标题 class：

```text
text-3xl md:text-4xl font-extrabold text-primary
```

虽然全局 CSS 将 `text-3xl/text-4xl` 收口到 18px，但语义上仍容易诱导后续继续写大标题。商务标页面更适合紧凑工作台，不需要营销式大标题。

### 影响

- 新页面容易误用 hero 级标题。
- PageHeader 与密集表格、素材库页面的信息密度不完全一致。

### 建议

将 `PageHeader` 定义为工作台标题组件：

```text
title: 18px / 600
description: 12-14px
actions: 统一 Toolbar/Button
```

第一轮只在商务标样板页中验证，不直接影响技术标页面。

## P2：硬编码颜色仍存在

### 发现

商务相关文件中仍存在硬编码：

## P2：素材库与 Wiki 编辑器按钮偏工具化，但缺少标准 Toolbar

### 发现

`MaterialDB.jsx` 内已有局部 `IconButton`，但没有进入共享组件；`MaterialWiki.jsx` 中富文本工具按钮直接写：

```text
B / I / H2 / list
p-2 hover:bg-surface-container-high rounded
```

### 影响

- 工具按钮尺寸、hover、禁用态无法和其他图标按钮统一。
- 后续 Figma 组件库中很难定义工具栏样式。

### 建议

将 `MaterialDB.jsx` 的 `IconButton` 思路上移为：

```text
src/components/ui/IconButton.jsx
src/components/ui/Toolbar.jsx
```

素材库目录工具栏、Wiki 编辑工具栏、弹窗关闭按钮统一使用。

