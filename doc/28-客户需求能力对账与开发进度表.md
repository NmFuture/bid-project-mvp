# 项目能力、客户需求与开发进度安排

> 日期：2026-05-26
> 代码基线：`wlb` / `origin/wlb`，已提交 `0123ced feat: align technical bid workflow with business UI`
> 用途：给决策者快速看清“现在有什么、客户要什么、下一步怎么排”

## 一、项目已有能力或者进展

项目已经形成一条投标平台主流程：

`S0 解析 -> S1 模板与目录 -> S2 审核目录 -> S3 缺口处理 -> S4 生成标书 -> S5 共创 -> S6 导出`

当前主要进展如下：

| 模块 | 当前进展 |
| --- | --- |
| 平台底座 | 已有前端、FastAPI、OpenCode、OnlyOffice、Postgres、Redis、MinIO 的 Docker Compose 架构 |
| 项目管理 | 已支持技术标/商务标项目区分，项目创建、资料上传、流程推进已有基础 |
| S0 解析 | 已支持招标文件解析，技术标和商务标都有解析方向；PDF/图片解析能力已接入 |
| S1/S2 目录 | 技术标目录链路已有；商务标目录 Skill 已完成第一版，并保留原始编号 |
| S3 缺口处理 | 技术标缺口识别已作为当前可验收点；商务标缺口处理也已有第一版 |
| S4 生成标书 | 技术标生成链路已有；商务标 S4 也已完成第一版，能按 `bidType` 分流 |
| S5 共创 | OnlyOffice 在线编辑链路已存在，必要时可走文本兜底 |
| S6 导出 | `/editor` 内已有 Word/PDF 下载入口 |
| 素材库/Wiki | 已有素材库、清洗预览、技术标/商务标 Wiki 构建能力 |
| 登录与审计 | 登录、设置、审计日志已有基础 |

当前还不够稳的部分：

- 技术标附表和待填 Word 的自动填充还没有完成最终验收。
- S4/S6 还缺评分点、证据链、段落覆盖和完整格式检查的生产验收闭环。
- 商务标虽然已有第一版链路，但还需要用真实样本跑端到端验收。
- 权限、部署、运维能力还有加固空间。
- 2026-05-26 已用当前代码重建 Docker 镜像并强制替换容器；后续业务验收仍需用真实技术标/商务标样本端到端跑通。

## 二、客户需求

客户现在的需求可以归成三类。

### 1. 标书主流程需求

| 客户需求 | 当前判断 |
| --- | --- |
| 技术标、商务标招标文件解析 | 已有基础，需要按客户字段口径固化 |
| 自动生成目录并人工审核 | 已有基础，商务标目录已完成第一版 |
| 技术标缺口识别与材料匹配 | 已有第一版，后续重点是填表、填 Word、复核 |
| 商务标资格、否决、评分、承诺、附件处理 | 已有第一版方向，需要真实样本验收 |
| 自动生成技术标/商务标 Word | 已有第一版，仍需提高可交付质量 |
| OnlyOffice 在线共创 | 已有基础 |
| 最终文档下载 | Word/PDF 下载入口已接入，完整格式检查和证据一致性待验收 |

### 2. 客户新增需求

| 新增需求 | 说明 |
| --- | --- |
| 解析内容字段维护表 | 客户希望字段可维护，不是写死在代码或 Skill 里 |
| 业绩表共享 | 技术标、商务标都可能要用同一套业绩数据和证明材料 |
| 三级目录 + 文件标签二维检索 | 素材库既要按目录找，也要按标签找 |
| 混排机型标书撰写 | 一个项目可能涉及多个机型，不能只按单一机型生成 |
| 部署服务器监控与一键启停 | 希望管理员能看到服务状态，并具备运维控制能力 |

### 3. 客户仍需补充的资料

| 需要客户补充 | 用途 |
| --- | --- |
| 商务标解析字段 | 固化商务标解析结果和页面展示 |
| 商务标业绩表 | 做业绩共享、业绩匹配、附件填充 |
| 技术标解析字段和事实维护字段 | 做技术标事实表、附表填充、正文一致性 |
| 混排机型素材和样例 | 设计多机型事实表和生成规则 |
| 部署服务器环境和权限边界 | 决定监控、一键启停、模型调用、数据边界怎么做 |

## 三、开发进度安排

建议不要同时铺开所有需求，先把主流程做成可验收版本，再做客户新增能力。

| 阶段 | 时间 | 目标 | 重点工作 |
| --- | --- | --- | --- |
| 第 0 阶段 | 0.5-1 天 | 冻结范围、补齐资料 | 确认本期交付范围；向客户要字段表、业绩表、混排样例、部署信息 |
| 第 1 阶段 | 约 1 周 | 技术标主链路验收 | 建立评测集；完成技术标附表填充、Word 占位填充、黄色高亮、证据链和 85% 评测 |
| 第 2 阶段 | 约 1 周 | 技术标导出闭环 + 商务标端到端 | 补 S4/S6 评分点覆盖、证据链一致性和格式检查；用真实商务标样本跑解析、目录、缺口、生成、共创、下载 |
| 第 3 阶段 | 约 1 周 | 客户新增需求一期 | 做解析字段维护表、业绩共享台账、三级目录 + 标签检索、Wiki/素材索引统一 |
| 第 4 阶段 | 约 1 周 | 混排机型和部署运维 | 支持多机型事实表、材料筛选、冲突检查；做服务器监控页和一键启停方案 |
| 第 5 阶段 | 3-5 天 | 交付验收 | 部署当前仓库；整理操作手册、管理员手册、验收报告、已知边界 |

接下来最应该做三件事：

1. 先向客户要齐字段表、业绩表、混排样例、部署环境信息。
2. 先把技术标填表/填 Word/评测体系做成可验收。
3. 同时用一个真实商务标样本跑完整端到端，确认商务标第一版到底差在哪里。
