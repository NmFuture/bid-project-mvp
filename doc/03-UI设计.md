## 一、设计原则

1. **专业、克制、不花哨** — 国企内部 B 端工具，避免消费级互联网的强色彩
2. **流程性强于功能性** — 首屏即呈现"当前项目处在第几阶段"，而非功能菜单堆叠
3. **AI 辅助感明确但不喧宾夺主** — AI 产出要有明确视觉标识，但不应盖过用户内容
4. **可追溯即可视化** — 证据链、覆盖评分项、审计痕迹尽量图形化
5. **人工审核节点强阻塞** — 目录审核、备料审核、覆盖红项必须"强制界面锁定直到通过"
6. **响应式适度** — 桌面优先（1440×900），笔记本可用（1280×800），无需手机优化

## 二、视觉规范

### 2.1 色彩

| 用途 | 色值 | 场景 |
|---|---|---|
| 主色 | `#1E40AF`（沉稳蓝） | 主按钮、链接、当前流程高亮 |
| 辅助色 | `#0F766E`（墨绿） | "通过 / 就绪"状态 |
| 强调色 | `#B91C1C`（红） | "未覆盖 / 驳回 / 错误" |
| 告警色 | `#D97706`（琥珀） | "弱覆盖 / 待审核" |
| AI 标识色 | `#7C3AED`（紫） | AI 生成内容、AI 建议、AI 对话 |
| 文字主色 | `#0F172A` | 正文 |
| 文字次色 | `#64748B` | 说明、辅助信息 |
| 背景 | `#F8FAFC` | 页面背景 |
| 分割线 | `#E2E8F0` | |

**紫色作为 AI 标识色**的理由：和"正常"内容（蓝/黑）区分明显，用户可一眼识别"这是 AI 动的"，符合可追溯原则。

### 2.2 字体

- **系统字体栈**：`"PingFang SC", "Microsoft YaHei", -apple-system, sans-serif`
- **等宽字体**（代码、编号、数据）：`"SF Mono", "Consolas", monospace`
- 基础字号 14px，行高 1.6

### 2.3 布局基线

- 主内容区最大宽度 1440px，居中
- 卡片圆角 `8px`，阴影 `0 1px 3px rgba(0,0,0,0.06)`
- 间距基础单位 4px（使用 4/8/12/16/24/32/48）
- 侧边栏宽度：主导航 240px，目录树 320px，右侧面板 360px

### 2.4 组件库基础

- **shadcn/ui** 作为基础组件
- 自定义组件遵循 shadcn 命名与结构
- 图标：Lucide（与 shadcn 配套）

- **右：段落信息面板**（上下文相关，选中段落时显示）

   - 右侧面板点"AI 改写"
   - 底部对话面板弹出，用户输入改写要求（或选预设："更正式"/"更简洁"/"加强表述"）

4. **一键刷格式**：
   - 顶部"格式"按钮下拉：
     - 重新应用样式模板
     - 清理多余空格/符号
     - 更新目录页码
     - 刷新多级编号

**AI 对话面板的特殊能力**：
- 引用段落：用户可以选中文档中的段落 → 点 📎 → 段落作为上下文发给 AI
- agent 思考可见：opencode agent 调 tool 的过程以折叠形式显示（可选展开查看）
- 结果应用需用户确认（diff 对比）
