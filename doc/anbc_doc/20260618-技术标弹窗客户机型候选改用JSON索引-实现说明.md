# 技术标项目弹窗：客户 / 风机机型候选改用三级目录 JSON 索引 — 实现说明

> 生成于 2026-06-18。
> 配套阅读：`20260618-技术标三级目录JSON索引-下游使用Handoff.md`（候选数据来源的 JSON 索引结构）。
> 本文记录已落地的前端改动，供后续编写正式 handoff / 维护时参考。

---

## 1. 需求背景

页面 `http://localhost/parse/technical` → 点击「参与该项目并进入工作区」会弹出
**新建/完善技术标项目** 弹窗（组件 `TechnicalProjectWizardModal`）。该弹窗里两个下拉的候选项需要改为
**实时从技术标三级目录 JSON 索引读取**，并各自在末尾固定追加一个「其他」手动输入入口：

| 下拉 | 旧候选来源 | 新候选来源 |
|------|-----------|-----------|
| **客户** | 静态常量 `STATIC_CUSTOMER_OPTIONS` | JSON 索引中 `tier === 'customer'`（客户定制）下各 3 级目录名 + 「其他」 |
| **风机机型明细 → 风机机型** | 静态常量 `STATIC_TURBINE_MODEL_OPTIONS` | JSON 索引中 `tier === 'standard'`（标准文件）下各 3 级目录名（即机型号）+ 「其他」 |

要求：**每次都从对应位置的 JSON 实时读取**（接口保证最新，空则后端即时重建）。

---

## 2. 数据来源

复用后端已暴露的现成接口（无需改后端）：

```
GET /api/technical/materials/index
```

返回的 JSON 结构见配套 handoff 文档。本次只用到两段：

- `tiers[]` 中 `tier === 'customer'` 的 `folders[]` → 每个 `folder.customerName`（回退 `folder.name`）= 客户候选
- `tiers[]` 中 `tier === 'standard'` 的 `folders[]` → 每个 `folder.name` = 风机机型候选

> 判档**以 `tier` 字段为准**（后端已归一），不要靠 2 级目录中文名硬判。

实测返回示例（节选）：

```
customer | 客户定制 | folders: 华能 / 国电投
standard | 标准文件 | folders: EW5.0-220 / EW5.6-202 / EW5.0-202 / EW6.25-220 ...
```

## 4. 详细实现

### 4.1 API 层 — `src/api/index.js`


### 4.2 派生函数 — `src/workspaces/shared/projectInfoOptions.js`

文件末尾新增（约 129–152 行）。设计成**纯函数**，便于复用与单测：

```js
// 「其他」兜底选项：客户与风机机型下拉都需要在派生候选末尾追加一个手动输入入口。
export const OTHER_OPTION_LABEL = '其他'

const appendOtherOption = (items = []) => {
  const list = normalizeStringOptions(items).filter((item) => item !== OTHER_OPTION_LABEL)
  return [...list, OTHER_OPTION_LABEL]
}

// 客户：tier==='customer'（客户定制）→ customerName（回退 name）+「其他」
export const deriveCustomerOptionsFromIndex = (indexPayload = {}) => {
  const tiers = Array.isArray(indexPayload?.tiers) ? indexPayload.tiers : []
  const customerTier = tiers.find((tier) => tier?.tier === 'customer')
  const names = (customerTier?.folders || []).map((folder) => folder?.customerName || folder?.name)
  return appendOtherOption(names)
}

// 风机机型：tier==='standard'（标准文件）→ 目录名（机型号）+「其他」
export const deriveTurbineModelOptionsFromIndex = (indexPayload = {}) => {
  const tiers = Array.isArray(indexPayload?.tiers) ? indexPayload.tiers : []
  const standardTier = tiers.find((tier) => tier?.tier === 'standard')
  const names = (standardTier?.folders || []).map((folder) => folder?.name)
  return appendOtherOption(names)
}
```

- `appendOtherOption` 复用文件内已有的 `normalizeStringOptions`（去空、去重），并保证「其他」**恒为最后一项且只出现一次**。
- 入参缺失 / 结构异常时返回 `['其他']`，不会抛错。

> 静态常量 `STATIC_CUSTOMER_OPTIONS` / `STATIC_TURBINE_MODEL_OPTIONS` **保留**，作为接口失败时的兜底，不再作为主候选。

### 4.3 弹窗组件 — `TechnicalProjectWizardModal.jsx`

#### (a) import

```js
import {
  STATIC_FOUNDATION_TYPE_OPTIONS,
  STATIC_PROJECT_INFO_OPTIONS,
  OTHER_OPTION_LABEL,
  deriveCustomerOptionsFromIndex,
  deriveTurbineModelOptionsFromIndex,
  loadProjectInfoOptions,
} from '../../shared/projectInfoOptions'
```

#### (b) 新增 state

```js
// 派生候选
const [indexCustomerOptions, setIndexCustomerOptions] = useState([])
const [indexTurbineModelOptions, setIndexTurbineModelOptions] = useState([])
// 「其他」手动输入态：客户用布尔；机型按行 id 记录
const [customerIsOther, setCustomerIsOther] = useState(false)
const [otherTurbineRowIds, setOtherTurbineRowIds] = useState(() => new Set())
```

#### (c) 候选计算（useMemo）

优先用 index 派生候选，接口为空时回退 `projectInfoOptions`（静态）。合并 form 现值时
**排除「其他」态字段**，避免把空值混进候选，并始终把「其他」放最后：

```js
const customerOptions = useMemo(() => {
  const base = indexCustomerOptions.length ? indexCustomerOptions : projectInfoOptions.customers
  const extra = customerIsOther ? [] : [form.customerName]
  const merged = mergeOptionValues(base.filter((item) => item !== OTHER_OPTION_LABEL), extra)
  return [...merged, OTHER_OPTION_LABEL]
}, [indexCustomerOptions, projectInfoOptions.customers, customerIsOther, form.customerName])

const turbineModelOptions = useMemo(() => {
  const base = indexTurbineModelOptions.length ? indexTurbineModelOptions : projectInfoOptions.turbineModels
  const formModels = form.turbineModels
    .filter((row) => !otherTurbineRowIds.has(row.id))
    .map((row) => row.model)
  const merged = mergeOptionValues(base.filter((item) => item !== OTHER_OPTION_LABEL), formModels)
  return [...merged, OTHER_OPTION_LABEL]
}, [indexTurbineModelOptions, projectInfoOptions.turbineModels, form.turbineModels, otherTurbineRowIds])
```

#### (d) 加载 index 的 effect（每次挂载拉取最新）

```js
useEffect(() => {
  let mounted = true
  const loadIndexOptions = async () => {
    if (!materialsApi?.index) return
    try {
      const payload = await materialsApi.index()
      if (!mounted) return
      const customers = deriveCustomerOptionsFromIndex(payload)
      const turbines = deriveTurbineModelOptionsFromIndex(payload)
      setIndexCustomerOptions(customers)
      setIndexTurbineModelOptions(turbines)
      // 现值非空且不在候选内 → 自动进入「其他」手动态（编辑/草稿恢复场景）
      const customerSet = new Set(customers.filter((i) => i !== OTHER_OPTION_LABEL))
      setCustomerIsOther((prev) => {
        const name = form.customerName.trim()
        return prev || Boolean(name && !customerSet.has(name))
      })
      const turbineSet = new Set(turbines.filter((i) => i !== OTHER_OPTION_LABEL))
      setOtherTurbineRowIds((prev) => {
        const next = new Set(prev)
        form.turbineModels.forEach((row) => {
          const model = String(row.model || '').trim()
          if (model && !turbineSet.has(model)) next.add(row.id)
        })
        return next
      })
    } catch {
      if (!mounted) return
      setIndexCustomerOptions([])
      setIndexTurbineModelOptions([])
    }
  }
  loadIndexOptions()
  return () => { mounted = false }
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [materialsApi])
```

#### (e) 移除静态默认客户注入

原 `loadProjectInfoOptions` effect 会把 `form.customerName` 默认填成静态列表首项（如「华润」）。
因候选已改为 index 派生，默认值留空让用户主动选，避免误填一个不在 index 中的客户：

```js
useEffect(() => {
  let mounted = true
  const loadOptions = async () => {
    const options = await loadProjectInfoOptions(technicalProjectInfoOptionsAPI)
    if (!mounted) return
    setProjectInfoOptions(options)   // 仅作静态兜底，不再自动注入默认客户
  }
  loadOptions()
  return () => { mounted = false }
}, [])
```

#### (f)「其他」交互（客户 & 机型同一套模式）

- 下拉选中值 === `OTHER_OPTION_LABEL` 时：
  - 客户：`setCustomerIsOther(true)` 并清空 `customerName`，UI 切换为文本输入框 + 「选候选」按钮。
  - 机型：`otherTurbineRowIds` 加入该行 `row.id` 并清空 `row.model`，该行 UI 切换为文本输入框 + 「候选」按钮。
- 手动输入框的值**直接写回原字段**（`form.customerName` / `row.model`），因此既有必填校验、`archivePathPreview` 归档路径预览、`handleCreate` 提交逻辑**无需改动即生效**。
- 点「选候选 / 候选」按钮 → 退出「其他」态、清空该字段，回到下拉。
- `removeTurbineRow` 删除行时同步从 `otherTurbineRowIds` 清理该行 id（防止 id 残留）。

## 5. 边界与已知行为

- **接口失败兜底**：`/materials/index` 异常 → 派生候选为空 → 自动回退静态常量候选，弹窗仍可用。
- **编辑 / 草稿恢复**：已保存的客户/机型若不在最新候选内，会自动进入「其他」态显示原值，不丢数据。
- **「其他」去重**：派生与合并阶段都会过滤掉值为「其他」的真实候选，保证它只在末尾出现一次。
- **客户默认值**：现在初始为空（「选择客户」），由用户主动选择或走「其他」。
- 校验项（`missingRequiredItems`）未改：客户读 `form.customerName.trim()`、机型读 `row.model`，「其他」态手动输入同样命中。
