# UI轻量设计规范

> 范围：第一轮服务于商务标链路 UI 统一。技术标链路暂不改动，后续可复用本规范中稳定下来的组件和 Figma UI Kit。

## 一、设计目标

商务标链路是内部 B 端工作台，不做营销化、装饰化或大幅重构。第一轮目标是：

```text
统一控件层级
统一页面密度
统一商务标任务处理体验
降低后续页面复制样式的成本
为 Figma UI Kit 提供已落地的组件标准
```

本规范优先服务以下页面：

```text
BusinessGapRecognition.jsx
MaterialDB.jsx
MaterialWiki.jsx
MaterialSelectModal.jsx
AuditDetailModal.jsx
```

`BusinessTenderReview.jsx` 当前仍复用技术标的 `TenderReview.jsx`，而后续商务标和技术标会完全隔离。第一轮不在共用审核页中做大规模 UI 改造；等拆分完成后，再把商务审核页纳入本规范。

## 二、视觉原则

### 1. 专业克制

界面应接近企业内部生产工具。避免大面积渐变、强装饰背景、过大的标题、过多强调色。

### 2. 信息密度优先

商务标页面存在大量任务、素材、证据、附件、审核动作。应保持紧凑但不拥挤：

```text
页面区块间距：16 / 20 / 24
卡片内边距：16
表格单元格：8 / 12 / 16
按钮默认高度：36
```

### 3. 操作层级明确

每个业务区域最多保留一个主要操作。其他操作使用次级、弱化或图标按钮。

### 4. 代码先行，Figma沉淀

第一轮以代码中已验证的组件为准。样板页通过后，将 token、组件状态、页面模式同步到 Figma。

## 三、设计 Token

### 1. 颜色

沿用 `src/index.css` 当前 token，不重新定义品牌色。

| 用途 | Token | 色值 | 使用场景 |
|---|---|---|---|
| 主色 | `primary` | `#0068b7` | 主按钮、当前选中、关键链接 |
| 主色浅底 | `primary-fixed` | `#e8f4ff` | 当前项浅背景、信息提示 |
| 成功色 | `secondary` | `#14a83b` | 已完成、已确认、通过 |
| 成功浅底 | `secondary-container` | `#e6f8ec` | 成功状态标签 |
| 信息/AI | `tertiary` / `ai-accent` | `#18b7d9` | AI、处理中、辅助强调 |
| 错误色 | `error` | `#c54040` | 错误、删除、驳回、风险 |
| 页面背景 | `surface` | `#ffffff` | 页面底色 |
| 区块浅底 | `surface-container-low` | `#f1f5f9` | 区块头、工具栏、淡背景 |
| 控件浅底 | `surface-container-high` | `#e1e8f0` | 次级按钮、标签底色 |
| 输入底色 | `surface-container-highest` | `#d5dee8` | 搜索框、筛选控件 |
| 主文字 | `on-surface` | `#2a4258` | 标题、正文 |
| 次文字 | `on-surface-variant` | `#60758a` | 说明、元信息 |
| 弱文字/边框 | `outline` | `#95a7ba` | 弱信息、图标 |
| 浅边框 | `outline-variant` | `#c4d0dc` | 卡片、表格、分割线 |

### 2. 禁止新增的颜色写法

新代码中避免继续使用：

```text
bg-[#0067B6]
hover:bg-[#0b74c8]
bg-[#e8eef2]
bg-[#f7f7f7]
bg-[#b6babd]
text-white
```

应替换为：

```text
bg-primary
hover:bg-primary-container
bg-surface-container-low
bg-surface-container-high
text-on-primary
```

少数历史技术标页面暂不强制替换。

## 四、字号与文字层级

### 1. 字号

| 层级 | 字号 | 字重 | 场景 |
|---|---:|---:|---|
| 页面标题 | 18px | 600 | PageHeader 标题 |
| 区块标题 | 16px | 600 | 卡片标题、弹窗标题 |
| 小节标题 | 14px | 600 | 表格标题、任务卡标题 |
| 正文 | 14px | 400/500 | 页面主体、表格内容 |
| 辅助说明 | 12px | 400 | 描述、路径、时间、来源 |
| 标签文字 | 12px | 500/600 | 状态、筛选、徽标 |

### 2. 标题规则

商务标页面不使用 hero 式大标题。页面标题应服务工作台识别，而不是营销表达。

推荐：

```text
页面标题：18px / 600
页面说明：12-14px / muted
区块标题：14-16px / 600
```

## 五、间距、圆角、阴影

### 1. 间距

基于 4px 栅格：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32
```

推荐：

| 场景 | 间距 |
|---|---:|
| 页面主区块之间 | 20 / 24 |
| 卡片内部 | 16 |
| 卡片标题和内容 | 12 |
| 表单项之间 | 12 |
| 按钮组之间 | 8 |
| 表格单元格水平 | 12 / 16 |
| 表格单元格垂直 | 8 |

### 2. 圆角

| 组件 | 圆角 |
|---|---:|
| 按钮 | 6px |
| 输入框 | 6px |
| 工具按钮 | 6px |
| 标签 | pill 或 4px |
| 卡片 | 8px |
| 弹窗 | 8px |
| 抽屉 | 0 或 8px，按位置 |
| 表格容器 | 6px / 8px |

### 3. 阴影

商务标页面以边框区分层级，阴影只用于弹窗、抽屉和浮层。

推荐：

```text
卡片：无阴影或 0 1px 2px rgba(17,34,51,0.06)
弹窗：0 12px 28px -16px rgba(0,62,111,0.2)
下拉浮层：0 8px 24px -8px rgba(0,0,0,0.15)
```

## 六、基础组件规范

## 1. Button

### 变体

| Variant | 用途 | 样式语义 |
|---|---|---|
| `primary` | 页面主操作 | 蓝底白字 |
| `secondary` | 正向但非主操作 | 绿浅底或绿底，谨慎使用 |
| `quiet` | 次级操作 | 浅灰底深字 |
| `ghost` | 弱操作 | 透明底，hover 浅灰 |
| `danger` | 删除、驳回、清空 | 红浅底红字 |
| `text` | 链接式操作 | 无底色，仅文字 |

### 尺寸

| Size | 高度 | 字号 | 水平内边距 |
|---|---:|---:|---:|
| `xs` | 28px | 12px | 8 / 10 |
| `sm` | 32px | 12px | 12 |
| `md` | 36px | 14px | 16 |
| `lg` | 40px | 14px | 18 / 20 |

默认使用：

```text
size="md"
variant="primary"
```

### 业务映射

| 动作 | 推荐变体 |
|---|---|
| 生成/更新商务缺口计划 | `primary` |
| 生成 AI 填写稿 | `primary` |
| 确认选择/确认产物 | `primary` |
| 上传补料 | `quiet` 或 `secondary` |
| 预览/查看 | `quiet` |
| 刷新/同步 | `quiet` |
| 标记忽略 | `ghost` |
| 删除/移除 | `danger` |
| 取消/关闭 | `quiet` |

### 规则

- 每个区块最多一个 `primary`。
- 同一行不要同时出现多个高饱和按钮。
- 图标按钮优先用 `IconButton`，不要用文字按钮承载纯工具行为。
- 禁用态统一使用 `disabled:opacity-50 disabled:cursor-not-allowed`。

## 2. IconButton

### 用途

用于关闭、刷新、删除、重命名、展开、缩放、上传等工具型操作。

### 尺寸

```text
xs: 24px
sm: 28px
md: 32px
```

### 规则

- 图标使用 `material-symbols-outlined`。
- 有业务风险的图标按钮使用 `danger`。
- 非熟悉图标应提供 `aria-label` 和 title。
- 关闭按钮统一为 `IconButton variant="ghost" icon="close"`。

## 3. Badge / StatusBadge

### 状态变体

| Variant | 用途 |
|---|---|
| `pending` | 待处理、未生成、待同步 |
| `running` | 处理中、清洗中、生成中 |
| `done` | 已确认、已完成、已同步 |
| `warn` | 待复核、疑似不完整、需补充 |
| `error` | 失败、冲突、风险、删除 |
| `info` | AI、说明、引用、模板 |

### 形状

```text
pill：状态标签
square：表格/卡片内的小标签
```

第一轮商务标默认：

```text
状态：pill
类型/来源：square
```

## 4. Input / Select / Textarea

### 尺寸

```text
sm: 32px
md: 36px
lg: 40px
```

默认：

```text
height: 36px
border: outline-variant
radius: 6px
font-size: 14px
```

### 搜索框

搜索框使用左侧 search icon，右侧可选 clear icon。

推荐形态：

```text
SearchInput size="md" clearable
```

### 表格内输入

事实表维护等表格内输入可以使用 `size="sm"`，但高度不低于 32px。

## 5. Card

### 变体

| Variant | 用途 |
|---|---|
| `default` | 普通内容卡片 |
| `section` | 带标题区的大区块 |
| `task` | 商务缺口任务卡 |
| `selected` | 当前选中目录/任务 |
| `muted` | 信息摘要、解析状态 |

### 规则

- 卡片不嵌套卡片，除非是任务内部的候选素材/产物条目。
- 卡片标题区固定 14-16px。
- 卡片边框使用 `outline-variant` 或 `surface-container-high`。
- 任务卡选中态只使用主色边框和浅蓝背景，不使用强阴影。

## 6. Dialog

### 结构

```text
Dialog
  DialogHeader
  DialogBody
  DialogFooter
```

### 尺寸

| Size | 最大宽度 | 场景 |
|---|---:|---|
| `sm` | 480px | 确认、冲突处理 |
| `md` | 640px | 简单表单 |
| `lg` | 760px | 上传素材 |
| `xl` | 960px | 素材选择 |
| `full` | calc viewport | 复杂审核 |

### 规则

- Header 固定：标题左，关闭按钮右。
- Footer 固定：取消在左或右侧次级，主操作在最右。
- 内容超高时 Body 内部滚动，不让整个页面滚动混乱。
- 弹窗底部背景统一 `surface-container-low`。

## 7. Drawer

### 用途

用于素材预览、候选文件预览、详情查看。

### 规则

- 右侧抽屉宽度默认 `min(960px, 100vw)`。
- Header 和 Footer 与 Dialog 一致。
- 预览区保留稳定高度，避免文件加载后布局跳动。

## 8. Table

### 基础表格

```text
表头高度：40px
行高：40px
表头背景：surface-container-low
行 hover：surface-container-low
边框：surface-container-high
字号：14px
```

### 密集表格

用于证据明细、字段表、事实表：

```text
字号：12 / 14
单元格 py: 8
横向滚动容器必须明确 min-width
```

### 空状态

表格空状态不要只显示一行文本，推荐：

```text
EmptyPanel icon + title + description
```

如果空间很小，可使用一行 muted text。

## 9. Toolbar

### 用途

页面操作区、筛选区、素材目录工具栏、Wiki 编辑工具栏。

### 规则

- 左侧放上下文信息或筛选。
- 右侧放操作按钮。
- 工具按钮之间 gap 为 4 或 8。
- 主操作始终靠右或放在区块标题右侧。

## 七、商务标业务组件规范

## 1. 商务缺口任务卡

### 结构

```text
标题 + 状态
元信息
素材处理方式
候选素材
AI填写结果
已生成/已上传产物
操作区
```

### 规则

- 任务卡标题区域最多一个状态标签。
- 任务主操作优先放在卡片右上或对应区块标题右侧。
- 候选素材卡片内部操作使用小按钮，不抢主操作权重。
- 风险/错误信息使用 `danger` 浅底，不使用高饱和红底。

## 2. 商务审核区块

适用于商务评分标准、承诺函、附件模板审核。

### 规则

- 区块标题左侧，审核按钮右侧。
- 审核通过按钮使用 `primary`。
- 切换预览、上一个/下一个使用 `quiet`。
- 条目列表选中态使用主色边框和浅蓝底。

## 3. 商务素材库

### 规则

- 顶部只保留一个主上传/同步操作。
- 目录树工具按钮统一为 IconButton。
- 文件行 hover、选中、状态标签统一。
- 上传弹窗和切分审核弹窗使用同一 Dialog 结构。

## 4. 商务 Wiki

### 规则

- 编辑工具栏使用 IconButton 或紧凑 Button。
- `B / I / H2` 可以保留文字工具按钮，但尺寸和 hover 必须统一。
- AI 摘要区使用 `info` 或 `ai` 浅底，不使用强色块。

## 九、第一轮代码改造边界

### 可以改

```text
商务标页面内的按钮、标签、弹窗、卡片、表格样式
商务标专用局部组件
新增 components/ui 基础组件
```

### 谨慎改

```text
PageHeader
DataCard

```

这些文件可能影响技术标。若必须改，应保证默认行为不变。

`TenderReview.jsx` 当前是技术/商务共用页，第一轮暂不深改。若拆分前必须推进商务审核 UI，应新建商务标专属 View，而不是在共用文件中堆复杂分支。

### 暂不改

```text
技术标专属页面
技术标路由
业务接口逻辑
数据结构
复杂交互流程
```

## 十、验收标准

### 样板页验收

1. 同一层级按钮视觉一致。
2. 页面主操作不超过一个。
3. 弹窗 Header / Body / Footer 一致。
4. 状态标签颜色和形状一致。
5. 商务缺口任务卡可快速区分状态、素材、AI产物和操作。
6. 商务审核页的审核动作清晰，不误触技术标样式。
7. 素材库上传、选择、预览弹窗风格一致。

### 工程验收

```text
npm run build
npm run lint
```

如 lint 存在历史问题，应记录，不把无关历史问题混入本次 UI 改造。

### 视觉验收

至少截图：

```text
/parse/business
/workspace/business/materials/structured
/workspace/business/materials/wiki
/workspace/business/projects/:id/gaps
```

同时抽查：

```text
/parse/technical
```

确认技术标未被明显改动。

## 十一、下一步执行建议

建议下一步直接进入代码改造，但先控制在基础组件和商务缺口样板页：

```text
1. 新增 components/ui/Button.jsx、IconButton.jsx、Badge.jsx、Dialog.jsx、Toolbar.jsx。
2. 改造 BusinessGapRecognition.jsx 的顶部操作区、任务卡操作区、素材选择弹窗。
3. 本地启动前端，截图给你审核。
4. 样板页通过后再处理 MaterialDB。
5. BusinessTenderReview 等商务/技术拆分后再纳入统一；拆分前必须推进时，新建商务标专属 View。
```

这样能最快看到统一效果，也能最大限度避免技术标被误伤。
