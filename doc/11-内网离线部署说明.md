# 内网离线部署说明

本文档对应 `code/` 目录下新增的离线打包与部署能力，目标是让项目在无法访问公网的内网环境中完成部署。

## 目标状态

- 内网部署时不从外部镜像仓库拉取镜像。
- 内网部署时不在容器启动阶段执行 `npm install`、`pip install` 等外网安装动作。
- LLM 由内网提供的 OpenAI-compatible 网关承接。
- 现场部署只需要 `docker load` + `docker compose up --no-build`。

## 本次改造包含的内容

`code/docker-compose.yml`

- 为 `web`、`fastapi`、`opencode` 增加了固定镜像名，便于预构建和导出。
- `opencode` 改为独立 Docker 镜像，不再在容器启动时在线安装 `opencode-ai`。

`code/docker-compose.airgap.yml`

- 离线覆盖文件，强制所有服务 `pull_policy: never`。
- 配合 `docker compose -f docker-compose.yml -f docker-compose.airgap.yml up -d --no-build` 使用。

`code/sewpg-bid-backend/opencode/Dockerfile`

- 在镜像构建阶段安装 `opencode-ai` 和运行所需 Python 依赖。
- 当前 `S4 生成标书` 使用的 `bid-tech-assembler` 依赖 `python-docx`、`lxml`、`docxcompose`、`PyYAML`，需要在联网构建阶段一并打进镜像。

`code/sewpg-bid-backend/opencode/docker-entrypoint.sh`

- 如果配置了 `INTERNAL_LLM_BASE_URL`，启动时自动生成面向内网网关的 opencode 配置。
- 未配置时继续兼容原有 `opencode.json`。

`code/.env.airgap.example`

- 提供一份内网部署专用环境模板。

`code/scripts/build-airgap-bundle.ps1`
`code/scripts/build-airgap-bundle.sh`

- 在可联网机器上预构建镜像并导出离线镜像包。

`code/scripts/load-airgap-images.sh`
`code/scripts/up-airgap.sh`

- 在内网机器上导入镜像并启动服务。

## 一、在可联网机器上制作离线包

进入目录：

```bash
cd code
```

Windows:

```powershell
./scripts/build-airgap-bundle.ps1
```

Linux/macOS:

```bash
./scripts/build-airgap-bundle.sh
```

执行完成后会在 `code/offline-dist/` 下生成：

- `images/sewpg-bid-images-<tag>.tar`
- `docker-compose.yml`
- `docker-compose.airgap.yml`
- `.env.airgap.example`
- `load-airgap-images.sh`
- `up-airgap.sh`
- `bundle-manifest.json`

说明：

- 该步骤允许联网，因为它的职责就是提前把外部依赖准备好。
- `OnlyOffice` 官方镜像会被拉取后重新打成本地标签 `sewpg-bid/onlyoffice:9.3.1.2`。
- `web`、`fastapi`、`opencode` 三个业务镜像会被本地构建并导出。
- `S4 生成标书` 所需的本地 skill、Python 脚本和依赖随业务镜像一起进入离线包；内网启动阶段不再安装这些依赖。
- 素材 Wiki 生成使用的 `wikibuild` 命令也随 `opencode` 镜像进入离线包；它会读取共享 manifest，并把完整 `wiki_blueprint.json` 写回 `/data/parsed/_wiki_build`。

## 二、把离线包带入内网

推荐带入以下内容：

- 整个仓库代码
- `code/offline-dist/` 目录

如果只想带最小部署包，至少需要：

- `offline-dist/docker-compose.yml`
- `offline-dist/docker-compose.airgap.yml`
- `offline-dist/.env.airgap.example`
- `offline-dist/images/sewpg-bid-images-<tag>.tar`
- `offline-dist/load-airgap-images.sh`
- `offline-dist/up-airgap.sh`

## 三、在内网机器上部署

1. 导入镜像

```bash
./load-airgap-images.sh ./images/sewpg-bid-images-<tag>.tar
```

2. 准备环境文件

```bash
cp .env.airgap.example .env
```

3. 按内网实际情况修改 `.env`

重点配置：

- `OPENCODE_PROVIDER_ID=internal-openai`
- `OPENCODE_MODEL_ID=<内网模型 ID>`
- `INTERNAL_LLM_BASE_URL=http://<内网网关>/v1`
- `INTERNAL_LLM_API_KEY=<如需鉴权则填写>`
- `ONLYOFFICE_BACKEND_BASE_URL=<浏览器和 onlyoffice 容器都能访问到的 FastAPI 对外地址>`

4. 启动

```bash
./up-airgap.sh ./.env
```

等价命令：

```bash
docker compose \
  --env-file ./.env \
  -f docker-compose.yml \
  -f docker-compose.airgap.yml \
  up -d --no-build
```

## 四、LLM 内网接入约定

当前离线方案默认支持内网 OpenAI-compatible 网关。

需要提供：

- 一个兼容 OpenAI Chat Completions / Responses 风格的内网地址
- 一个可用模型 ID
- 如有需要，一个 API Key

可选扩展：

- `INTERNAL_LLM_HEADERS_JSON`
  - 用于补充额外请求头，例如租户头或内部鉴权头
  - 示例：`{"X-Tenant":"bid","X-Env":"prod"}`

## 五、注意事项

- 内网部署阶段不要执行 `docker compose build`。
- 内网部署阶段不要执行带 `--build` 的 `docker compose up`。
- 如果前端页面之前依赖 Google Fonts，本次已经改为本地系统字体栈，不再访问外网字体服务。
- `S4 生成标书` 依赖的 Python 包必须在外网构建离线包时完成安装；内网部署时不要再执行 `pip install`。
- `opencode` 镜像内应能找到 `s1parse / s2toc / s4gap / s4fill / s7assemble / wikibuild` 这些命令；如果缺失，说明镜像不是当前版本，需要重新外网构建并导入。
- 如果需要更新应用版本，应在外网机器重新执行一次离线打包，再把新的镜像 tar 带入内网。

## 六、建议的验收命令

```bash
docker compose ps
curl http://localhost/api/healthz
curl http://localhost/ds/healthcheck
curl http://localhost:4096/global/health
docker compose exec -T opencode sh -lc 'command -v wikibuild'
```

如果修改了端口，请替换为实际端口。
