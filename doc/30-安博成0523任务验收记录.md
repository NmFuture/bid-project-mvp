## 1. 素材库路径检查

### 1.1 检查结论

当前系统不是只做了 UI 分隔。技术标和商务标在前端入口、后端接口参数、数据库字段和对象存储 key 上都已经具备独立路径：

| 层级 | 当前状态 | 证据 |
|---|---|---|
| 前端入口 | 已分开 | 技术标路由在 `code/sewpg-bid-frontend/src/workspaces/technical/routes.jsx`，商务标路由在 `code/sewpg-bid-frontend/src/workspaces/business/routes.jsx`。素材库入口分别是 `/workspace/tech/materials/*` 和 `/workspace/business/materials/*`。 |
| 前端查询 | 已按标类锁定 | `MaterialDB` / `MaterialWiki` 通过 `workspaceKind` 和 `bidTypeFromWorkspace()` 锁定 `bidType`，查询 `raw/files`、`wiki`、`identity-options` 时带 `bidType=技术标` 或 `bidType=商务标`。 |
| 后端接口 | 已按标类过滤 | `/api/materials/raw/files`、`/api/materials/wiki`、`/api/materials/identity-options`、`/api/materials/turbine-model-options` 都接收 `bidType`；`material_store.raw_files()` 会过滤 `ext_fields.bidType`，不同标类不会互相返回。 |
| 数据库路径 | 已有独立根 | `raw_folders` 有 `技术标` 和 `商务标` 两个根；商务标下已初始化 `通用素材 / 客户素材 / 项目素材`。 |
| 对象存储路径 | 已按文件夹路径隔离 | 原始文件对象 key 由 `_raw_object_key(folder_path, file_name)` 生成，形如 `raw/技术标/.../文件名` 或 `raw/商务标/.../文件名`。 |
| 商务标业务链路 | 已用商务标范围 | 商务标 S3 和正文装配读取素材时传 `bid_type="商务标"`，不会读取技术标文件作为商务标候选。 |

### 1.2 运行态检查结果

在本机 Docker Compose 运行态通过 `http://localhost:8080` 检查：

| 检查项 | 结果 |
|---|---|
| `/api/materials/raw/tree` | 顶层返回 `技术标` 和 `商务标` 两个根。 |
| `/api/materials/raw/files?bidType=技术标&pageSize=5` | `total=95`，样例文件均为 `bidType=技术标`，路径在 `技术标/...` 下。 |
| `/api/materials/raw/files?bidType=商务标&pageSize=5` | `total=0`，当前商务标素材库已建目录但没有原始文件。 |
| `/api/materials/raw/files?folderPath=技术标&bidType=商务标&pageSize=3` | `total=0`，商务标筛选不会读技术标路径。 |
| `/api/materials/raw/files?folderPath=商务标&bidType=技术标&pageSize=3` | `total=0`，技术标筛选不会读商务标路径。 |
| `/api/materials/turbine-model-options?bidType=技术标` | `total=26`，机型候选来自技术标素材库参数表。 |
| `/api/materials/turbine-model-options?bidType=商务标` | `total=0`，商务标不会误读技术标机型参数表。 |
| PostgreSQL `raw_files.ext_fields->>'bidType'` | 当前所有 95 个原始文件均为 `技术标`。 |
| PostgreSQL `sourceMinioKey` 样例 | 对象 key 包含 `raw/技术标/...` 路径前缀。 |

### 1.3 未对齐与后续改造项

| 项目 | 当前结论 | 建议 |
|---|---|---|
| 商务标 Wiki | 未完全对齐。`/api/materials/wiki?bidType=商务标` 当前只有一个 `新建节点`，不是预期的商务标 Wiki 五类结构。 | 后续应执行或修复商务标 Wiki bootstrap，生成商务素材总表、模块映射、证据卡片、待处理清单、使用规则等结构。 |
| 商务标素材文件 | 目录已初始化但文件为空。 | 需要导入商务标固定素材、资格证书、业绩资产、商务模板底稿等真实材料后再做匹配质量验收。 |
| 历史根目录 | DB 里还有 `通用素材 / 客户素材 / 项目素材` 这类旧根目录残留。 | 当前接口主要按 `bidType` 和 `ext_fields` 过滤，不影响本次隔离结论；后续可做一次迁移清理，避免管理端误解。 |
| 交集素材 | 还没有显式的“双侧可见”策略。当前完全依赖 `bidType` 过滤，会议提到的 `业绩表` 如果只挂在技术标路径，商务标不会看到。 | 不建议取消隔离；建议新增 `applicableBidTypes` 或共享素材标记，让 `业绩表` 等少量交集材料在两个标类都可检索，并保留原始归属路径。 |
| 混排机型素材 | 当前技术标支持单机型选择和按机型参数筛选，未实现“多机型 + 台数 + 按机型目录/tag 检索”。 | 作为后续研发项，项目信息应支持多机型及台数，素材检索按机型、部件 tag 和章节共同过滤。 |

### 2.2 本轮前端改动

- `code/sewpg-bid-frontend/src/pages/GenerateProgress.jsx`
  - 商务标点击生成时自动打开进度弹窗。
  - 运行中弹窗不可误关，完成或失败后可关闭。
  - 弹窗展示生成进度、任务列表、最近执行事件、章节/附件结果概览。
  - 商务标页面移除原始 FutureCode 输出卡片，避免汇报页面暴露 Provider、Model、Session 和原始片段。
  - 技术标生成页保持原行为不变。

## 3. 当前结论

素材库隔离的主链路已经成立：前端入口、API 查询、DB 标类字段和对象存储 key 均按 `技术标 / 商务标` 分开。当前最大的真实缺口不是“后端仍共用一套数据”，而是商务标侧素材和 Wiki 尚未完整建库，以及 `业绩表` 这类交集素材缺少明确的双侧可见策略。

UI 对齐方面，会议列出的演示口径大部分已经在当前分支具备；本轮补齐了项目内商务标生成页的弹窗进度展示，并收敛了不适合汇报展示的原始调用输出。
