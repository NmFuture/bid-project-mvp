# 生成标书与覆盖诊断说明

> 用途：记录当前“生成标书”和“覆盖诊断”的真实实现口径，避免继续沿用旧的“初稿生成”理解。
> 2026-05-02 更新：前端主进度已把内部 S7/S8 合并为“生成标书”。`/coverage` 和 `coverage` 状态仍保留为诊断/导出检查能力，但不再是主流程独立节点。

## 1. 当前结论

生成标书已替换为 `bid-tech-assembler` 技术标正文拼装链路。

核心逻辑是：

```text
S2 目录 JSON
  -> S2 Wiki 卡片
  -> 当前素材库清洗后 Word
  -> 缺口处理计划与补料/AI 填写产物
  -> bid-tech-assembler 拼装正文 docx
  -> 覆盖诊断校验未拼上的素材和未匹配目录项
```

旧的 `bid-draft-sections-json` 初稿生成思路已经不再作为主链路。

## 2. 生成标书输入

后端准备一个 `s7_assembly_workdir`，核心输入包括：

| 输入 | 来源 | 说明 |
|---|---|---|
| `投标文件-总目录.json` | S2 输出 | 当前支持 `bid-toc-json-v1` 的 `items[]` 结构 |
| `wiki/卡片/*.md` | S2 Wiki 导出 | 卡片承载 `skeleton_section`、`material_id`、`path`、`scope/category` 等素材定位信息 |
| `素材库/投标资料库-通用` | 后端运行前导出 | 从 PostgreSQL/MinIO 当前素材库导出的清洗后 Word |
| `素材库/投标资料库-定制` | 后端运行前导出 | 项目/客户定制素材 |
| `gap_plan.json` | 缺口处理确认结果 | 记录匹配素材、人工上传、选择已有素材、AI 填写产物和完整性校验结果 |
| `project_params.json` | 后端项目状态 + S2 JSON | 缺失字段以 `[待填写：xx]` 占位 |
| 可选正文模板 | S1 模板上传 | 没有可用模板时生成最小母版 |

## 3. 后端执行流程

1. 校验目录已确认、缺口处理已确认。
2. 读取 S2 目录 JSON；如果文件缺失，回退使用 `outline_state.nodes` 生成兼容 JSON。
3. 读取 `gap_plan.json`，并把缺口处理产物补充成可供拼装读取的素材卡片。
4. 复制 S2 `wiki/` 目录，或从素材库接口导出 Wiki。
5. 遍历 Wiki 卡片，按 `material_id` 优先下载清洗后 Word；没有清洗稿时尝试原始 Word。
6. 将素材导出成 skill 能读取的文件系统结构。
7. 重写 Wiki 卡片 `path`，让卡片指向导出的相对路径。
8. 写入 `s7_assembly_input.json` manifest。
9. 调用：

```bash
python opencode/skill/bid-tech-assembler/scripts/run_from_manifest.py \
  --manifest <s7_assembly_input.json> \
  --response summary
```

10. 生成正文 Word，并复制到项目文档路径，供共创/导出继续使用。

## 4. 主要输出

| 输出 | 说明 |
|---|---|
| `投标文件-正文_*.docx` | S7 拼装出的技术标正文 |
| `assembly_plan.json` | 每个目录项的匹配状态、素材路径、占位状态 |
| `assembly_report.md` | 拼装审计报告 |
| `needs_review.md` | 人工确认清单，包括占位符、未匹配章节、适配项 |
| `fill_state.assembly` | 后端保存的拼装路径和报告索引 |
| `fill_state.coverage` | 覆盖诊断使用的素材拼装覆盖结果 |

## 5. 覆盖诊断当前逻辑

覆盖诊断当前不再只按章节 `generationMode` 做 mock 覆盖。

它以 S7 的 `assembly_plan.json` 和导出的素材卡片为依据：

- `fullCover`：已经被拼装计划使用的素材数量。
- `noCover`：素材库中可用但没有出现在 S2 目录 JSON 或拼装计划中的素材数量。
- `partialCover`：目录中未匹配素材或需要人工确认的项数量。
- `tree`：按 `scope/category` 分组的素材拼装覆盖树。
- `partialItems`：未匹配目录项。
- `noCoverItems`：未拼装素材清单。

边界：

- 当前覆盖诊断是“素材拼装覆盖校验”。
- 正式版评分点覆盖审计还需要继续把招标评分点、正文段落、素材证据建立细粒度追溯。

## 7. 当前仍需后续完善

- 缺口处理产物当前已作为项目级真实文件参与拼装；是否沉淀为全局可复用素材库，需要单独补齐入库、版本和复用策略。
- 覆盖诊断从“素材拼装覆盖”升级到“评分点/证据/段落覆盖”。
- `needs_review.md` 的人工确认项可以进一步映射到前端可操作列表。
- 对素材 Word 的格式异常、横竖版错误、空章节等问题增加更明确的前端提示。
