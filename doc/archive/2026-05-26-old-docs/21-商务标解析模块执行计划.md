# 商务标解析模块说明

> 用途：让研发、产品和测试人员快速理解“商务标解析模块”的功能边界、输出内容、后端链路、前端展示、Skill 关系以及后续 S2/S3/S4 如何消费解析结果。
> 当前状态：已实现模块说明文档。
> 更新日期：2026-05-12
> 2026-05-25 补充：本文已按当前商务标双轨入口修订，当前接口以 `routes/business.py`、`business_parse_service` 和 `BusinessTenderReview` / `BusinessParseResult` 为准；文中不再把旧通用 route 或旧共享页面作为当前代码索引。

## 1. 模块定位

商务标解析模块是商务标链路的 S1 入口，负责把上传的商务招标文件解析成后续流程可消费的结构化数据和可预览 Word 产物。

它不是技术标解析模块的简单复用，而是一条按 `bidType=商务标` 分流的独立解析 profile。

核心目标：

| 目标 | 说明 |
|---|---|
| 提取商务评分与审查规则 | 识别商务评分标准、投标报价评分标准、符合性审查标准 |
| 提取商务附件模板 | 从招标文件的投标文件格式、响应文件格式、商务标格式等章节中切出可后续使用的 Word 模板 |
| 识别并生成承诺函草稿 | 识别明确要求单独提供承诺函/承诺书的条款，生成 Word 草稿 |
| 生成项目事实字段 | 输出项目名称、招标编号、招标人、交货周期、质保期、投标截止日期等字段，供 S3/S4 填表使用 |
| 支持人工审核和同步素材库 | 商务评分、附件模板、承诺函可审核；确认参与投标后同步到项目素材库 |

## 2. 与技术标解析的边界

商务标和技术标通过 `parse profile` 严格区分。

| 项目 | 技术标解析 | 商务标解析 |
|---|---|---|
| bidType | `技术标` | `商务标` |
| parse profile key | `technical` | `business` |
| schemaVersion | `bid-tender-structured-v1` | `bid-business-tender-structured-v1` |
| targetSkill | `bid-tender-structured-parser` | `bid-business-tender-structured-parser` |
| workspace | `technical-workspace` | `business-workspace` |
| 核心输出 | 技术评分、风机参数、性能保证、环境适应性、技术附表 | 商务评分、报价/合规审查、商务附件模板、承诺函、项目事实字段 |

商务标解析不输出以下技术标专属字段组：

| 技术标字段组 | 商务标处理 |
|---|---|
| `turbineCoreParameters` | 删除，不在商务标页面展示 |
| `performanceGuarantees` | 删除，不在商务标页面展示 |
| `environmentAdaptation` | 删除，不在商务标页面展示 |
| 技术评分标准 | 不作为商务标评分结果展示 |

对应代码位置：

| 文件 | 作用 |
|---|---|
| `code/sewpg-bid-backend/app/services/parse_profiles.py` | 定义技术标/商务标解析 profile |
| `code/sewpg-bid-backend/app/services/parsing.py` | 根据 profile 执行解析、附件提取、承诺函识别和结构归一化 |
| `code/sewpg-bid-frontend/src/workspaces/business/pages/BusinessTenderReview.jsx` | 商务标解析上传、审核和参与投标入口 |
| `code/sewpg-bid-frontend/src/workspaces/business/pages/BusinessParseResult.jsx` | 商务标进入工作区后的解析结果和模板目录衔接页 |

## 3. 用户视角功能

商务标解析页面目前支持：

| 功能 | 当前表现 |
|---|---|
| 新建商务标解析项目 | 前端创建 `bidType=商务标` 的待解析项目 |
| 上传并解析商务招标文件 | 解析接口保存文件、抽取文本、生成结构化结果 |
| 查看商务评分标准 | 展示商务评分、报价评分、符合性审查 |
| 审核商务评分标准 | 审核后可在确认参与投标时同步到项目素材库 |
| 查看承诺函 Word 预览 | 对自动生成的承诺函草稿进行 OnlyOffice 预览 |
| 审核承诺函 | 审核后可在确认参与投标时同步到项目素材库 |
| 查看商务附件模板产物 | 对投标函、授权书、报价表、偏差表、规格表等模板进行 Word 预览 |
| 审核商务附件模板 | 审核后可在确认参与投标时同步到项目素材库 |
| 参与投标 | 填写项目信息后进入后续工作区，并触发已审核解析产物同步 |

前端当前刻意隐藏了部分中间分析模块，例如项目基础信息表、承诺线索、资格与支撑要求、商务响应要求、证据明细等。这些数据仍可能存在于 JSON 中，但不作为商务标解析页的主要操作模块展示。

## 4. 总体技术链路

商务标解析的真实链路是：

```text
前端上传商务招标文件
  -> 后端保存上传文件
  -> 按 bidType 选择 BUSINESS_PARSE_PROFILE
  -> 提取文本 DOCX / PDF / 图片 OCR
  -> 本地结构化解析生成初始 result
  -> 提取商务附件模板和表格模板
  -> 转换为商务标专用 contract
  -> 可选调用 opencode / bid-business-tender-structured-parser skill
  -> 后端再次归一化商务 contract
  -> 生成 Word 产物路径和预览元数据
  -> store 持久化 parse_result
  -> 前端展示、预览、审核
```

需要注意：

| 机制 | 当前实现 |
|---|---|
| 是否完全由 AI 解析 | 否。本地规则和后端归一化承担主要确定性逻辑 |
| 是否调用 Skill | 可调用。由 `settings.s1_parse_opencode_enabled` 控制 |
| Skill 失败怎么办 | fallback 到本地结构化解析结果 |
| 商务标解析产物是否立即入素材库 | 否。先在解析结果中审核，确认参与投标后再同步项目素材库 |

## 5. 后端入口与关键接口

主要路由在 `code/sewpg-bid-backend/app/api/routes/business.py`，业务逻辑收口到 `business_parse_service`。

| 接口 | 作用 |
|---|---|
| `POST /api/business/projects/{project_id}/parse-results/upload-and-run` | 上传招标文件并立即解析 |
| `GET /api/business/projects/{project_id}/parse-results` | 读取解析结果，并补齐可预览 Word 产物 |
| `GET /api/business/projects/{project_id}/parse-results/progress` | 读取解析进度 |
| `GET /api/business/projects/{project_id}/parse-results/appendices/{appendix_id}/preview` | 商务附件模板/附表 Word 预览 |
| `POST /api/business/projects/{project_id}/parse-results/appendices/{appendix_id}/approve` | 审核单个商务附件模板 |
| `POST /api/business/projects/{project_id}/parse-results/appendices/approve` | 批量审核商务附件模板 |
| `POST /api/business/projects/{project_id}/parse-results/business-scoring/approve` | 审核商务评分标准 |
| `GET /api/business/projects/{project_id}/parse-results/commitment-letters/{letter_id}/preview` | 承诺函 Word 预览 |
| `POST /api/business/projects/{project_id}/parse-results/commitment-letters/{letter_id}/approve` | 审核单个承诺函 |
| `POST /api/business/projects/{project_id}/parse-results/commitment-letters/approve` | 批量审核承诺函 |

确认参与投标时，商务标项目 service 会调用商务解析产物同步逻辑：

```text
PUT /api/business/projects/{project_id}
  reviewDecision = participate
  -> sync_approved_business_parse_assets(project_id)
```

## 6. Skill 与本地解析的关系

商务标解析 Skill：

```text
code/sewpg-bid-backend/opencode/skill/bid-business-tender-structured-parser/
```

Skill 命令：

```bash
s1parse <manifest>
```

manifest 由后端生成，典型路径：

```text
parsed/{project_id}/s1_parse_manifest.json
```

完整结构化结果写入：

```text
parsed/{project_id}/s1_structured_result.json
```

当前不是“AI 自由发挥生成最终结果”的模式，而是：

| 层级 | 作用 |
|---|---|
| 后端本地解析 | 提取文本、识别通用结构、提取附件模板、构建商务 contract |
| opencode / Skill | 在启用时按 manifest 产出结构化结果，补充或替换部分结构 |
| 后端二次归一化 | 无论 Skill 是否可用，最终都通过 `_transform_to_business_contract` 归一为商务标 schema |
| fallback | Skill 调用失败时，保留本地结构化解析结果，并记录 `opencodeError` |

相关函数：

| 函数 | 作用 |
|---|---|
| `parse_tender_documents` | S1 解析总入口 |
| `_run_parse_skill` | 调用 opencode / Skill，失败时 fallback |
| `_resolve_skill_structured_result` | 解析 Skill 输出并合并本地字段 |
| `_transform_to_business_contract` | 将结果归一化为商务标专用 contract |

## 7. 解析结果 Contract

商务标解析结果的核心字段位于：

```text
parse_result.structured
```

主要结构：

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 固定为 `bid-business-tender-structured-v1` |
| `targetSkill` | 固定为 `bid-business-tender-structured-parser` |
| `mode` | `local-structured-parser` 或 `opencode-skill` |
| `sourceDocuments[]` | 源招标文件清单 |
| `scoringCriteria.business[]` | 商务评分标准 |
| `scoringCriteria.price[]` | 报价评分标准 |
| `scoringCriteria.compliance[]` | 符合性审查标准 |
| `fieldGroups.projectBasics[]` | 项目基础信息 |
| `fieldGroups.businessResponse[]` | 商务响应要求 |
| `fieldGroups.qualificationSupport[]` | 资格与业绩支撑要求 |
| `fieldGroups.commitmentRequirements[]` | 承诺事项要求统计和依据 |
| `requirementPresence` | 资格、业绩、偏差、保证金、承诺、否决条款的存在性判断 |
| `coverage[]` | 商务覆盖情况汇总 |
| `projectDates` | 投标阶段日期 |
| `projectFactFields[]` | 后续 S3/S4 可填充的项目事实字段 |
| `appendices[]` | 商务附件模板 Word 产物 |
| `commitmentLetters[]` | 自动生成的承诺函 Word 草稿 |
| `commitmentClues[]` | 未自动生成、需人工判断的承诺线索 |
| `commitmentTemplateAlignments[]` | 承诺要求与已有附件模板的匹配关系 |
| `businessFormatRegions[]` | 投标文件格式区域识别结果 |
| `businessScoringAsset` | 商务评分标准审核和同步状态 |

## 8. 商务评分标准提取

商务评分标准只保留三个桶：

| 桶 | 含义 |
|---|---|
| `business` | 商务评分标准 |
| `price` | 投标报价评分标准 |
| `compliance` | 符合性审查标准 |

评分来源包括：

| 来源 | 机制 |
|---|---|
| 本地结构化解析 items | 从招标文件文本中抽取评分行 |
| Markdown 表格 | `_extract_markdown_scoring` 根据标题分类并解析表格行 |
| Skill 输出 | 如果 Skill 返回 scoringCriteria，后端会合并并保留商务标需要的桶 |

前端展示时不显示“证据位置”列，但后端数据仍保留 `sourceFile`、`sourceDocumentId`、`section`、`evidence`、`evidenceLocation`，供调试和后续链路使用。

审核后，商务评分标准会在确认参与投标时写成 Word 并同步到：

```text
商务标/项目素材/{project_id}/03-模板底稿与过程文件/商务评分标准.docx
```

## 9. 商务附件模板提取机制

商务附件模板的目标不是提取普通附表标题，而是从招标文件中切出后续投标文件可复用的模板或表格，例如：

| 类型 | 示例 |
|---|---|
| 投标函类 | 投标函、投标函附录 |
| 授权类 | 法定代表人身份证明、法定代表人授权书 |
| 廉洁/承诺类 | 投标人廉洁自律承诺书、履约保证函格式 |
| 报价类 | 开标价格表、投标价格表、报价明细表 |
| 响应表类 | 商务偏差表、货物规格一览表、供货范围表 |
| 资格业绩类 | 业绩情况表、资格证明文件格式 |
| 其他说明类 | 投标人需要说明的其他内容、附件 9、否决项响应 |

当前采用“对象 + 语义锚点 + 表格指纹”的实现路径。

### 9.1 DOCX 对象级解析

对 `.docx` 文件，后端不会只按纯文本切片，而是读取 Word body 中的段落和表格对象：

| 函数 | 作用 |
|---|---|
| `_iter_docx_blocks` | 按 Word body 顺序读取 paragraph/table block |
| `_docx_paragraph_metadata` | 识别段落样式、标题层级、居中、加粗等标题特征 |
| `_detect_business_format_regions` | 定位“投标文件格式/响应文件格式/商务标格式”等模板区域 |
| `_extract_docx_appendices` | 在模板区域内切出附件模板或表格 |

### 9.2 模板区域识别

系统会优先定位以下语义区域：

| 起始语义 | 说明 |
|---|---|
| 投标文件格式 | 常见于第六章 |
| 响应文件格式 | 常见于采购响应文件 |
| 商务标格式 | 商务投标文件模板区 |
| 附件/附表格式 | 附件集中区 |

进入模板区域后，会尽量保留其中的段落、表格和占位符，直到遇到下一个同级或更高层级的大章节。

### 9.3 表格指纹识别

对于没有明显“附件标题”的表格，系统会根据表头指纹识别可用模板。

| 指纹类型 | 典型表头 |
|---|---|
| 报价表 | 序号、名称、单价、合价、备注 |
| 货物规格表 | 货物名称、规格型号、数量、单位 |
| 商务偏差表 | 条款号、招标要求、投标响应、偏差说明 |
| 供货范围表 | 设备名称、供货范围、数量、备注 |
| 业绩表 | 项目名称、合同金额、业主、投运时间 |
| 保证金/保函 | 保证金、保函、金额、有效期 |

提取结果会带上：

| 字段 | 说明 |
|---|---|
| `artifactType` | `business_attachment_template` |
| `templateType` | 模板类型，例如 `bid_letter`、`opening_price`、`commercial_deviation` |
| `templateTypeLabel` | 中文类型标签 |
| `tableFingerprint` | 表格指纹识别结果 |
| `templateSectionTitle` | 所属模板章节 |
| `sourceStart/sourceEnd` | 原文切片边界 |
| `extractionMode` | `source_docx_slice`、`source_docx_table_fingerprint`、`markdown_slice`、`text_slice` |
| `extractionQuality` | `complete`、`probably_incomplete`、`title_only`、`needs_review` |
| `qualityIssues[]` | 质量问题说明 |

### 9.4 质量过滤

为了避免“只提取到一个标题就生成 Word”，当前会做质量判断。

以下候选通常不会生成 Word：

| 情况 | 处理 |
|---|---|
| 目录页中的附件标题 | 过滤 |
| 只有标题、没有正文、没有表格 | 不物化为可用 Word |
| 没有明显表格、签章栏或待填写占位符 | 默认不作为可用附件模板生成 |
| 普通条款或评分标准误判为模板 | 过滤或标记需复核 |

如果启用了 AI 语义复核，会通过 `review_business_attachment_templates_with_trace` 对候选模板做 `accept/review/reject` 判断。

## 10. 承诺函识别与生成机制

承诺函识别的目标是：只对商务标中明确要求投标人单独提供承诺函/承诺书的事项生成 Word 草稿。

### 10.1 强规则识别

系统会识别以下明确表达：

| 表达 | 处理 |
|---|---|
| 明确写“承诺函”或“承诺书”且要求提供/提交/出具 | 进入生成候选 |
| “须提供承诺函/承诺书” | 进入生成候选 |
| “应出具承诺函/承诺书” | 进入生成候选 |
| “需提供书面承诺” | 进入生成候选 |
| “须无条件承诺……” | 进入生成候选 |
| “投标人不得存在下列情形之一” | 强制生成“投标人不存在下列情形之一承诺函” |

### 10.2 技术承诺过滤

商务标解析会过滤明显属于技术标的承诺，例如：

| 技术承诺关键词 | 处理 |
|---|---|
| 发电量、上网电量、功率曲线 | 不生成商务承诺函 |
| 满负荷小时、等效满负荷小时 | 不生成商务承诺函 |
| 风机、机组、叶轮、塔筒、载荷、噪声 | 不生成商务承诺函 |
| 性能保证、技术指标 | 不生成商务承诺函 |

### 10.3 AI 语义复核

对于容易误判的候选，系统可调用 `review_business_commitments_with_trace` 做语义判断。

AI 复核输出动作：

| action | 含义 |
|---|---|
| `generate` | 明确需要生成承诺函/承诺书 |
| `clue` | 有承诺线索，但不确定是否应单独成文 |
| `ignore` | 章节标题、目录项、模板名、技术承诺或无单独成文要求 |

如果 AI 复核不可用，明确强规则候选会按规则兜底生成；不明确候选只进入 `commitmentClues[]`。

### 10.4 主题归一与去重

系统会按主题归一承诺函标题，避免同一主题重复生成。

| 主题 | 默认标题 |
|---|---|
| `confidentiality` | 保密承诺书 |
| `disqualification` | 投标人不存在下列情形之一承诺函 |
| `certificate_obtainment` | 材料取得承诺书 |
| `delivery` | 交货周期承诺书 |
| `quality` | 质量服务承诺书 |
| `security` | 投标保证金承诺书 |
| `compliance` | 合规承诺书 |

### 10.5 与已有模板对齐

如果招标文件的附件模板区已经提取到相同主题的承诺书模板，系统不会再重复生成一份承诺函草稿，而是写入：

```text
structured.commitmentTemplateAlignments[]
```

这表示“该承诺要求已被已有附件模板覆盖”。

## 11. 项目事实字段

商务标解析会生成 `projectFactFields[]`，供后续 S3/S4 填表和正文生成使用。

当前字段：

| fieldKey | 中文名 | 是否必填 |
|---|---|---|
| `projectName` | 项目名称 | 是 |
| `tenderNo` | 招标编号 | 是 |
| `tenderer` | 招标人 | 是 |
| `managementUnit` | 管理单位 | 否 |
| `bidSectionScale` | 标段规模 | 否 |
| `deliveryPeriod` | 交货周期 | 否 |
| `warrantyPeriod` | 质保期 | 否 |
| `bidStartDate` | 投标起始日期 | 否 |
| `bidDeadline` | 投标截止日期 | 是 |

字段来源优先来自 `fieldGroups.projectBasics` 和 `projectDates`。每个字段保留：

```text
value / status / confidence / sourceFile / sourceDocumentId / section / evidence / evidenceLocation
```

这些字段后续应进入商务标 S3 的项目事实表，由人工确认后供 S4 模板填充、承诺函变量填充、正文装配使用。

## 12. 解析产物保存位置

解析阶段的临时产物位于：

```text
parsed/{project_id}/
```

## 13. 审核与同步素材库

商务标解析产物不会在解析完成后立即写入原始素材库，原因是解析产物可能需要人工判断是否准确、是否适合进入项目素材库。

当前规则：

| 产物 | 审核入口 | 同步目标 |
|---|---|---|
| 商务附件模板 | 解析页“商务附件模板产物”审核当前/审核全部 | `商务标/项目素材/{project_id}/02-商务响应文件/` |
| 承诺函草稿 | 解析页“承诺函 Word 预览”审核当前/审核全部 | `商务标/项目素材/{project_id}/02-商务响应文件/` |
| 商务评分标准 | 解析页“商务评分标准审核” | `商务标/项目素材/{project_id}/03-模板底稿与过程文件/` |

同步触发时机：

```text
用户点击“参与该项目并进入工作区”
  -> 前端提交 reviewDecision=participate
  -> 后端 sync_approved_business_parse_assets(project_id)
  -> 已审核资产上传到商务标项目素材库
```

相关代码：

| 文件 | 作用 |
|---|---|
| `code/sewpg-bid-backend/app/services/business_parse_assets.py` | 审核状态维护、产物转 Word、同步项目素材库 |
| `code/sewpg-bid-backend/app/services/bid_project_service.py` | 参与投标时触发解析资产同步 |
| `code/sewpg-bid-backend/app/services/business_material_store.py` | 商务标项目素材库上传 facade |
| `code/sewpg-bid-backend/app/services/material_store.py` | 底层素材库持久化底座，不作为业务入口直接使用 |

## 15. 后续 S2/S3/S4 如何消费

商务标解析结果不是最终标书，它为后续阶段提供输入。

| 阶段 | 消费内容 | 用途 |
|---|---|---|
| S2 模板与目录 | 招标文件文本、解析结果、上传模板文件 | 生成商务标目录和响应结构 |
| S3 缺口处理 | `projectFactFields`、`appendices`、`commitmentLetters`、`scoringCriteria`、素材库/Wiki | 判断每个目录任务是否有材料、是否要填表、挂载、AI 起草或人工补料 |
| S4 正文装配 | S3 已确认任务、项目事实字段、附件模板、承诺函、评分标准、素材库原件/切片 | 生成商务投标 Word，并在拼装后进入格式清洗 |

重点关系：

| 解析产物 | 后续用途 |
|---|---|
| `projectFactFields[]` | 填充投标函、授权书、报价表、承诺函中的项目名称、招标编号、招标人等 |
| `appendices[]` | 作为 S3/S4 的模板填充候选 |
| `commitmentLetters[]` | 放入“投标人需要说明的其他内容”等章节 |
| `scoringCriteria` | 作为商务评分索引和缺口识别依据 |
| `commitmentTemplateAlignments[]` | 避免重复生成同主题承诺函 |

## 16. 当前边界和注意事项

| 边界 | 说明 |
|---|---|
| 解析不是最终法务审查 | 承诺函草稿仍需要人工复核 |
| 模板提取依赖源文件质量 | DOCX 结构越规范，附件模板切片越准确 |
| PDF/图片可 OCR，但不是当前附件模板优化重点 | 当前效果最佳的是 Word 文档对象级解析 |
| AI 语义复核是增强，不是唯一来源 | AI 不可用时有规则 fallback |
| 审核后才同步素材库 | 防止错误模板、无效承诺函进入项目素材库 |
| 技术标链路不应被商务标改动影响 | 新增逻辑应受 `profile.key == "business"` 或 `bidType=商务标` 限制 |

## 18. 推荐验收点

后续修改商务标解析模块时，建议至少验证：

| 验收点 | 判断标准 |
|---|---|
| 商务标/技术标不串线 | 商务标不出现技术字段组，技术标解析结果不受影响 |
| 商务评分可提取 | `business/price/compliance` 三类结果正确 |
| 附件模板不是标题空文档 | 投标函、报价表、偏差表等 Word 产物包含正文或表格 |
| 目录页不误提取 | 目录中的“附件 X”不生成 Word |
| 技术承诺不生成商务承诺函 | 发电量、功率、满负荷小时等不进入 `commitmentLetters` |
| 明确商务承诺能生成 | “须提供承诺书/须无条件承诺”等生成对应 Word |
| 已有模板覆盖时不重复生成 | `commitmentTemplateAlignments` 正常记录覆盖关系 |
| 项目事实字段可用 | `projectFactFields` 包含项目名称、招标编号、招标人、截止日期等 |
| 审核和同步正常 | 审核后的附件、承诺函、评分标准在参与投标后进入项目素材库 |
