# 章节判断细则

`SKILL.md` 的「章节判断方法」展开版。只在索引列为空、需要人工/AI 判断该索引哪些章节时用。

## 五条原则

1. **投标响应原文是最强锚点。** 响应里点名的专有名词——系统名（PHM）、证书名（碳中和证书）、部件名、基地名、机型名——逐个去标题树里找对应章节，找到就必须入索引。这是最不容易出错、也最容易被忽略的一条。

2. **按系统归属查全。** 评审因素若指向某个系统，对照下面的速查表逐个部件在标题树里找专题章节，防止漏项。**最常漏的是轮毂、制动系统、升降机**这类不起眼但确属该系统的部件。

3. **承诺类指向具体条款，数据类指向具体表。** 涉及保证值/考核值（发电量、可利用率、功率曲线、无故障时间）的，指向承诺函下的**具体条款**和考核章节，而不是笼统的整章；涉及参数、业绩、安全等级的，直接指向那张一览表或附表。

4. **粒度取"能独立回答该因素的最小完整章节"。** 父章节只在需要覆盖它全部子节时才用。响应明明点了子节（如"绿色采购及碳中和证书"），就不要只丢一个父章节了事。

5. **数量控制在每行 3–6 条。** 只有 1 条通常意味着漏了；超过 8 条会稀释重点。同时保证**专属性**——一个章节只出现在它真正支撑的因素下，别把热门章节到处铺。

## 常见陷阱

- **漏部件**——按速查表逐项核对，别凭印象。
- **张冠李戴**——把某因素专属的章节塞进别的因素（如把"自主可控"塞进"运维"）。
- **只给父章节**——响应已点名子节却仍笼统指向父章节。
- **照搬旧项目**——不同项目章节号必变，必须重新判断并经 `verify` 校验。

## 已知限制：自动算页码

脚本默认不调 Word，页码写占位符，靠成稿里的 `<w:updateFields>` 让 Word/WPS 打开时刷新。

装了 pywin32 的 Windows 机器可以加 `updateFieldsWithWord`（或去掉 `--no-word`）把页码算进文件。但在**后台/无交互桌面的会话**里，Word 打开超大文档（100MB+、上千张图）会卡在 `Documents.Open` 不返回——征兆是 Word 进程 CPU 停滞、内存远低于文档解压体积，且设置 `Visible` 报 "can not be set"。这不是文件或脚本的问题，遇到时改回 F9 手动刷新。
