# 当前开发计划

> 更新日期：2026-05-26

## 1. 当前目标

先把现有框架收成可验收版本，再扩展新增需求。当前研发重点不是继续堆页面或文档，而是用真实技术标、真实商务标样本跑通闭环，找出差距并修到可交付。

## 2. 权威文档

当前只看仓库根目录 `doc/` 下 4 个文档：

- `doc/值得留下来的内容.md`
- `doc/代码结构梳理.md`
- `doc/需求梳理.md`
- `doc/研发计划.md`

历史文档只在 `doc/archive/2026-05-26-old-docs/` 中追溯，不作为当前计划。

## 3. 下一批工作

1. 用真实技术标样本跑完整流程：导入、解析、目录、素材匹配、缺口处理、生成、共创、Word/PDF 下载。
2. 用真实商务标样本跑完整流程：导入、解析、目录、商务任务、素材/模板匹配、草稿/表格、生成、共创、Word/PDF 下载。
3. 把失败点归类为前端、后端、Skill、素材、模板、部署或权限问题。
4. 优先修阻断主流程的问题，再做体验优化。
5. 单独推进生产权限、临时文件清理、部署监控和一键启停。

## 4. 开发原则

- 技术标和商务标双轨隔离，不能为了省事恢复旧通用业务入口。
- 共享底座可以复用，但业务判断要放回对应技术标或商务标模块。
- AI 结果必须保留人工复核入口，不能静默替代报价、承诺、法务或最终投标判断。
- 文档只记录当前状态、验证基线和下一步，不再堆逐次调试记录。
